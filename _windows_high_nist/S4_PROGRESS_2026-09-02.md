## 5. 实机暴露并已修复的缺陷（S4 首批发现）

### 5.1 加固脚本 apply_hardening.ps1

1. icacls 对受保护系统根失败：C:\WINDOWS / Program Files / ProgramData 在 Win11 25H2 上 `icacls /deny` 报“拒绝访问”（exit 5），交互式提权亦复现；.NET `Get-Acl/Set-Acl` 可用。已全部改写为 .NET API（`Invoke-AclDeny/DenyRemove/Grant/GrantRemove` + `Get-AclRuleIdentitySid`/`Get-AclInheritance`）。
2. 注册表 Get-Acl 用 `-LiteralPath` 失败（Registry provider 不支持）→ 改 `-Path`。
3. RegistryAccessRule 构造参数顺序写反（把 AccessControlType 传给 inheritanceFlags）→ 修正为 (identity, rights, inheritance, propagation, type)。
4. `Set-AppLockerPolicy -Force` 参数不存在 → 移除。
5. Ensure-RunUser 成员判断按短名匹配（实际 `DESKTOP-QMAPMFH\AgentUser`）→ 改 `-like "*$RunUser"`。
6. 盘符根遍历误伤 ISO/光驱（UDF）与 FAT32/EFI → 只收 NTFS 固定卷。

### 5.2 sandbox assurance/windows_sandbox.py

7. `StringSidToSidW` 不是有效导出 → `ConvertStringSidToSidW`。
8. `wintypes.HANDLE(handle)` 双重包装 TypeError（ctypes 拒绝 c_void_p 再包装）→ 新增 `_as_handle` 归一化（Job 句柄、令牌、NUL 句柄等 4 处）。
9. CreateRestrictedToken 传错结构：把“GroupCount+数组”的包装结构地址当 `PSID_AND_ATTRIBUTES` 数组传，内核把 GroupCount 当 SID 指针解引用 → ERROR_NOACCESS(998)；特权数组同理。→ 改为直接构造并传 `SID_AND_ATTRIBUTES` / `LUID_AND_ATTRIBUTES` 数组。
10. `AllocateAndInitializeSid` argtypes 缺 nSubAuthorityCount（10 参声明 vs 11 参调用）两处（`_is_elevated`、`_set_token_integrity`）→ 补 DWORD。
11. 环境块未带 `CREATE_UNICODE_ENVIRONMENT` → UTF-16 块被按 ANSI 解析报 87/203 → 有 env 时加 0x400 标志。
12. env_ptr 用 `create_string_buffer` 包 UTF-16 字节 → 改 `c_char_p(env_block)`。
13. 受限令牌（禁用/deny-only Administrators）在该环境无法 spawn 任何进程（0xC0000142 STATUS_DLL_INIT_FAILED；AppLocker 排除后仍复现；disable 与 deny-only 均复现）→ 弃用“从管理员令牌 CreateRestrictedToken”路线，改为 run-user 登录令牌模式（AgentUser LogonUser，ACL 也才能绑定到 RunUser，与设计意图一致）。

### 5.3 runner / 通道

14. `run_enforcement_probe.ps1` 把无符号退出码转 Int32 溢出（0xC0000142=3221225794 大于 int32 max）→ 改 `[int64]`。
15. 加固后 guest 内 CIM/DCOM 全断（防火墙 blockoutbound + RFC1918 block 拦本机 DCOM）：Register/Start/Unregister-ScheduledTask、Get-CimInstance 全部失败；原生 `schtasks.exe`（RPC）可用 → runner 改用 schtasks，持久任务复用，不再反复注册/注销。

### 8.3 实机缺陷（本续更新发现，编号续 §5）

17. **CreateProcessWithTokenW 不接受 STARTUPINFOEX/EXTENDED_STARTUPINFO_PRESENT**（此 build 报 87）；CPAU 可行但需 SeAssignPrimaryTokenPrivilege → 任务账户改 SYSTEM（8.2.1）。
18. **CPAU + LogonUser 令牌在 HL 任务令牌下报 1314**（缺 SeAssignPrimaryTokenPrivilege）→ 同上。
19. **0xC0000142（STATUS_DLL_INIT_FAILED）根因 = session 0 服务 winsta/desktop ACL 只授任务属主（-1001）+ Administrators**：任何"非任务属主令牌"（受限管理员/AgentUser）spawn 的进程 DLL 初始化失败；授予该 SID winsta/desktop 访问后恢复（§5.2.13 的旧解释"受限令牌无法 spawn"实为桌面 ACL 问题）。
20. **CreateProcessAsUserW 环境块编码**：UTF-16 + 0x400 正常；此前 87 的真凶是 cwd（C:\s4 下非 AgentUser 可写路径），非环境块本身。
21. **AppContainer + 匿名管道 std 句柄 → 0xC0000142**：管道 DACL 只授创建者（SYSTEM），AppContainer 令牌无权访问句柄；high-nist 子进程跳过 STARTF_USESTDHANDLES（探针结果写文件）。
22. **AppContainer + powershell.exe（.NET Framework CLR）→ 0xC0000142**；cmd/python（原生）正常 → 探针宿主改 python（8.2.3）。
23. **AppContainer + ctypes（_ctypes/libffi）→ DLL 初始化失败**；whoami.exe 在 AppContainer 内也无输出 → 探针令牌类检查改行为代理（工作区 Low/Medium 写差异、LOCALAPPDATA 包 AC 重写特征），job_object_assigned 由父侧 sandbox observation 断言（已注释说明）。
24. **AppContainer 子进程读不到用户自建目录 C:\s4**（需包 SID / ALL APPLICATION PACKAGES 授权）→ 探针复制进工作区执行。
25. **工作区默认 Medium 标签阻止 LOW 子进程写入（no-write-up）** → sandbox 对 high-nist 工作区 `icacls /setintegritylevel Low /T`。
26. **CreateAppContainerProfile 以调用者（SYSTEM）profile 建包，但 OS 把子进程 TEMP/LOCALAPPDATA 重写到 `运行用户\AppData\Local\Packages\<app>\AC`** → sandbox 预创建 + 包 SID 授权（注意 `Path("C:")` 是驱动器相对路径，曾把目录建到错误位置，已修为 `Path("C:\\")`）。
27. **SYSTEM 运行时 Get-RunUserProfileRoot 用 $env:USERPROFILE 推导错误**（C:\WINDOWS\system32\config\AgentUser）→ 固定 `%SystemDrive%\Users\<RunUser>`。
28. **AgentUser 首登 profile 建到 `C:\Users\AgentUser.DESKTOP-QMAPMFH`**（目录冲突改名）→ reg save 拷贝 NTUSER.DAT 到正确路径 + ProfileImagePath 修正。
29. **AppContainer 重写 LOCALAPPDATA 导致 appdata_frozen 误报** → 断言改查真实用户 AppData 路径（USERPROFILE\AppData\Local）。
