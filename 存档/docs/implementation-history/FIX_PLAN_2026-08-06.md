## 1. 决断清单（全部定稿，用户确认）

### D-1 引用规则（主 agent prompt 固化）
- **载体**: orz 主 agent（及两个检索子代理）的 prompt 文档——**不是**项目文档/CLAUDE.md/索引（用户裁决：prompt 不可为 index，index 是开发目录文档，与二进制无关）
- **形态**: 一条规则 + 内联标记，非结构化模板（用户权衡过「给模板让模型填写」负担大——orz 无打下手子代理，主 agent 单挑，负担要最轻）
- **内容**: 「凡基于外部依据、参考实现、内部文档的引用，必须在引用处附带内联标记 `[来源: 路径:行号]`；无法定位来源的内容不得引用（不得凭记忆声称『参考自某处』）」
- **收益**: 阻断幻觉引用（P7 失实记录「Python 参考移植」是直接先例）；内联标记可被下游机械校验（grep `[来源:`）
- **内部文档引用注意**: 用 `文档ID §节/锚点` 而非裸行号（行号漂移，审计已实证 v0.2 行号过期）

### D-2 memory 立场（慎重处理）
- orz-memory 是 v0.2 §2.1 保留清单成员（「记忆系统 (默认关闭)」），语义 = **显式 opt-in 的可选功能**，**不是裁剪对象**
- 审计中「16 个产品不可达」（Slice #13 记录）是「未接线」的事实描述，非「应删除」判定
- §3.2 桥接裁决时 memory/chat-state 的接线路径必须保留为可选功能

### D-3 工具状态接口化（IP2a 定稿方向，P3 修复）
- **会话级机械探查**: 新会话 bootstrap 时（权限策略确定后）机械探查一次工具状态（策略随会话变：Interactive/ReadOnly/Benchmark）
- **名级拒绝**（策略级，如 Benchmark 下 web/bash）→ 从模型可见工具声明中**过滤**（接口状态；Gemini「从模型记忆完全排除，省 context」理由）
- **作用域/参数级拒绝** → 保留可见、执行时**显式拒绝原因**（Codex 拒绝原因透传；区分「用户拒绝」vs「系统无效响应」）
- **失败必显式**: 任何工具结果不得空白——全路径「空白返回」盘点（成功/错误/子代理错误/截断/deny 各路径），失败必须返回显式失败消息
- **连续拒绝熔断**: 连续拒绝 3 次/轮（Claude Code maxConsecutive 3 与 Codex guardian 3 的业界共识值）→ 注入「换策略」消息（含当前工具不可用及原因）；**成功调用重置计数**；总量 10/轮保守上限
- **每轮机械告知剩余轮次**（见 D-8）
- 与「prompt 少硬性约束」哲学一致（D-4）

### D-4 prompt 少硬性约束（设计哲学）
- 理想：用**明确可达信息**（机械状态/接口事实）隐式换取低幻觉与准确，而非堆 prompt 约束
- 边界：无法机械表达的环境信息（如「测试文件不可见」）仍用 prompt 声明，但作为「任务环境信息」提供而非行为约束
- §4.6 问询 block 属「收尾自查」设计裁决，不冲突

### D-5 P9 裁决（思维链输出侧）
- **不展示、不入 journal**（用户裁决：按当前模型思维速度，对人类用户展示思维链做审计收益极低）
- 明确记录**工具和动作**（工具事件链 + 动作结果即审计面）——与 D-3 接口状态化一致

### D-6 thinking 恢复（核心配置）
- `thinking: {type: "enabled"}` + `reasoning_effort: "max"`，**三实例统一**（主 agent + 内部检索子代理 + 外部检索子代理，全部拉到最高）
- **max_tokens: 160000**（128+32 只是数值来源的解释——128K 思考 + 32K content 的期望分配；**不做拆分语义**，DeepSeek 无子预算参数，160K 就是总量；上限 384K 合法）
- **空 content 重试链**（orz 侧「结构性保证最终轮有输出」）：
  1. 区分两类空 content：工具轮 `content==''` + 有 tool_calls = **合法**（不重试）；最终轮 `content==''` + `finish==length` = **异常**（思考吃光预算）
  2. 异常 → **字节级重试一次**（同一请求；必须带原 reasoning_content 回传——DeepSeek 400 规则；参照 DeepSeek-Reasonix PR #7259/#7101 + 24h 熔断）
  3. 仍空 → **thinking disabled 降级重试一次**（等价 effort=none，DeepSeek 特有可行路径）
  4. 链终点仍空 → 记录 + 明确终止原因（「预算耗尽零输出」事件，非静默）
- **reasoning_tokens 观测**: journal 记录 usage（校准预算与延迟，数据决策 160K 是否回调）
- 回放防御保留（含空串语义：V4 工具轮 reasoning_content 空串 59% 常态；**空串原样回传 200、空对象/缺失 400**；回放时保留 `""` 而非 null/缺省）
- **回放逻辑单点化**（一个适配层）+ 官方文档引用（契约漂移预警：DeepSeek 可能放宽回放要求，LangChain 2026-06 记录；未来可能反转——单点控制便于审计）
- fork 需扩展: `ThinkingConfig` 加 `reasoning_effort` 字段（当前仅 type）+ 三实例设置

### D-7 transport 路径与超时重试（P1/LOOP-16）
- **不用 /anthropic 端点**（用户裁决）：① 合规风险——Anthropic TOS 对中国用户方案（「被找上门」风险）；② 格式统一——不加第三底座（已有 Grok ACP 层 + async-openai fork 两个）；③ 观测整体化（usage 单格式统一记录）
- **不用 Responses API**（助手评估）：DeepSeek 官方 Codex 适配是 Responses 形态，但社区实测 v4-flash 工具轮停滞（opencodex #875）、v4-pro 未生效、需代理层回放——**保持 Chat Completions**（async-openai fork，已稳定 + 回放已实现；官方 schema 同样支持 reasoning_effort）
- **超时重试定稿**（吸收 Claude Code 全套）：
  - 有限指数退避 **10 次/32s 封顶**（替换 fork 的无限 backoff——当前非流式 create 路径无限重试违反 08-02「零重试边界」记录，无 ADR 授权）
  - **流空闲看门狗**（20s 提示/90s 静默强制中止——TCP 超时抓不到挂死）为主；总超时放宽为辅助（配套 160K 预算量级：满负荷 thinking 可能 10min+，**有进展的慢推理不算超时，挂死才中止**）
  - **已见输出不重试**（幂等规则：重发会重复执行工具调用；保留输出 + incomplete 标记 + 明确终止原因）
  - 单请求超时（10min 级）
  - `-p`/stdio 非流式路径改走 `generate_stream`（P8 落点）
  - **全部参数化**（Codex 式配置：request_max_retries/stream_max_retries/stream_idle_timeout_ms）
  - **取消与超时严格区分**（Gemini 教训：Ctrl+C 被误判为 ETIMEDOUT 静默重试 35s；我们的 select! 取消已分离，重试层必须保持）
  - 重试策略与 08-02「零重试边界」的冲突需 ADR 级确认（retry_policy 显式化）
- 若保留「零重试」语义则显式关闭重试——二选一，以 ADR 记录

## 3. 检索关键事实（新窗口可直接引用，勿重复检索）

### thinking 预算（2026-08 现状）
- **DeepSeek V4**: thinking 参数仅 `type`（enabled/disabled，默认 enabled）+ `reasoning_effort`（low/high/max，默认 high；v4-pro 当前仅 high/max，2026-08 初补齐三档；**medium→high、xhigh→max 静默映射**）；**无 budget 类参数**（budget_tokens 发送但被忽略=no-op）；max_tokens 默认输出封顶 64K、最大 384K、1M 上下文；thinking 时 temperature/top_p/presence/frequency 静默忽略；thinking 开启时工具轮 content='' 是**合法状态**（官方样例）；工具轮必须回传 reasoning_content 否则 400；**reasoning_content 空串是常态（59%）——空串回传 200、空对象/缺失 400**；旧别名 deepseek-chat/reasoner 已废弃
- **全业界无 min_output_tokens/预留参数**（OpenAI 官方原话 "There is no 'minimum tokens' setting"）
- **Anthropic**: 块共存结构（thinking 块 + text/tool_use 块，content 数组永不恒空）；thinking tokens 计入 max_tokens；budget_tokens 时代要求「留出空间」但从不保证；adaptive 时代 budget_tokens 400；Claude Code 默认 max output 32K（env CLAUDE_CODE_MAX_OUTPUT_TOKENS）、**subagent 硬顶 8K 被思考吃光输出前死亡（issue #78460——与 orz 同构的反面教材）**；官方示例 max_tokens=16000
- **OpenAI**: max_output_tokens 默认未声明（客户端 4096 是客户端实现）；无独立 reasoning 预算；`incomplete` 可发生在零可见输出前（官方承认）；官方建议 reasoning+output 预留 ≥25K；用 usage.output_tokens_details.reasoning_tokens 校准
- **Gemini**: thinkingBudget 0=关/-1=dynamic 默认（dynamic 实测吃 90-98% 预算，content 空是常见事故）；Gemini 3 改 thinkingLevel；Gemini CLI 封顶 8192 防 runaway
- **预算经验值**: OpenAI 25K 预留 + effort 加成（low+1K/medium+5K/high+25K）；Anthropic 生态 ore adapter effort max→80% 保 1024 正文
- **DeepSeek /anthropic 端点**（已裁决不用，备查）: 块共存**真实**（reasoning_content 包装为 thinking 块含 DeepSeek 自签 signature，工具轮=signature-only thinking 块 + tool_use 块，content 永不恒空）；官方 Claude Code 集成指南推荐 effort=max、主 v4-pro[1m]/子 v4-flash；但协议义务转为「thinking 块+签名原样回放（空串填充=状态篡改 400）」；官方未文档化响应结构；Anthropic TOS 合规风险
- **Codex/Responses 形态**（已裁决不用）: DeepSeek 官方适配 `wire_api="responses"` + supported_reasoning_levels low/high/max + supports_reasoning_summaries（默认 none）；v4-flash 工具轮停滞实测（opencodex #875）；v4-pro 支持未生效
