## 2. 发现清单

### M2W-2（P3；dns_refusal.py 健壮性）——只服务 UDP DNS；TCP DNS 查询
（Windows DNS 客户端的 TCP 回退路径）无应答可能退回超时

- 位置：dns_refusal.py `DnsRefusalServer`（仅 SOCK_DGRAM）。实测 TNC
  huggingface.co 复测 735ms 说明当前链路无 TCP 回退问题；但该边界未在
  README 明示。建议 README 补“TCP DNS/QUIC 面未覆盖，若实测出现 TCP
  回退超时需接 WFP 层”。

### M2W-3（P3；dns_refusal.py fail-fast）——`--allowlist-domains` 解析
静默忽略空段；构造时仅校验“有 allowlist 必须有 upstream”，未校验端口
占用/非 root 权限可绑定性（运行期 OSError 才失败）

- 建议：启动前自检 bind/权限并输出清晰错误（现有 selftest 只验 NXDOMAIN
  语义）。

### M2W-4（P3；T2.3 驱动健壮性）——`ORZ_FAKE_SCENARIO` loader 对
“text 与 tool_calls 同时出现”（text 静默胜出）、`call_id` 非字符串
（静默回退缺省）、条目内 `tool_calls: []`（放行空批）三种形状不是
fail-closed

- 位置：orz-bin main.rs `load_fake_scenario`（dd5b1dac）。
- 影响：仅测试驱动，无生产风险；但“fail-closed”承诺与实现不完全一致，
  且空 tool_calls 批可能导致 loop 空转。建议三处改为显式 Err；单测补
  三种形状。

### M2W-5（P3；T2.3 验收口径）——T2.3 仍未闭，且与 01 S3 / 02 M1L-1

## 4. 实机证据数值复核

- Run A（AC）：allowlist_reachable=false，wf12 allowlist_reachable_ms=14
  （0–16ms 即拒）——与 audit “必 FAIL”一致。
- Run B（no-AC）：allowlist_reachable=true（31ms、15–47ms 区间），
  network_blocked 0–16ms、metadata_blocked 0–15ms——audit 声称值与
  证据文件一致。
- egress：前测 total_wall_ms=13,091（job 内另见 13,558 批次）；复测
  total_wall_ms=920、最差 735ms；NXDOMAIN 7ms；DNS_RESTORED=True——
  与 audit 完全一致。
- 结论：T2.2 的验收数值可复核、无虚报；三项结转 FAIL 在证据文件中
  可见，审计边界声明可信。

## 5. 正面发现

- DNS 拒答器默认“不携带域名 allowlist → 全 NXDOMAIN”设计干净：评测端
  直连 IP 走 allowlist-ip，DNS 面全局拒绝，从机制上不泄露 allowlist 域
  内容，符合 P4 最小化。
- 部署可逆性做得完整（保存/恢复网卡 DNS、stop daemon、清防火墙规则），
  且有 op 级断言（WF12_FWRULES 空、DNS_RESTORED）。
- no-AC 探针失败被 spill 到子进程 stdout/stderr 供宿主诊断——本次
  Errno 13 的定位就是靠该 spill 完成的，工具链自证有效。
