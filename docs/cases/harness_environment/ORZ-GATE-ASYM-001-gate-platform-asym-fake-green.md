# ORZ-GATE-ASYM-001 — 守门者平台不对称＝伪绿源（案例候选）

- **状态**：`candidate`（2026-09-18 RS-01 根因收官当日案例化）
- **晋级理由**：检查器自身的平台不对称制造了最危险的失败形态——**本机绿、CI 红**且红灯可稳定复现 16 天无人定位（根因行一直在库内）。守门规则的平台对称性是「本机绿」具备证据力的前提。
- **来源证据**：[`docs/incidents/ORZ-CI-BLINDOUT-001.md`](../../incidents/ORZ-CI-BLINDOUT-001.md) 根因节；`scripts/check_repository.py::_check_markdown_links`（修复 diff 在父仓 `667d7d8d`）。
- **机理**：`(parent / target).resolve()` 对盘符目标（`D:/CLI/...`）在 Windows 是绝对路径（存在→绿），在 Linux 沦为含 `D:` 目录的相对路径（不存在→断链报错）。守门规则依赖了单 OS 的路径语义。
- **能力（纪律）**：
  ①**守门规则须语法级平台对称**——对本地链接拒绝盘符前缀/根斜杠/反斜杠目标（语法规则跨 OS 一致），而非依赖各 OS 的 resolve 行为；
  ②**「本机绿」对跨 OS CI 无证据力**——凡门禁含路径解析步骤，逐条自问「另一 OS 会怎样」；
  ③**存档区豁免须显式**——`存档/` 冻结指针（指向库外 `D:\tb-eval` 的证据路径）按冻结纪律保留，靠检查器的显式豁免区承载而非放行规则。
- **回归入口**：探针三形态（盘符/根斜杠/反斜杠）应被报 `non-relative local link`；全库链接检查应为空。
- **同族先例**：`ORZ-PS1-BOM-001`（编码语法先查——同为「机器可判的语法门替代人工 eyeballing」）。
- **验证记录**：2026-09-18 探针测试全拦＋run 35326045846 起 ubuntu 契约步转绿并保持。
