## §1 摘要

三个设计件互补：**D1／D2 缩短单次派发时长**，**D3 保证同轮多请求时主代理也能尽早拿到回合**。

- **D1 阈值回送**：子代理自判可用来源，满 **5** 条即收尾产出结果总结回送主代理；
  机械护栏 **10** 条兜住"自律失败"的无界形态；护栏倒数**对子代理可见**；允许**提前交付**。
- **D2 未达标交回**：单批墙钟 **300 s**，到点以「部分证据＋缺口＋指针」**正常交回**，不以失败收口。
- **D3 合并优先＋溢出拆轮**：同轮多检索先合并为**单激活多 query**（上限 3），超出部分以"未派发"交回。

## §3 D1 阈值回送

### §3.1 语义

子代理在自己的检索过程中判定"某来源是否可用"（它看得到抓取正文与 SERP 摘要，本就有判断材料）；
累计到 **5** 条即停止继续抓取，产出**结果总结**回送主代理，由主代理决定下一步。

与现状的差别只在**收尾触发条件**：现状是"子代理自认完成"（无条数纪律，r1 gpt2 出现
20/20 搜索成功仍继续搜的形态）；D1 是"够了就停"。

### §3.2 参数（定案）

| 参数 | 定值 | 谁判定 | 作用 |
|---|---|---|---|
| `sufficiency_target` | **5** 条 | **子代理**（用户裁决） | 达标即请求收尾 |
| `mechanical_cap` | **10** 条 | 机械层 | 子代理未自行收尾时的强制收尾护栏（二取一余地） |
| `batch_wallclock` | **300 s** | 机械层 | 未达标也交回（§4） |
| 计数口径 | **宽口径** | 机械层 | 阈值／护栏／可见倒数**共用一把尺** |

**护栏为何必要**：判定权留给子代理是用户的收益判定选择，本文不推翻；但"自律失败"有实证——
r1 gpt2 单批 598 s、r2 extract-elf 单批 636 s 都是在可用证据已足的情况下继续检索。
护栏只做"再不停就停"，**不判断"什么算有用"**，因此不侵占子代理的判定权。

### §3.3 计数口径（定案：宽口径）

计数**不采信模型自报**，用既有 ledger 事实：

- 依据：`build_structured_result` 产出的 `source_counts{total, full_text_observed, partial_text_observed, metadata_only}`
  与每条来源的 `visibility`／`relevance`／`content_sha256`；
- **定稿口径（v1.1 勘误）**：`usable = |{ 按 content_sha256 去重 : visibility ∈ {full_text_observed, partial_text_observed} }|`
  ——即「全文或部分正文的工具证据」；
- **v1.1 勘误依据（2026-09-19 审查处置）**：v1.0 原稿口径含 `∧ relevance = direct`——该限定词在机械计数点
  **不可实施**（工具证据 `EvidenceRecord` 无 relevance 字段），且在本文引用的 ledger 事实上**为空操作**
  （机械 ledger 条目 relevance 恒 `direct`，`evidence.rs` 硬编码）⇒ 收窄为 visibility 口径；§3.3 一手读数
  即该口径读数，S2 实现与读数一致，零行为变更。tangential 语义由 ledger 披露与 prefilter 候选池承载，
  不入机械计数；若后续把关数口径重新引入 relevance，须与倒数行、阈值、护栏**同批改**（§10-6 同理）。
- **一手依据（为何不能用严口径）**：七次已提交批次的严口径（只数 `full_text_observed`）为
  **7／7／6／7／4／6／7**，最大 7 ⇒ 护栏 10 永不触发、形同关闭，与"二取一余地"的意图相反；
  同批次宽口径为 **12／10／21／11／21／14／13** ⇒ 每批都在自然收尾前越过 10，护栏真实生效；
- 软规则（子代理自判）与硬护栏共用同一计数；两者不一致时**记 anomaly**（判据 5），不静默取其一。

### §3.4 收尾形态（定案：β）

| 形态 | 做法 | 取舍 |
|---|---|---|
| α 机械截断 | 达标即不再请求模型，直接用 ledger 装配结果 | 最快，但没有子代理的筛选结论文本 |
| **β 收尾回合（定案）** | 达标后注入中性事实并**把工具面收空**，允许**一次**模型回合成总结 | 保留"结果深入筛选者"定位；工具面收空是机械保证，收尾回合不再烧检索 |

### §3.5 与 effort 档位的关系

阈值回送后，档位从"实际用量"退化为"上限"。档位仍决定 `max_results` 与 SERP 导航预算
（standard 5／extended 8／deep 12；8／16／32），即**单轮抓取宽度** ⇒ 分析件 C1（外部车道 effort 地板）
仍需单独处置，不能算被 D1 顺带解决。

### §3.6 可见倒数（定案）

每批检索结果末尾由**机械层**追加一行（模型不可写；随该次工具结果入**模型面消息**——会话侧车承载，
journal 的 `ToolCompleted` payload 不含该行，**不新增事件类型**；载体口径 v1.1 对齐 S2 实态）：

```
[机械] 本批可用证据 3/5；距强制报告额度上限还剩 7 条（上限 10）。本轮已发起检索调用 12 次。
```

- **目的**：把护栏从隐形的黑箱变成子代理**可规划的资源**（0ac「即时且有信息量」契约的直接延伸），天然抑制无界检索；
- **口径歧义（必须钉住）**：护栏 10 计的是**可用条目**而非**检索调用次数** ⇒ 文案必须**同时报两个数**
  （条目额度／已发起调用数），否则子代理会把「还剩 7 条」误读为「还能搜 7 次」，护栏会从上限变成配额；
- **同一把尺**：倒数读数、子代理自判、机械护栏三者同口径（§3.3）。

### §3.7 提前交付（定案）

- 语义：子代理**不满 5 条**也可主动请求交付（例如判定「本题 2 条即够」）；
- 形态：在 β 收尾回合里以**显式标记**声明（**零新增工具面**，遵守主面工具纪律），
  机械层解析为 `terminal_reason = subagent_early_delivery`；
- 硬性要求：提前交付**必须带证据指针**（已得 ledger／`archive_ref`）；缺指针则按普通收尾处理（fail-open＋anomaly）；
- 收益：杜绝「为凑满 5 条而灌水」——硬凑数会诱发低质量抓取；
- 风险护栏：连续 N 次提前交付且可用计数 <5 时落 anomaly（可审计、不阻断）；主代理仍可按 §5 续派。

## §4 D2 未达标交回与单批 300 s（定案）

### §4.1 300 s 依据

| 形态 | 实测 | 300 s 下的行为 |
|---|---|---|
| r3 torch 首批（达标） | 206 s | **不受影响** |
| r1 gpt2 batch1 | 598 s | 截断至 300 s（−298 s）后交回 |
| r2 extract-elf batch1 | 636 s | 截断至 300 s（−336 s）后交回 |
| r1 torch batch2／batch3 | 390 s／289 s | 前者截断、后者不变 |
| r2 gpt2 batch2、r1 gpt2 batch2 | 228 s／232 s | 不受影响 |

**余量提示**：300 s 相对达标批次 206 s 仅 **1.45×** 余量；在本轮实测单次 p50 20–27 s 与子代理首回合延迟
叠加下，会有相当比例批次"接近达标但未达标"⇒ 300 s **必须与"未达标也交回"配对**，否则会把可成功批次变成失败。

### §4.2 交回形态

到点交回 = **部分证据报告**：已得来源数／可用条数／缺口说明（如「可用 3/5，已检索 12 次，
末三次无新增来源」）＋证据指针（ledger 分区／`archive_ref`）；
**不以 `subagent_failed` 收口**（现状 0ac ⑥ early-close 走失败臂，本设计不复用，见 §7）。

### §4.3 档位表（定案）

| 档位 | 现状墙钟 | 定稿 | 适用 |
|---|---|---|---|
| standard | 240 s | **180 s** | 单点事实查询 |
| extended | 600 s | **300 s** | 一般检索／评测主用 |
| deep | 900 s | **450 s** | 显式「调研/比较/综述」类（现由 breadth 词面命中升档） |

日常检索与调研由**批数**承载（多批 × 300 s），不靠单批无限延长；deep 保留一倍余量覆盖跨源深度调研。
`ORZ_RETRIEVAL_SUBAGENT_TIMEOUT_SECS`（显式 env）**优先级不变**，仍可覆盖档位默认。

## §5 D3 合并优先＋溢出拆轮

### §5.1 现状机制（代码事实）

1. 一轮模型响应可带多个 `tool_calls`；主循环**按声明序逐个执行**（`while tool_idx < response.tool_calls.len()`）；
2. 只有**开头连续一串**「可并行读类」调用走并发批（`parallel_read_eligible`；集合 `PARALLEL_READ_TOOLS`
   ＝read_file／grep／list_dir／search_tool／web_fetch／browser_read／blackboard_read／memory_*／lsp）；
3. **`web_search` 不在该集合**，注释明确「生成式检索，信号量=1＋pacing 纪律」保持串行；
4. 主车道 `web_search` 路由到 `DispatchTarget::ExternalRetrieval`（`relay::route`），
   执行体是**同步 await 的检索子代理会话**；
5. ⇒ **同轮第 2 个 `web_search` 必须等第 1 个子代理会话整体收口才开始；主代理要等该轮全部 tool_calls 返回才进下一轮。**

### §5.2 一手证据

r3 torch：一轮内 2 次 `web_search`（16:49:06）⇒ 第一条派发 16:49:06→16:52:32（206 s，**含答案**），
第二条**在同一条 `retrieval_close_record` 的同一秒**启动，跑到 17:01:46 墙钟 ⇒ **主 agent 全场只有 1 个回合**。
r1 gpt2／r2 extract-elf／r2 gpt2 同形（首批后主回合 1／0／0）。

### §5.3 为什么是结构问题

模型并列多个检索请求表达的是**并行意图**；框架实现为「串行＋不可撤销＋主代理整轮阻塞」。
模型既看不到这是串行，也无法在第一个结果回来时改变主意——**它没有回合**。

### §5.4 定案方案

| 方案 | 做法 | 结论 |
|---|---|---|
| R-1 轮级单席位 | 每轮最多派发 1 次检索，其余结构化"未派发" | 作为**溢出兜底**保留 |
| R-2 合并同轮多 query | 同轮 N 个检索合并为 1 个激活 | 作为**主路径** |

**定案：合并优先＋溢出拆轮**

1. **合并优先**：同轮多个检索调用**先合并为同一激活的多 query 任务**——结果契约的 `query_summary`
   本就是数组（`runtime/retrieval-result-event-payload-v0.2.schema.json`），多 query 单激活在契约上已有位置；
   子代理对合并任务给结果总结，收尾阈值按**批级合计**；逐 query 计数降为**可核披露**
   （`query_summary` 逐条携带宽口径可用计数，主代理据此对未覆盖 query 自主续派——裁决权归主代理）。
   **v1.1 勘误**：v1.0 原稿「阈值逐 query 计数」与护栏 10 不相容（逐 query 5×3=15 > 10，合并激活将恒触
   护栏、阈值形同虚设），且护栏 10 系用户定案参数——放弃逐 query 收尾语义，覆盖保障改由
   「逐 query 披露＋主代理续派」承担；若 S3 真机读数显示合并批覆盖受损，可凭读数再提逐 query
   参数组（逐 query 阈值＋逐 query 护栏）另行裁决。
2. **溢出兜底**：同轮检索调用数超过**合并上限 3 query／激活**时，超出部分按 R-1 形态返回
   ——无 `ToolStarted` 的预派发拒绝，`cause=retrieval_dispatch_deferred_one_per_round`，交回主代理下一轮决定。
3. **二者互补**：合并让子代理承担更重任务（用户取向：与主代理同水平、不必过度弱化），
   消除 N 倍往返与 N 倍子代理额度；溢出底座保证"一轮发了 5 个搜索"也不会让主代理失去回合。

**与工具面纪律的关系**：合并发生在**契约文本与派发调度层**，主面工具仍是 `web_search` 一个入口；不新增工具。

### §5.5 模型面文案（溢出拒绝，中性事实）

```
[web_search] 本轮已派发 1 个检索激活（query: "<已派发>"，合并上限 3）；
本调用未派发（cause: retrieval_dispatch_deferred_one_per_round，deferred_call_id: <call_id>）。
```

配**一次性重述**（去重、仅下一轮开头出现一次）：「上一轮有 1 次检索未派发」，避免模型漏看丢覆盖。

### §5.6 幂等与风险纪律

1. **模型原样重发**：最多浪费一个回合（p50 约 8 s）；同一 `query` 字符串在同一 run 内已派发过 ⇒
   机械层**回踩已有结果的 `archive_ref` 指针**，不重复检索；
2. **覆盖率下降**：被推迟的 query 若未被重发，由 §5.5 的一次性重述兜住；
3. **不教学**：文案只报事实（已派发／未派发／cause），不含"建议拆成多次"之类指引（FP-2 纪律）。

## §8 判据（可机械核对）

1. 每次派发的 `retrieval_close_record.terminal_reason` ∈ {…, `evidence_threshold_met`, `dispatch_wallclock_bound`, `subagent_early_delivery`}，
   且 `dispatch_wallclock_bound` 必带「已得计数＋缺口」字段；
2. 单批派发墙钟 ≤ `batch_wallclock` ＋ 收尾回合耗时（默认 300 s ＋ 一次模型回合）；
3. 首批 commit 之后主 agent **回合数 ≥1**（对 r1–r3 语料回放应达 100 %）；
4. D3 生效时：溢出调用返回 `cause=retrieval_dispatch_deferred_one_per_round` 且**无对应 `ToolStarted`**；
5. 软规则与机械护栏计数不一致时落 anomaly（不静默取一）；
6. 合并激活的 `query_summary` 条目数 = 本轮被合并的 query 数，且**逐 query 可用计数**可核；
7. 提前交付必带证据指针；可见倒数行与该批 `source_counts` **同口径一致**（宽口径）。

**验收读数**（沿分析件 §6，五项均不依赖投递族事件）：主回合数、首批 commit→首次落盘间隔、
落盘时距墙钟剩余、检索族墙钟占比、首批后续派发数。

## §9 批序（已裁决）

1. **S1 契约面**（schema＋fixtures＋pytest）——零行为变更、可独立验收；
2. **S2 实施面**——三件**可分笔实施**，顺序 **D1 → D2 → D3**
   （D1 单件即可覆盖 r1 gpt2／r2 extract 的无界形态；D3 改派发调度层、变动面最大，放最后以便前两件先落地读数）；
3. **S3 真机复验**——同三题同口径 `k=1` 复跑，按 §8 判据＋验收读数收取；
4. **ADR-0010 转录随 S2 同批**（不单独成批）。

各步独立放行，**不得跳步合批**。用户 2026-09-19 已同意全部判定 ⇒ **S1 具备放行条件**，实施启动以实施令为准。

## §10 开放项与风险

1. 阈值 5 对"必须跨多源交叉验证"的题型可能偏小（碎片化检索）；护栏 10 与档位宽度是缓冲；
2. β 收尾回合带来每批一次模型调用；用户裁决不设硬节流 ⇒ 只做去噪三项：空批不唤醒／批间不重置任务契约
   （contract revision 不变）／重复 query 回踩已有结果指针
   （**S2 范围注记，v1.1**：批间契约不重置由既有 M4 continue 语义满足；空批不唤醒与重复 query 回踩
   未随 S2 实装，登记并入 S3 前处置范围——见 BACKLOG 0ar）；
3. 300 s 与 206 s 余量仅 1.45× ⇒ 慢网下"未达标交回"会变常态，交回文案必须携带足够缺口信息；
4. r3 gpt2 形态（零检索亦不交付）不受本设计影响（§9.2 已裁决不干预）；
5. **提前交付滥用**：频繁以 <5 条提前交付会使批数上升、覆盖变窄 ⇒ anomaly 观测（不阻断）；
6. **可见倒数口径漂移**：若后续把关数口径改回严口径，倒数读数会与「还剩 N 条」的实际效果脱钩（须同批改）。

## §11 实施前提

- S1 契约面先行；S2 每件带钉子；S3 同三题 `k=1` 真机复验（载体与适配器身份按当轮锁定值）；
- 不改任务镜像／verifier／数据集 pin；不在 orz 做容器内环境提前补强（沿用 2026-08-29、§10.8 裁决）；
- 不针对单一 benchmark 调参：D1/D2/D3 参数对日常检索／调研场景同时成立。
