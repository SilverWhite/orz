## 2. 残余压力清单（模型每轮实际经历）

### 2.1 常驻契约面（每轮都在）

- **8 工具类型签名 + Result 信封（summary≤200B / cap / pointer / payload）+
  GetPut 律 + term/pipe 文法**。模型须记住合法组合；不兼容 pipe 被类型化拒绝
  （`pipe_incompatible`，任一工具不执行）；search_replace 锚点语义（未给锚点取
  最近 read、错锚 anchor_mismatch、n>1 ambiguous fail-closed）。
- **blackboard_read：6 分区 + temporal 四查询面**（now/recent/history/feature，
  字段 u_prog/u_err/u_stuck/T̂/err10/succ10）。零常驻 token 的另一面 = 「何时
  该 PULL、查哪个面、k 取多少」由模型自决——新增元决策负担。V3 冒烟中模型是
  「按提示精确查 4 次」，真实任务无提示。LIF 参考系每独立 run 从头确定
  （run 起点归一），时间特征只表达本会话内部相对时间。

### 2.2 周期打断面（不每轮，长任务反复）

- **12 类注入块仍注册**（inventory §1.3）：反例门（终答前一次自查）、
  orientation 软门（50 轮三问）、DC 强制模板轮（禁工具，最重）、机械审计
  终答前执行事实报告、动作台账、压缩标记、状态行、预算、breaker、
  checkpoint refill 等。每次注入 = 一次注意力切换 + token 消耗 + 偏离主任务
  风险。
- **已闭合**：LIF fires 不注入（设计 §9.7 裁决），数学体未新增打断面。

### 2.3 错误反馈面（10 题批次实证大头）

- 命令非零退出（exit_1/127）、模型幻觉工具名（10 个变体：run_terminal_cpt /
  句 / craft / cell / cplet）、浏览器结构化错误（空页/坏 scheme）、候选 cap
  拒绝、is_background 拒绝、access_in_scope 拒绝、检索降级 transition、
  web 120s 超时错误、300s 中间回报（tool_running）。每条 = 一次「继续/换路/
  重试/诊断」决策。
- 半助理层 diagnostics 已把「诊断」机械化（≤2KB 签名词典），但「消费错误并
  决定下一步」仍在模型。

### 2.4 生成约束面（写错即打断）

- search_replace 锚点、submit 两阶段、生成期守卫（复读 L400/W800/门槛 20/
  标点块 0.50/802 线、3-gram 0.70/门槛 15、空响应链 ≤2 次/档 + backoff
  0.5–10s、DEGENERATION_LIMIT=3 → run_invalidated）。守卫触发即打断并烧轮。

### 2.5 时间/上下文

- 每轮墙钟 10–22s（max effort 推理 + 工具执行；mteb 228 轮/3600s）；256K 上限、
  128K fold、tail 8K、每轮注入 50K；journal 命中率 82–98%（对照官方 98%+，
  观察项）。
- **关键观察**：跨轮簿记只转移了一半——temporal 分区 + 内容寻址已落，依赖图
  未实施，模型仍靠动作台账/黑板/实体注册表兜底跨轮记忆。

### 2.6 核心残余：下一步动作决策

- 8 选 1 + 参数 + pipe 组合 + 何时 PULL temporal + 何时 submit + 失败分支。
  设计宣称唯一保留给模型的成分，不可也不该机械化为自动动作（否则即干预模型
  怎么做，超出本项目边界）。

## 3. 与跑分的关系（用户裁决边界）

- 官方 minimal mode 2 工具 82.7%；Ante 完整工具面亦 82.7%（同模型同 benchmark）。
  工具数量不是差距主因 → 工具面冻结，不再删除。
- 差距主体在「总工作量 > 墙钟」（08-29 画像 18/23 超时），修复方向是执行侧
  成熟度（web_search 120s、终端分层超时、fold 桥修复），不是跑分特化。
- 只做通用修正：任何正常使用都受益的改动（见 §4）；不为跑分特化（按任务预置
  数据清单、按任务开关工具等均不做）。

## 4. 可通用降低的候选（供深度讨论，非裁决）

1. **依赖图实施**——把「跨轮簿记」真正移走（设计已承诺未兑现）；机械层加厚、
   模型层零改动，符合 P6。需界定最小可用范围（锚点/实体边随归约维护）。
2. **注入块重复面清理**——TOOL_ROUND_BUDGET / TOOL_POLICY_BREAKER 与工具轮
   上限、sealed 拒绝的重复面（inventory §8.2 已点名）。
3. **错误反馈一致性**——Fail code → 结构化动作提示映射统一（R2 拒绝词汇表已
   镜像，可继续收口）；注意与「机械审查不给建议」的边界（给事实，不给判断）。
4. **工具名相似度**——幻觉变体源于工具名近拼；改名有兼容成本，是否值得由用户
   定；否则登记已知边界。
5. **「何时 PULL temporal」元负担**——极轻提示（如每 N 轮一行）vs 维持零打扰；
   与 P6「注入面扩张」的张力，属设计决策。

## 5. 冻结边界（不动清单）

- 8 工具面（不再删除）；模型档位 max；k=1 多次尝试不做；机械层环境探测前置
  不做（用户裁决）；`.gsa` 写/删保护不做（登记已知边界）；不为跑分特化。

## 8. 深度讨论裁决收口（2026-08-31 用户确认）

> 性质：裁决记录（讨论稿内收口，不替代设计权威）；实施/设计登记见
> BACKLOG P2-11 / TODO P2-11。10 题小批证据：temporal 分区 0 查询、
> pipe 0 使用、锚点拒单 0 次、复读守卫 0 触发、工具名幻觉 15 次自回正、
> 浏览器结构化错误 3 次、DC 0 触发。

1. **PULL 自描述（采用）**：`blackboard_read` 任意分区查询响应携带「自上次读取
   以来」增量（分区变化计数 + temporal 域迁移摘要），temporal 单次查询按模型
   意图尽量一次返回所需内容（控制返回量 ≤1 KiB、简单描述、不让模型为补齐信息
   二次查询）。零注入、模型无感边界不变（无新常驻 token、无主动注入）。
2. **DC 强制模板轮清理（裁决：删除）**：需求低（本批 0 触发；`run_tests` 封存后
   主信号源死亡；模型增强后收益不足），连同 plan 反例变体注册（无点火路径）一并
   清理；P3「DC 硬信号 4/6」遗留项随机制退役。checkpoint 共用件按需拆分
   （orientation 软门与 console 询问轮保留）。
3. **错误反馈一致性收口（采用）**：类型化错误信封 `Fail` 增机械分类位
   `retryable: bool`——确定性失败 false（scheme / 锚点 / sealed / cap），暂时性
   true（超时 / 网络）；错误码事实推导、非建议，schema/verifier/fixtures 先行。
4. **search_replace 锚点 / submit 两阶段（维持现状）**：锚点拒单本批 0 次、
   submit 8 次全通，优化收益不足，不做；复读守卫不可让步（本批 0 触发）。
5. **工具名幻觉（登记已知边界）**：不改名、不加别名——学习成本 + 兼容面 +
   收益上限约 15 轮/10 题（≈2% 墙钟）且无阻塞；fail-loud 自回正维持。
6. **跨轮簿记（依赖图）**：下一轮主线。最小范围=文件锚点链（read→write 锚点边
   + 工具→实体变更边；D3 命令/检索副作用不建图），PULL 查询面、模型零改动；
   顺带闭合 F11 receipt↔事件链逐段同构核对。
