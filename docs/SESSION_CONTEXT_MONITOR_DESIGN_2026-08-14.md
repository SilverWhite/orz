# 会话累计上下文监测设计（2026-08-14）

> 状态：设计已确认（2026-08-14 用户）；实施未开始；权威登记：ADR-0010 §14.13（v1.13 补写）。

## 1. 定义与边界

- 度量：**当前会话累计模型可见输入 token**——usage 实报优先，缺失时 journal 估算兜底。
- 与压缩独立：压缩机制把请求窗口钉在 384K 内（160K 触发 / 200K 兜底），本监测是会话生命周期信号，不干预压缩、不改变请求窗口。
- 非目标：不做上下文窗口预测；不自动调整压缩触发；不自动开新窗口；不打断 headless/自动化运行。

## 2. 阈值与行为

| 阈值 | 行为 |
|---|---|
| 384K | 机械提醒（默认；阈值可配） |
| 500K | 机械总结推荐（默认；阈值可配） |

- 最简实现：在到达阈值的「最后一轮模型输出末尾」机械附上一句提醒。
- 500K 推荐内容：复用压缩五段模板（目的/计划/变动文件路径/注意事项/后续衔接）+ 一段「新窗口开场」提示骨架；只给产物，不自动开新窗口。
- headless / 自动化：仅写日志，不附加模型可见提醒（无用户侧）。

## 3. 实施要点

1. 度量接线：模型完成轮后累加 usage 输入 token（transport/loop 完成点）；usage 缺失时按 journal 估算。
2. 阈值配置：env/TOML 可配（默认 384K / 500K）。
3. 机械附言注入点：到达阈值的最后一轮模型输出末尾（主车道；headless 仅日志）。
4. 测试：阈值到达/未到达、usage 缺失兜底、headless 分支、幂等（同一阈值只触发一次）。
5. 实施审计与 BACKLOG/TODO/索引状态同步。
