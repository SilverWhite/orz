# 会话压缩次数监测设计（2026-08-14；2026-08-16 度量重定）

> 状态：设计已确认（2026-08-14 用户）；实施未开始。2026-08-16 用户裁决：度量由
> 「会话累计模型可见输入 token（384K/500K）」改为「会话内压缩次数」——累计 token 对模型
> 不可见、阈值无对应质量边界，压缩次数是会话寿命/摘要链损耗的更直接代理；权威登记：
> ADR-0010 §14.13（v1.13 补写），§14.18（v1.18 补写）取代其度量条款。

## 1. 定义与边界

- 度量：**当前会话内已执行的压缩次数**——以 `context_compressed` 事件为准，仅计
  reason∈{rhythm, fallback} 的会话内压缩；`session_end` 不计（该压缩发生在 run 结束、
  属存档动作，计入会稀释会话寿命信号）；一次压缩只计一次，重试/守卫失败/存档失败不重复计数。
- 与压缩独立：压缩机制把请求窗口钉在 384K 内（160K 触发 / 200K 兜底），本监测是会话生命周期信号，
  不干预压缩、不改变请求窗口。
- 非目标：不做上下文窗口预测；不自动调整压缩触发；不自动开新窗口；不打断 headless/自动化运行。

## 2. 阈值与行为

| 阈值 | 行为 |
|---|---|
| ≥2 次 | 机械提醒（默认；阈值可配） |
| ≥3 次 | 机械总结推荐（默认；阈值可配） |

- 语义对应：每次压缩约代表一个窗口的累积（160K–200K），2 次≈旧 384K 提醒、3 次≈旧 500K
  推荐；默认值待校准，配置优先于默认。
- 最简实现：在到达阈值的「最后一轮模型输出末尾」机械附上一句提醒（附当前压缩次数）。
- ≥3 次推荐内容：复用压缩五段模板（目的/计划/变动文件路径/注意事项/后续衔接）+ 一段
  「新窗口开场」提示骨架；只给产物，不自动开新窗口。
- headless / 自动化：仅写日志（含压缩次数），不附加模型可见提醒（无用户侧）。

## 3. 实施要点

1. 度量接线：监听 `context_compressed` 事件（reason=rhythm/fallback）累计会话内次数；
   `session_end` 不计；同一次压缩只计一次。
2. 阈值配置：env/TOML 可配（默认 2 / 3）。
3. 机械附言注入点：到达阈值的最后一轮模型输出末尾（主车道；headless 仅日志）。
4. 测试：阈值到达/未到达、session_end 不计、同一次压缩只计一次、headless 分支、幂等
   （同一阈值只触发一次）。
5. 实施审计与 BACKLOG/TODO/索引状态同步。
