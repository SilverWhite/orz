## 0. 需求与动机（run `RUN-CLI-6aa7e0aa` 一手证据）

- 台账折叠 66 次、末段每 4–5 分钟一次：任务线 15:52 断裂（orientation 回答退化到 hour-0 状态）、362 行自产代码被表述为「上一轮遗留」、`agent_loop.rs` 180 次分窗读取中 ~70 次纯重读、终局虚构「协调者指令」。
- 模型需要的（代码结构、接线结论）恰是机械折叠无法保留的；能折叠且可追溯的（命令流水、工具摘要）是可折的。⇒ 「留什么」交给模型，机械层并存（执行折叠＋兜底）。
- 经济面：每次折叠 = prefix cache 全量失效；66 次 ≈ 66×~120K ≈ 800 万 uncached input tokens。
- 恢复面错配：`blackboard_read` ×87（plan 30/session 25/edits 11/exec 5）；`plan_write` ×0；折叠台账近 write-only。

## 3. D0 黑板写入面（新增承重件）

- **现状**：模型面无任何写黑板工具（§1 探针实据）；黑板各分区由机械层单写者维护（edits/exec/processes/session 等）。
- **设计**：新增模型工具 **`blackboard_write(section, content)`**，可写分区限 **`plan`** 与新增 **`notes`** 两个域（`notes` 为新分区，模型自有工作笔记）；机械单写者分区（edits/exec/actions/processes/temporal/session）**不开放写入**，所有权不变。
- **约束**：写入走既有黑板结构化盖章（(round,domain) 写时盖章）、渲染折叠、存档打包全套既有语义；单次写入 ≤8K；写入落 journal 复用 `plan_write` 事件族并扩展 `section` 字段（零新族，行集纯增量）。
- **水位可视（用户定案）**：黑板 live 字节水位改为**明示状态标**——`blackboard_read` 各分区响应头带 `【3.2M/10M】` 式读数（复用 PULL 自描述增量头扩展），D2 各阶梯提醒文本携带当时水位，既有 10MiB 疲劳提醒机制不变。
- **工具面冻结纪律**：8 工具面冻结为「不再删除」；本件为**用户主导的新增**（2026-09-15 口径「明确提示可使用黑板」），登记为冻结纪律的显式例外。
- **DP-6**：工具形态（独立 `blackboard_write` vs 复活并泛化 `plan_write`）与 notes 分区命名。

## 4. D1 首轮 plan 问询＋补救规则（用户已同意方向）

- **触发**：首轮动作批次结束（`post_tool_batch_gap`），复用 0x initial-round inquiry 票据与注入机制，追加一问：「请将本任务的工作计划与关键中间结论写入黑板 plan/notes（`blackboard_write`）；黑板不受上下文折叠影响，920K 压缩时只有黑板内容与保留尾可依托。」
- **补救规则（用户已同意）**：至第 **N** 轮仍无任何 `blackboard_write`（建议 N=20，DP-2）→ 再提醒一次；此后不再提醒、不设硬门。
- **判据**：长实现类 run `blackboard_write` ≥1；折叠后重读率（唯一 offset/总读取）显著下降（本轮基线：`agent_loop.rs` 180 读/110 唯一 offset）。

## 5. D2 注意力阶梯（用户已定框架；1M 窗口口径）

| 阈值 | 形态 | 内容要点 |
|---|---|---|
| 128K | **打断式**提醒 | 注意力管理开始：请将接线结论/关键读数固化至黑板 plan/notes；预告后续阶梯（300K→700K 软提醒、800K 最后通牒、920K 强制压缩） |
| 160K | 不打断的提醒式 | 随下一合法边界附注，不单独成块 |
| ~~200K~~ → 300K | 软提醒 | 固化进度问询：若尚未固化，此刻是低成本窗口 |
| 500K / 600K / 700K | 软提醒 | 同上，语气随阈值递进 |
| 800K | **截断式硬提醒**（最后通牒） | 920K 将打断全部动作进入压缩；未固化内容届时丢失，唯一保留面=黑板＋保留尾 |
| 920K | **打断全部动作 → 进入压缩** | 压缩**具体实施交给模型**：固化必要内容至黑板（明确提示可用）、标注可弃范围；机械层按模型标注执行折叠并落台账/桥 |

- 形态定义：**打断式**＝独立注入块、作为下一请求首个注入块要求消费；**提醒式/软提醒**＝附随下一合法边界（mechanical audit 附注等）不单独成块；**截断式硬提醒**＝独立注入块＋升级语气＋明确后果。
- 每阈值只触发一次；920K 压缩完成后全阶梯**重新武装**（从 128K 起）。
- 长视图质量读数：**用户已裁定接受**（orz 为通用框架，不做逐模型窗口适配；参数 env 可配即天然多模型可移植）——DP-3 就此关闭，不做强制探针；V4 论文塌陷带（384K–512K）对 V4.1 的适用性作为已知未知项登记于 §9。

## 6. D3 机械压缩并存、920K 压缩实施交模型（「机械辅助模型压缩」）

- **并存结构**：机械层保留全部现有机制（折叠执行、外挂台账、桥、审计双轨、整轮配对、依赖完整性三纪律）＋新增阶梯提醒发射器；模型负责「留什么」（经 D0 写入面固化）与 920K 压缩的具体实施（固化＋标注可弃范围）。
- **920K 压缩轮语义**：打断全部动作（不再派发新工具调用）→ 注入压缩任务块（可用黑板提示＋当前视图结构摘要）→ 模型进行固化与标注（有限轮数内，建议 ≤3 轮，DP-7）→ 机械层按标注执行折叠（标注区折叠、未标注区按保留尾策略）→ 事件与 marker 标注 `model_participated: true`。
- **兜底的兜底（DP-7）**：模型超轮未完成固化/标注 ⇒ 机械无差别折叠照旧执行（今天的机制），`model_participated: false` 如实落账。机械压缩风险（本轮实证的失忆）由「提醒阶梯＋黑板固化」前置缓解，由本兜底封底。
- **不动项**：8 工具面冻结（D0 为用户主导显式例外）；FP-2；检索子代理折叠策略（main lane only）；ACAF/权限/墙钟。
