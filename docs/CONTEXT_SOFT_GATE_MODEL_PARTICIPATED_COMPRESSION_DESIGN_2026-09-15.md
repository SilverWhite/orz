## 0. 需求与动机（run `RUN-CLI-6aa7e0aa` 一手证据）

- 台账折叠 66 次，末段每 4–5 分钟一次（128K 触发线）：任务线 15:52 断裂（orientation 回答退化到 hour-0 状态）、362 行自产代码被表述为「上一轮遗留」、`agent_loop.rs` 180 次分窗读取中 ~70 次为纯重读、终局虚构「协调者指令」。
- 模型需要的（代码结构、接线结论）恰是机械折叠**无法保留**的；能折叠且可追溯的（命令流水、工具摘要）是**可折**的。⇒ 「留什么」应交给模型（经黑板固化），机械层退为**辅助**（执行折叠＋兜底＋桥/台账维护）。
- 经济面：每次折叠=prefix cache 全量失效；本轮 66 次 ≈ 66×~120K ≈ 800 万 uncached input tokens 纯消耗于折叠扰动。
- 恢复面错配：`blackboard_read` ×87（plan 30/session 25/edits 11/exec 5/processes 2/actions 3/temporal 1）；**`plan_write` ×0**——唯一能免费带知识过折叠的面（黑板，折叠不灭）从未被写入；折叠台账（exec）实际近 write-only（轮数展开全程仅用 1 次）。

## 1. 现状机制盘点（参数以本 run 实测为准）

| 机制 | 现行参数 | 本轮表现 |
|---|---|---|
| 台账折叠（FUS-LEDGER-FOLD-STATE） | 视图估算 ≥128K 触发（`ORZ_FOLD_TRIGGER_TOKENS`），保留尾 8K 级（实测 9.6K） | 66 次；无差别切割，知识面随之丢失 |

## 2. 设计总览（四件）

- **D1 首轮 plan 问询＋补救规则**（§3）：让黑板从 run 起点就开始承载知识。
- **D2 注意力阶梯（软门化）**（§4）：1M 窗口下的提醒/兜底双线，机械折叠触发线改造为固化提醒（DP-1）。
- **D3 机械压缩辅助模型压缩**（§5）：模型经黑板固化决定「留什么」，机械层执行折叠/压缩并兜底；不新增工具、不动 8 工具面冻结。
- **D4 折叠桥内容增补**（§6）：桥内机械段携带自编辑清单＋run 起始基线，机械解决出处/基线失忆。

## 3. D1 首轮 plan 问询＋补救规则

- **触发**：首轮动作批次结束（`post_tool_batch_gap`），复用 0x initial-round inquiry 的票据与注入机制，追加一问（或独立问询）：「请将本任务的工作计划与关键中间结论写入 plan（`plan_write`）；黑板与 plan 不受后续上下文折叠影响。」
- **补救规则（用户已同意）**：若至第 **N** 轮 `plan_write` 仍为 0（建议 N=20，DP-2），再提醒一次；此后不再提醒（不刷屏、不设硬门——吸取 P0-C2 plan-first 硬门教训：强制模板先于上下文存在即空转）。
- **为什么是 plan/黑板**：黑板折叠不灭，是全框架唯一「免费跨折叠」的记忆面；本 run 证明模型会主动 `blackboard_read` 找状态锚（30 次 plan 空读），只是没人要求它写。
- **判据**：长实现类 run `plan_write` ≥1；折叠后重读率（唯一 offset/总读取）显著下降。

## 4. D2 注意力阶梯（1M 窗口；核心未验证项已标注）

用户口径：DeepSeek 现为 **1M 上下文**。阶梯：

| 阈值 | 动作 | 文本要点 |
|---|---|---|
| 折叠/压缩现行触发线（128K/160K，DP-1 定去留） | 第一次固化提醒（仅提醒，不折叠） | 「上下文已增长，细节召回将衰减；请把必要结论固化到黑板/plan」 |
| 700K | **最后一次打断式提醒** | 升级语气：注意力明确衰减、固化最后期限、920K 将机械硬压缩 |
| 920K | **机械硬压缩**（沿用现有折叠/压缩机制，无差别、模型无选择权） | 事件与 marker 标注 `hard_backstop` |

- **注入纪律**：合法边界注入（轮末/post-tool-batch，与 0ac 即时回报的成本模型一致）；每阈值一次，不重复刷屏；文本必附可执行动作清单。
- **DP-1（本稿最大决策点）：现行 128K 机械折叠的去留**。两选项：
  - **选项 A（保守保留）**：128K 折叠照旧，阶梯改挂「累计会话 token」计数（视图恒 ≤~130K，700K/920K 为会话级门）。⚠️ 本 run 的失忆循环在此选项下**会原样复现**（折叠仍是机械无差别），本设计仅新增提醒与桥增补——风险不改，收益有限。
  - **选项 B（软门化，本稿推荐）**：128K 机械折叠降级为第一次固化提醒，视图可长至 920K；折叠只在 920K 机械执行（现有机制）。收益：缓存近乎全命中（本轮 66 次 cache 全失效消失）、重读风暴消失、模型真正参与记忆管理。风险：**V4.1 在 >130K 视图上的检索质量无读数**——V4 论文的塌陷带（384K–512K）对 V4.1 是否平移/消失未知（用户已点名此疑问）。
  - **推荐路径**：B 以**探针为前置**——实施前先做一手验证（provider 官方窗口/长上下文质量口径，或 MRCR 式小探针复测 V4.1 塌陷带位置），探针结论决定 700K/920K 定案值；参数全部 env 可配（新增提醒阈值 env，保留 `ORZ_FOLD_TRIGGER_TOKENS` 系列），可随时回退 A。
- **DP-3**：700K/920K 是否探针后再定案（本稿建议：是）。

## 5. D3 机械压缩辅助模型压缩

- **分工**：模型＝决定「留什么」（经 `plan_write`/黑板固化必要结论、接线地图、编辑清单——由 D1/D2 的提醒显式引导）；机械层＝执行折叠/压缩（现有机制不变：命令流水可折可追溯，三条既有纪律——整轮配对、审计双轨、依赖完整性——全部保留）、维护外挂台账与桥、920K 兜底。
- **压缩选择权的表达形态**：**不经新工具**（8 工具面冻结不动）。模型通过「固化行为」表达去留——被写入黑板/plan 的内容天然不受折叠影响（黑板折叠不灭是本设计的承重墙），未固化的命令流水按现行机制折叠。
- **与 DP-1 的耦合**：选项 B 下模型的固化职责变重（不固化即失），D1/D2 的提醒是唯一引导面——若 A/B 实测固化行为不发生，回退选项 A 或追加提醒频次（DP-2 联动）。

## 6. D4 折叠桥内容增补（机械解决出处/基线失忆）

桥内新增机械段（零模型调用，+数百 token）：

1. 本 run 自编辑文件清单（路径＋编辑次数＋末次时间）；
2. run 起始基线（worktree 干净与否、HEAD、关键起始读数）；
3. 最近 N 次编辑指纹（路径＋receipt）。

解决本 run 实证的两类失忆：362 行「上一轮遗留」误述（出处）、edits 面缺基线不可判读（基线）。**DP-4**：是否随本设计一起落（本稿建议：是——它与 DP-1 两选项正交，先落即收益）。

## 7. 判据（A/B，长实现类 run ≥2h）

- 重读率（唯一 offset/总 read_file）——本轮基线：`agent_loop.rs` 180/110；
- fold 后任务线断裂次数（orientation 回答退化判读）——本轮基线：1 次（15:52）；
- 出处/基线正确率（交接件自述 vs journal）——本轮基线：2 处失准＋1 处虚构；
- `plan_write` ≥1；折叠次数（B 选项下应 ≈0，A 选项下不变）；cache 失效次数；
- 同批交付量（落码行数/编辑数）——本轮基线：362 行＋7 编辑。

## 8. 边界

- 不动 8 工具面冻结；不改 FP-2；检索子代理折叠策略不变（main lane only）；ACAF/权限/墙钟机制不变；不新增常驻注入（提醒均为阈值触发的一次性注入）。
- V4.1 注意力适用性未验证前，全部阈值 env 可配；探针结论回写本稿后参数方可定案。
- 本稿不改变 0ac ①-b 的任务边界（提交/推送/重建仍按批另行放行）。
