## 0. 触发与依据（为什么必须重跑）

**代际事实（一手来源）**：DeepSeek 于北京时间 2026-09-10 12:00 发布 V4.1 Flash
并下线 V4 Flash；模型名 `deepseek-v4-flash`（本项目全部官方跑批固定使用该名）
被**暂时路由**到 V4.1 Flash，**兼容路由无公布截止日**。

**盘面事实（地面真值）**：`jobs-official` 全部官方批次 234 份 `result.json` 全量
扫描 → verifier 1.0 共 **81 条**、涉及 **77 题**；其中跑在 V4.1 Flash 上的通过题
**有且只有 1 题**（path-tracing-reverse，09-10 14:11–14:27），其余全部为真 V4 Flash。
详见 [`OFFICIAL_LEDGER_MODEL_GENERATION_ANNOTATION_2026-09-12`](audits/OFFICIAL_LEDGER_MODEL_GENERATION_ANNOTATION_2026-09-12.md)。

**项目既有裁决**：口径分歧（65/74/76/77）保留、不并轨——「目前成绩并不可靠」。

**结论**：旧账面是混代际数据，不能充当新后端的对照基线；重跑的目的**不是刷新分数**，
而是建立一份**单代际、语料冻结、载体版本唯一**的新基线。

## 2. 代际记录纪律（本轮口径，避免重犯「混代际不自知」）

1. **模型名不变、代际可再切**——兼容路由无公布截止日，而名称全程不变正是上次
   混代际未被当场发现的原因。
2. 每 run 落**起止时间戳** + 轮首**代际探针**，把 run id 与代际时间线绑定。
3. 跑完按 **0aa** 方式做一次全量分桶复扫（批次 / 时间窗 / 事件族），把「轮内是否
   再次切换」变成可核事实，而不是推断。
4. 报告口径：**新一代基线**，不与 V4 Flash 数字做差值；确需对照时只报同题
   「是否通过」的集合差，不报分差。
