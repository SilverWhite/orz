## §1 F1：强制窗工具摘要缺省范围（P1，设计-实现符合性）

### 1.1 病灶

370 重写的强制窗 prompt 承诺「summary 不含 `压缩块:` 行 ＝ 按全部处理」，但 loop-top 注入把工具摘要一律盖 `ModelRequested` ⇒ `default_all=false` ⇒ `compress_blocks_now` 把选中块 `truncate(1)`——**强制窗内只折最旧一块**。正文路径（识别点盖 `Mandatory`）与工具路径语义相反；后果＝T1 越线下一次只折一块、窗口反复以「首问」重开、0bn R1 升级链（产出未落地 ⇒ 计数 ⇒ 第三次机械截断）对工具路径两头不沾。

### 1.2 修复（`agent_loop.rs` loop-top 注入点）

- 延迟收口态 `model_compression_close.2`（强制位）在注入时点仍可读（finalize 在其后才 take）：强制位真 ⇒ 盖 `CompressionWindowKind::Mandatory`（缺省＝全部已闭合分块；NoOp 时 0bn R1 分支如实计数）；否则 `ModelRequested`（H1/模型自选语义，缺省最旧一块）。
- 窗种类只在延迟收口轮可判：其余时刻无窗口在程，`ModelRequested` 即正确归因（369 §0 的「工具知情发起」口径在无窗场景保持不变）。

### 1.3 钉

`mandatory_window_tool_summary_counts_as_participation_without_escalation` 扩断言：`rounds_dropped ≥ 2`（修前恒 1——6000 字符×2 轮的场景折一块即回线下，旧钉区分不出）；归因改判 `context_scale_window`（随强制窗种类）。

## §2 F2：参与审计计入工具摘要（P2）

### 2.1 病灶

`finalize_model_compression_close` 参与判定只看黑板笔记写数（`writes_now > window_start_writes`）。369/370 让工具摘要成为强制窗 prompt 首选路径后，按指引提交摘要而未写黑板的合规模型被系统性记 `model_participated=false`——370 §3 挂账的理由（「不是 369 新引入」）随主路径化失效。

### 2.2 修复

- `finalize_model_compression_close` 增参 `tool_summary_participated`：参与＝写数增加 **或** 本 loop-top 注入了工具摘要；payload 如实标注 `tool_summary_participated=true/false`（与纯文本轮内嵌审计的 `semantic_summary=` 字段同形）。
- 注入点置位传入；budget/close_round/gate_block 三个 break 位与 run 尾按各自时点传（run 尾＝F3 排水位）。
- 归因口径债（370 §3「工具摘要记 model_selected」）随 F1 一并收口：有窗随窗种类，无窗 `model_selected`。

### 2.3 钉

同钉扩 ⑤：`model_compression` 收口审计恰一条且 `model_participated=true tool_summary_participated=true`、无 `model_not_participated` 异常。

## §3 F3：run 尾摘要槽排水（P3）

- **病灶**：run 尾安全网只消费 `pending_semantic`；工具摘要锁存在 `compression_summary` 槽位后若下一 loop-top 被非 ModelCompression 的 pending checkpoint（Orientation 等）顶住且 run 随即终止，内容随 run 静默消失（run 起点复位清残留，journal 零痕迹）——违反同文件 deferred supplements 的「绝不静默蒸发」纪律。
- **修复**：run 尾（与 `pending_semantic` 安全网同点）排水槽位折入 `pending_semantic` 走既有按块压缩；强制位照收口态判（该态此刻仍可读）；排水位传给收口审计（F2）。
- **测试口径（如实登记）**：排水本体服务的例外路径（Orientation pending + budget break）e2e **不可经 `run_turn` 构造**——orientation 态不进测试入口（`run_turn` 传 `None`，内部 `run_agent_loop` 参数不暴露）。落两道替代防线：① 预算收口序钉 `tool_summary_in_final_budgeted_round_compresses_before_exhaustion_break`——末预算轮排队的摘要在 D-8 收尾轮模型请求**之前**压缩完成（守住「注入先于收尾」这一常规路径不丢失前提；注入点若被移到收尾检查之后此钉先红）；② 排水代码与既有 `pending_semantic` run 尾安全网同形对称（后者有 `final_answer_semantic_summary_is_consumed_at_the_run_tail` 长期钉）。
- **已知边界（不变）**：`?` 错误传播路径仍会丢弃槽位/`pending_semantic`（既有挂账，与本批无关）。

## §4 F4：state 过滤拒绝形状登记（P3）

R-369-04 的失败形状（`blackboard_read state 只支持 live 读取…`）此前不被 `is_blackboard_render_error` 识别 ⇒ 失败读挂增量头＋推进 state 游标（违反 2026-08-31 M2「模型没拿到内容不算读过」）。已收录该前缀形状＋`is_blackboard_render_error_detects_fail_shapes_only` 补臂；O4 先例（形状错误保持 exit 0）不变。

## §5 F5 三小项

- **F5a**：no-op clear（原本已空）不落 `StateWrite` 事件——事件语义＝机械状态变化；指令本身由 ToolCompleted（`cleared:false`）如实留痕。367 档「clear 为 outcome=cleared」口径同步修订为「**变化的** clear 落行」。
- **F5b**：payload schema `allOf` 两组 if/then（accepted ⇒ required `updated`；cleared ⇒ 禁 `updated`）。Rust conformance 两新臂（accepted 缺章拒、cleared 带章拒）；Python 侧 `Draft202012Validator` 直读同一份 schema 文件，零镜像成本。JSON 无重复键（`allOf` 承载，serde_json 语义安全）。
- **F5c**：非字符串 `summary`（null 豁免＝可选参数惯例）⇒ 整调用 exit 1（`summary 必须是字符串…本次未压缩`、`whitelist_applied:false`、零副作用），走 R-369-03 同一拒绝块。端到端钉 `non_string_summary_rejects_the_call_fail_closed`。

## §6 M1-S1 P3 收口

- **none 词数组项**：`normalized_items` 先剔除 none 词（`none`/`NONE`/`无`）再计数——全 none ⇒ 清空（不限原始条数，与文本字段 `none` 语义一致）；混合保留实质项；EmptyItem/ItemTooLong 报错保留原始行位。文档形态（parse → split_items → apply）统一归一。钉：`none_word_array_items_are_filtered_and_clear`。
- **parse_document 严格头**：只认逐字 `state v1`；`state v2`（缺冒号→InvalidDocument）、`state goal: 误写`（未知字段→InvalidDocument）如实报错。钉：`document_state_prefixed_lines_are_rejected_not_skipped`。
- **逗号分隔不采纳**（裁决）：含逗号的合法单条目（「部署在 a, b 两环境」）会被误拆，语义歧义成本大于收益；维持挂账。
- **state_write schema 描述**中 `open/constraints` 的「0-3 条」语义不变（none 词剔除后计数）。
