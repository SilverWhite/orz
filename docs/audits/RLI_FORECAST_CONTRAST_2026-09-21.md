## §0 run／会话口径与报告纪律（2026-09-21 用户澄清后补；**含未来边界**，见 §0.2）

### 0.1 现状（成立，但属过渡态）

- **run ＝ 一次 orz 进程执行**（journal 一处 `.gsa/runs/<run_id>/`，run id ＝ `RUN-CLI-{ts}`）。本件的「137 runs」即 **137 次执行**，不是轮、也不是回合；**轮（round）＝ run 内的决策轮**。
- **今天 run ≡ 单对话**：UI 未接多轮，狗粮轮也都是单对话，故一次执行＝一段对话。
- **预测只认本执行内**（用户口径）：每个 run 独立回放（每次 `LifEngine::new()`）、预测与实现**在同一 run 内**配对；跨 run 只用于**报告分布**，**不做任何拟合**（本件零参数估计、零先验）。
- 主读口径＝**逐 run 分布**（中位数／正比例／p10／p90），总平均仅作对照。

### 0.2 未来边界（**用户 2026-09-21 明确要求登记**）

- **UI 接入多轮后 run ≡ 单对话将不成立**：一段连续对话会跨**多个** run（多次执行）。届时必须区分两个身份——
  - **run**＝一次进程执行（`RUN-CLI-{ts}`，一次 journal）；
  - **session（会话）**＝一段连续对话（`.gsa/conversations/<session8>.json`），**可跨多个 run**；现有 `session8 ↔ RUN-CLI-{ts}` 前缀互认（0ak）只是过渡实现的桥。
- **随之重述本件纪律**：自适应与预测的**合法作用域＝本会话**（在线、因果、连续，状态随会话侧车延续——RLI 影子已随 `TemporalSessionSnapshot` 进会话侧车）；**跨会话只作描述性对照，不用作参数来源**。即「独立 run 预测」在多轮形态下的准确表述是**「独立会话内连续自适应」**。
- 登记形态：索引 `candidate` 条目 `GAP-RUN-SESSION-BOUNDARY`（不进当前工作集、不计入未闭合总数），触发条件＝UI 多轮接入；届时需把 run／session 身份、journal 归属与侧车延续口径一并定案（含与 0ba 铸号唯一化的接口）。

## §1 对拍口径

- **预测**：通道状态的**闭式自由演化**前推到 `h·T̂`（`h ∈ {1,2,5,10,30}`；生产面只渲染 `h=10`）。取法：`RliChannel::prediction(m·T̂/10)` ＝ 自由演化 `m·T̂`（复用生产同一套 API，不经二次实现）。
- **对照**：**同一 run 内**第一个 `≥ t + h·T̂` 的决策轮采样上的**真实 `u`**（含该窗口内真实发生的注入）。
- **基线**：**持久性**（"假设 `u` 保持不变"）。预测打不过它即无信息量。
- **粒度**：**轮级**对拍（采样粒度＝事件级、判决粒度＝轮级；本件取轮级，与域判定同格）。
- 回放路径与生产同形：`LifEngine::new()` ＋ `enable_rli_shadow()` ＋ `on_decision_round` / `on_tool_event`（与 `rli_shadow_replay.rs` 同构）。

## §3 两处结构性发现

1. **`prog` 前推系统性劣于"不变"基线，且 horizon 越长越差**。机制：`prog` 是**冲量重置型**通道（成功事件把 `u` 置 1），闭式自由演化只含**衰减**、不含未来注入 ⇒ 系统性偏低（137-run `h=10` 均值：预测 0.091 vs 实际 0.592；活体 0.103 vs 0.752）。**进度轴恰是域判定的主轴** ⇒ 「10 步预测没有可用性」的直接来源是这一条，而非步长选择；**缩短 horizon 不能救 `prog`**（h=1 仍为负），它要的是**注入／到达过程建模**。
2. **a2 短视档存在文档漂移，且短视档未作为独立锚点存在**：模块头注释（`rli.rs:41`）与 `RliAnchors.prediction` 字段注释（`rli.rs:237`）仍写「a2 短视预测 û(t+T̂) ≈ u + v·T̂」（同设计件 §3 a2），而实现已是 `RLI_PREDICTION_STEPS(10)·T̂` 的**二阶闭式长视前推**（`rli.rs:343` 明记「退役一阶短视近似」）⇒ 渲染面 `pred(10T̂)` 与两处旧注释不符；**h=1 档需调用方自行取**。读数上 Slow／Stall 恰在 h=1–2 最优、Err／Deny 在 h=5–30 最优 ⇒ **单一 horizon 对所有通道都不是最优**。

## §4 边界与不采信面

- 本件是**单通道自对拍**（预测 vs 该通道真实演化），**不是**"预测 vs 框架动作"；后者口径见回放件 `prog_predicate_contrast` 段（对同轮动作结果窗）。
- **θ 侧命中率在本批退化、不采信**：`pred ≥ θ` 与 `real ≥ θ` 两侧计数均为 **0**（θ≈1.0、`u_prog` 常驻 0.9 上下）⇒ 1.000 属空命中。
- 语料混合（含 0bc 轮与历史轮），`T̂` 与事件密度随轮变化；读数以段内语料为准，不作跨批趋势断言。
- **跨 run 只作描述**（用户口径 2026-09-21）：本件不产生跨 run 先验、不拟合参数；若日后要在 run 内自适应（如到达率在线估计），那是**只在 run 内**的估计，本件不预设其数值。
- 探针对拍用生产同一 API 回放，但**不是生产运行时读数**；生产面实际只暴露 `h=10` 一档。

## §6 用户裁决（2026-09-21）：三点放行 ＋ 自适应／优化器口径

- **放行三项**（用户令「新的三点裁决都可以放行」）：① **run 内在线到达率估计＋`prog` 前推修正**（不跨 run、不拟合、不动配极语义表）；② **分通道 horizon ＋ 把短视档补为独立锚点**（读数面）；③ **自适应参数轨迹进侧车**（复算可核；新增持久面）。
- **口径裁定（自适应 ≠ 优化器）**：判据＝**更新律是否由"最小化某损失函数"导出**。
  - **在线估计**（分位数、中位数、矩匹配、到达率／间隔统计）＝**估计**，不是优化器；RLI 现行 θ／T̂／`prog` ω 热更新全属此档。
  - **解析更新**（闭式最小二乘、按估计时标做极点重配）＝**闭式解**，仍**不需要迭代优化器**。
  - **误差反传／非线性损失下降**（含递归最小二乘这类"在线优化"）＝**才需要优化器**，也正是「禁拟合」要避免的那档（会把参数绑死在语料上，产生跨会话平凡解）。
  - 本批**只做第一档**：低维、可解释、有统计量或闭式更新的量（到达率 λ̂，必要时一个增益）；**语义参数 ω／ζ 不动**。若日后要动 ω／ζ 或做误差驱动学习，属 ADR 级修订，另行裁决。

## §7 会话作用域裁决（2026-09-21）＋ 疲劳值／繁杂度提案

### 7.1 裁决：**每会话**（用户令「我觉得得每 session 才行」）

- 理由（用户）＝**单会话内域判定必须持续稳定**，要在整个会话内构建**连续时间轴**供模型定位与回看；本件读数亦支持——域时间线是**多尺度**的（本轮 51 次切换、中位驻留 2 轮／49.8 s，尾段 786 s 不切换），**跨 run 切断会人为截断该时间轴**。
- 技术上同向：RLI 影子状态本就随 `TemporalSessionSnapshot` **进会话侧车延续**；T̂／θ／λ̂ 都是**会话级时间尺度量**；run 只是执行容器。
- **量的归属（分流口径）**：

| 归属 | 量 | 说明 |
|---|---|---|
| **会话级** | RLI 通道状态（u/v/θ/E/r）、T̂、自适应参数（含 λ̂）、域时间线与 spikes、繁杂度／疲劳读数 | 自适应用它；读数以会话为单位 |
| **run 级** | 进程身份（`RUN-CLI-{ts}`）、journal 完整性、墙钟／资源读数（0bc 面）、工具事件预算 | 执行事实；不跨 run 拼接 |

- **仪器影响**：对拍／读数件必须**按会话拼接多 run journal**（今天 `session8 ↔ RUN-CLI-{ts}` 前缀互认可达 1:1；UI 多轮后需要真正的 session 归属键——见 `GAP-RUN-SESSION-BOUNDARY`）。本探针当前按 run 加载，**UI 接入前须补会话拼接**。

### 7.2 繁杂度绑定 RLI（用户 2026-09-21 二次裁定：**机制照抄疲劳度，只需一个指标**）

- **现况（P2-13 既有设计，照抄对象）**：会话疲劳＝**黑板 live 字符水位**（W=10 MiB 软上限，三档 50／70／90%），**用户侧提醒、不注入模型**（E9，机械追加在输出最后），门控 `fatigue_tiers_notified`（SUCCESS-ONLY 回写、**每档越线只提醒一次**）；设计件明记其为**工作总量代理，非复杂度模型**（§13.2）。
- **用户裁定**：机制**不复杂**——只要**得到「繁杂度」这个指标**，其余**完全照疲劳度办**：**仅机械提醒用户面**，让用户知道该换对话了。
- **时间轴断裂不是问题（用户）**：RLI 的时间轴**不是跨会话长状态**（记忆系统），它服务的是**单会话内压缩造成的时间轴断裂**，目的是维护模型的**元认知**；跨会话**直接当新任务重开**（当前未配记忆系统）。
  ⇒ 本项**不设会话桥接**、不设跨会话延续要求。
- **例外登记**：**安卓线**需要维护一定的记忆系统，跨会话延续届时另行考虑（**本项不含**）。
- **唯一实质决定点＝指标定义**（其余照抄）：
  1. 指标＝**会话内预测准确性**（四条复极点通道的 skill，相对**本会话**前段基线）；
  2. **禁用 `prog`**（h≥2 结构性负，会报假疲劳）；
  3. 阈值不引入人工绝对定值——复用 RLI 现成的**分位数自校准**（θ 同法）；**档位与提醒设施照抄 E9**（用户面、每档一次），但与"水位"档**分开命名**；
  4. 与域抖动（dwell 缩短／切换密度）、到达率 λ̂ 的合成＝**可选增强，先不做**。
- **依赖顺序**：必须在 §6 三项（λ̂＋horizon／短视＋轨迹侧车）之后——"用预测准确性做繁杂度"的前提是预测本身已能赢过持久性。
- **与模型面提醒的关系**：本条**只到用户面**，不占模型上下文预算、不涉"提醒不可见"问题；模型面的**数值判定式提醒**仍按既定令放改造之后（§6）。
