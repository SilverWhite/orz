## §1 S1 读码勘定（设计稿 §2 的三条结论）

读码范围＝bash/mod.rs（6,241 行）／terminal.rs（6,467 行）／orz-host lib.rs（DispatchGuard、
spawn sink、finalize sweep）／process_tree.rs（判定矩阵）／xai-tty-utils lib.rs（ProcessGroup、
Job 挂接）／task_output tool.rs（读出截断）。三条勘定结论：

1. **Job 归属已在**（设计稿 §2.1）：三种后台化路径（显式 `is_background`／auto-bg 180s／
   Ctrl+G）殊途同归 actor 任务域——per-call `ProcessGroup`（`KILL_ON_JOB_CLOSE`）原句柄
   由 actor `ProcessState` 持有直到任务终；`DispatchGuard::drop` 只关宿主侧复制句柄 dup，
   不杀活任务。「长程宿主不落前台调用域 job」在后台路径结构性成立；ep1 事故属前台域
   by-design 拆树（前台 shell 收殓→其 Job 句柄闭合→脱离挂后台仍留 job 内的孙进程整树
   回收），正解是教学（长程走显式声明）不是重挂 Job。
2. **跨 run 死因唯一＝finalize sweep**（设计稿 §2.2）：run 尾
   `SweepMode::Finalize{own_run_id}` 对 `run_id==own_run_id` 登记行按三条件 `kill_pid`；
   派发期 ambient spawn sink 对**所有** spawn（含后台任务 shell）写
   `.gsa/process_trees/` 行（`run_id=own_run_id, job_name="call"`）→ ep96 机理。装配期
   Start sweep 对会话内跨 run 场景因 parent_chain（宿主 pid）存活 `ParentAlive` 拒绝，
   天然不杀；宿主死亡后的孤儿行由下会话装配扫净＝0bq 兜底，保留不动。
3. **30h＝单执法点改值；显式后台并非真无界**（设计稿 §2.3，**勘正 295 批**）：绝对兜底
   唯一执法点＝poll tick `p.timeout.min(BACKGROUND_MAX_RUNTIME)`（terminal.rs:1713）；
   显式后台 `timeout` 0/None 解析为 `Duration::MAX`，但被该 `min` 实际钳在 10h 兜底内
   （signal=`max_runtime`）。295 批「0/None → unbounded」表述随本批勘正；30h 放宽
   因此＝`BACKGROUND_MAX_RUNTIME` 单常量＋模型正向超时钳制 `ABSOLUTE_MAX_TIMEOUT_MS`
   同步，无语义新增。

## §2 设计定案摘要（D1–D8；全文见设计稿 §3）

- **D1 通道形态**：宿主装配注入 `hide_background_input:false`（库层缺省 true 不动）；
  `is_background` 进 schema（描述自解释在树）；声明即立即后台化不烧 180s；`&` 封闭不动；
  requires_expr 强制伴随同台 ⇒ `RETAINED_GROK_BUILD_TOOLS` **+2**（get_task_output／
  kill_task）＝**8 工具面纪律第二显式例外（+2，296 裁决授权）**，随 §14.87 登记。
- **D2 收割豁除（待勘①）**：`ProcessTreeRecord`+`lifetime`（`"call"` 缺省／`"session"`），
  sink 经 `SpawnObservation` 传递；**finalize sweep 对 session 行 `Refuse(SessionOwned)`
  审计可见不杀**；Start sweep／前台拆树／0bq 兜底全不动。**三种后台化路径一律 session**
  ——ep96 正是 auto-bg，只豁显式则事故原地重演；与 CC「后台 shell 会话内跨轮」单一
  语义对齐；30h 兜底统一封顶。生命周期边界显式化（借鉴 c）＝会话域：宿主存活⇒跨 run
  存活；宿主死亡⇒Job 句柄闭合树灭＋残留行下会话装配收净；不承诺跨进程重启。
- **D3 Job 归属（待勘②）**：零新增层；现役 actor 任务域升格为设计条款（所有权派发域→
  任务域；树拆点四处）。
- **D4 30h（待勘④）**：`BACKGROUND_MAX_RUNTIME` 36_000s→108_000s＋
  `ABSOLUTE_MAX_TIMEOUT_MS` 36_000_000→108_000_000＋env 口子 `GROK_BG_MAX_RUNTIME_MS`
  （钳位下限 1h，不可配没）；monitor 工具常量不动（不在保留面）；idle-kill 300s 原样；
  schema 两句文案随批改写（timeout:0 语义按勘定结论三改写）。
- **D5 教学面（借鉴 a）**：三件套＝参数自解释（is_boundary 一短句）＋描述模板一句话
  （lifetime/kill_task 句保留、timeout:0 句改写）＋结果文案 just-in-time（起任务 summary
  补会话域边界行）；**零长备注常驻注入、零新触发规则**（用户令）；完成 reminder 现役保留。
- **D6 增量读出（借鉴 b）**：服务端每任务字节游标（actor `ProcessState` 承载、会话域随
  任务灭）；运行中任务返回自上次读出以来新增段（现役 40K 单次钳制不变）＋
  `TaskOutputResult.new_bytes`（optional，None＝旧语义）；终态封口；全量仍走
  `read_file(output_file)`。
- **D7 契约面**：四结构 +1 字段（ProcessTreeRecord.lifetime／SpawnObservation.lifetime／
  SweepRefusal::SessionOwned〔键 `session_owned`〕／TaskOutputResult.new_bytes）＋schema
  三句文案；**journal 事件族零新增**（sweep fact／tool_running/completed 现役承载）。
- **D8 批序**：S2 落码触点七文件＋钉子八面（显式即后台化／session 豁除×call 对照／Start
  sweep 照扫／30h 生效＋env 钳位／游标三态／schema 可见性×封闭态回归／教学字面／跨 run
  提醒不吞）→ S3 载体（字节判据随 S2）→ S4 真机（294 预登记判据不变＋增量读数对照）。
