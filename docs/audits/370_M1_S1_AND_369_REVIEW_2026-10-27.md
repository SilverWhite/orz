## §2 Findings（按严重度）

### P1（重建前必须闭）

**R-369-01 强制窗内 summary 的消费顺序（已修，缺回归测）**

- 原实现：`finalize_model_compression_close` 先执行，369 的 `take_compression_summary` 后执行；若模型在 `PendingCheckpoint::ModelCompression` 窗口内用 `context_manage(mode=compress, summary=…)` 提交，`closed_mandatory && pending_semantic.is_none()` 仍成立 ⇒ 被记成“窗口未参与”，可能多计 T1 失败/提前截断。
- 现状：`agent_loop.rs:2978-3015` 已把摘要注入移到 `finalize` 之前；`summary_slot_open` 允许 `ModelCompression`，其它 pending 仍锁存。
- 仍缺：专门的“强制窗内工具 summary”回归测；现有 `context_manage_summary_tool_call...` 是普通轮，不覆盖强制窗。**建议重建前补。**

### P2（重建前裁决或修正）

**R-369-02 旧 prompt 仍教正文摘要**

- `context_scale.rs:310-328` 的 `summary_block_guide` 仍内嵌 `[SEMANTIC_SUMMARY]` 骨架；`soft_reminder_block` / `mandatory_compression_window_block` 仍使用它。
- 与“教学不进 prompt，改黑板说明书/工具注释”不完全一致；也会让模型继续走 fallback、把摘要写回 assistant 正文。
- 建议：把 prompt 侧改成一行 `context_manage(mode=compress, summary=…)` 指针，骨架只留工具描述/guide；同步改 `context_scale.rs:1130-1149` 的 0bn R2 钉。若不改，应在 369 档明确“旧 prompt 仅兼容 fallback，迁移期保留”。

**R-369-03 summary + whitelist 的校验顺序**

- `tool_run.rs:1390-1455` 先处理 whitelist，之后才 `normalize_tool_summary`；非法 summary 仍可能先写入 whitelist（副作用）。
- 建议：先 normalize/validate summary，再处理 whitelist；或明确文档化“whitelist 独立生效”。

**R-M1S1-01 `state_write` payload 的“历史”表达**

- 原 schema 描述称“replaying accepted rows 可重建全文”，但 merge 语义下 payload 只有 `fields/goal` 预览，缺 now/next/open/constraints 值；全文只在对应 `model_output.tool_calls.arguments` 里。
- 已修正 schema 描述与 `event.rs` 注释（改为“join model_output 参数 + accepted rows”）。
- 仍待裁决：是否给 payload 加 `state` 全文快照（≤~400 字符）使 `state_write` 行自包含；若不加，367 档应明确 `state_history` = `StateWrite` 行 + `model_output` 参数的联合视图。

**R-M1S1-02 测试缺口**

- 缺：`state_write` payload 历史断言；`replace_state` 失败原子性；`state` 过滤参数拒绝（已修代码，未加测）；`state` 精确 200/201 token 边界。
- 369 缺：强制窗内 tool summary、同批多 summary、summary+whitelist、空/超长 summary 的端到端 ToolCompleted 断言。

## §3 设计合理性评价

### M1-S1

- **薄层选择正确**：state 只存 6 个当前事实字段，不复制 plan，符合“state 是永远小的当前事实”；merge + 系统 `updated` 让模型只写变化，减少每轮刷新。
- **存黑板而非独立文件正确**：复用持久化、会话快照、journal、权限与 PULL 面；state 不进 epoch 快照的裁决合理（会话事实不随 plan 轮换）。
- **200 token 硬门合理**：用 chars/2 与上下文计量同尺；拒绝而非裁剪，避免模型误以为写入成功。
- **主要设计债**：`state_history` 没有独立自包含快照；人类 pane 未落；`state` 与 `blackboard_read` 通用过滤参数的关系需要明确（已按 guide 纪律收紧）。

### 369

- **方向正确**：工具调用是类型化控制面，天然不参与终答判定；把压缩摘要放工具参数，消除了 368 的根因，而不是继续加文本分类器。
- **“summary 不给模板”正确**：工具调用已经声明语义，不需要段标签防误识别；自由文本更适合不同任务形态。旧的两段校验仅留给正文 fallback，边界清楚。
- **最小改动正确**：复用 `context_manage` 单工具、复用 `pending_semantic`/`compress_blocks_now`，没有新工具、新事件、新 UI 契约。
- **主要设计债**：prompt 仍在教旧正文路径；工具参数在 tool card 的可见性未定义；强制窗参与的审计口径（`model_compression` 只看黑板写数）仍未把 summary 计入——这是既有审计口径，不是 369 新引入，但 369 让“工具 summary”成为主路径后应重新审视。

## §4 实现合理性评价

- **单源**：state 解析/校验/渲染集中在 `state.rs`，`blackboard.rs` 只做写入/版本/快照；`state_write` 与 `blackboard_write section=state` 共用 `apply`，避免两套语义。
- **原子**：`apply` 先 clone 再校验再提交；`replace_state` 以空 state 为基底；失败不改原状态（有测试）。
- **权限/工具面**：`state_read/write` 两表同批登记（controller READ_ONLY_EXEMPT + host permission bridge），探针/Python WORK_TOOLS 同步；host 453 串行全绿。
- **369 实现**：controller 的 `compression_summary` 一次性位 + run 起点复位 + loop-top 注入；工具 handler 统一校验/排队/回执；没有绕过 `compress_blocks_now`。P1 顺序问题已修。
- **风险点**：summary 先于 whitelist 校验（P2）；旧 prompt 仍教正文（P2）；强制窗工具 summary 缺测（P1 回归缺口）。

### 9.1 R-370-00 断连根因（摘要；证据链详见复现件）

- 定位：`orz-tools/src/types/exec_policy.rs` `pipe_interpreter_hit`（规则⑧

  原命令）panic 位点逐字一致；③ 触发形状＝`Select-String -Pattern 'a|中文'`
  （引号内 `|` 被无引号感知扫描器当管道）。
- 修复：改 `char_indices()` 字符安全遍历（空白/断词判定用真实 `char`，
  切片/前进恒落边界）；判定语义不变（中文词非解释器闭集 ⇒ Allow）。
- 回归钉 ×2：`pipe_interpreter_hit_is_char_boundary_safe`（合成边界＋命中
  面不回退）、`encoded_exec_survives_real_crash_commands_with_chinese_patterns`
