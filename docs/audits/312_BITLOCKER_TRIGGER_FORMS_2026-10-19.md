# 312 批：BitLocker 风险触发形态查证——软锁数据卷／硬锁重启 PIN 门（2026-10-19）

> **批次性质**：查证落账批（零源码零跑批；**计数 60 不变**；候选
> `OBS-REMOTE-ONE-TO-ONE-2026-10-19` 维持 `candidate`）。
> **来源**：用户问询「风险时能直接触发 BitLocker 吗？反正恢复后也就正常进系统了」。

## §1 查证结论（调研底稿 v1.2 §8）

1. **OS 卷运行中不可锁（硬边界）**：BitLocker＝静态加密，运行时卷密钥在内存、卷已挂载，
   无受支持 API 可重新封印运行中的 OS 卷；`manage-bde -lock` 仅限非系统固定数据卷
   （有打开句柄即失败）。且锁的前提是**早已加密**——风险时无法现场加密（小时级），
   全部依赖装机基线。
2. **软锁＝数据卷即时上锁（可行）**：`manage-bde -lock <数据卷>`，装机基线核验该卷已
   启用 BitLocker；远程输 ACAF 密码即解锁恢复；orz 存活。
3. **硬锁＝重启进固件 PIN 门（可行，核弹档）**：装机预配 TPM+PIN 启动保护器（PIN＝
   ACAF 密码）＋恢复密钥入 keystore；风险触发重启 ⇒ 固件 BitLocker PIN 门——无 PIN
   谁也进不了（断电冷启动同在，强于锁屏）；输对 PIN 正常进系统＝用户预期成立。
   **代价＝与 ⑥ 后门冲突**：重启即 orz 进程与远程会话终止，恢复须有人物理在机前输
   PIN（远程用户同样被锁外）——只能作显式配置的硬档，不作默认。
4. **风险响应定两档**：默认软档＝替代五件套＋数据卷软锁；硬档＝BitLocker 重启 PIN 门
   （配置期显式启用）。PIN 固件输入用内置键盘（与设备白名单兼容）。
