## §1 P0 处置

### 1.1 版本偏斜：编译期桥版本 vs 磁盘 child 探针

- **旧缺陷**：`bridge_version` 与 `child_version` 都探 `current_exe()`，同一文件，`version_skew` 恒 false。
- **修复**：
  - `WebConfig.bridge_version` 由 `orz-bin` 的 `env!("CARGO_PKG_VERSION")` 注入（0.9.7），`ServerState.bridge_version` 承载；`/api/boot` 不再取 `orz-web` crate 的 0.1.0。
  - child 版本仍由 `state.agent_binary --version` 探针读取，但加 **3 s 超时**（旧载体无 `--version` 会落 TUI 分支）；失败/超时返回 `null`，并新增 `child_probe: "ok" | "failed_or_timeout"`。
  - `version_skew` 只在 child 版本可得时比较；桥版本恒为真实运行版本。
- **证据**：`server.rs` 的 `version_skew`/`binary_version`/`api_boot`；单测 `version_skew_compares_bridge_and_child`；`orz --version` 实测 `orz 0.9.7 (windows/x86_64/debug)`。
- **残余**：真实「桥 0.9.7 内存 + 磁盘 0.9.8」双二进制场景未在真机复现；单测只证明比较函数，boot handler 级双二进制测试未做（需可控临时 exe）。

### 1.2 0.9.8 必闭台账闭合

- 330 §5 后新增 **§5.1 逐条台账**：`closed/waived/partial` 三态，附证据/缺口；不再用「333 覆盖 3–10」替代逐条核对。
- #2 ACP v1：**`waived`**（用户 2026-10-21 裁决「不追 v1」，自台账生效）。
- #4 回放口径：**`closed`**——裁定 **text_only**（只回放用户/助手正文；工具/系统不回放），`_orz/session_replay` 通知＋`replay` 响应字段＋UI 系统行；已在内存时 load 早退，不二次回放；因不回放工具面，不需要 `tool_call_id` 去重。
- #8 诊断与版本：**`partial`**——补齐 retrieval/web-port/token/CDP、runs 数值序/终态、启动 integrity 复用；明确缺口「配置分层未纳入；端口只探默认 21487」。
- S1 切区 run 守卫、S4 取消 30 s 兜底、S12 版本偏斜：均 `closed`（见 §2）。

### 1.3 CLI 删除门与幂等重试

- **旧缺陷**：`orz delete-session` 直接调 `delete_session_on_demand`，不查 lease/close；首个删除失败即 `?` 中断；不删 `.lease`；部分失败后 `_orz/session_delete` 早退 `already=true`。
- **修复**：
  - 新增 `delete_session_checked`：先 `leased_sessions` 扫描；命中即 `lease_conflict`（**不写墓碑、不动文件**）；墓碑已存在且无残留时返回成功（CLI exit 0）。
  - `delete_session_on_demand`：逐件收集失败、最后汇总；`NotFound` 不算失败；墓碑先写（防复活）；`.lease`（未被其他进程持有）纳入删除口径。
  - `handle_session_delete`：墓碑存在时**不早退**，继续清理残件；只有确实无残留才 `already=true`；`archived` 直接删；`active/closing` 拒绝。
- **证据**：`acp_server.rs` 的 `delete_session_checked`/`delete_session_on_demand`/`handle_session_delete`；单测 `cli_delete_requires_lease`、`delete_archived_session`、`load_after_out_of_process_tombstone_is_rejected`、原有 `unarchive_and_delete_session_on_demand_scope_and_gates`。
- **残余**：CLI 仍只知 8 位 s8，`.lease` 按前缀扫描；极端 s8 碰撞会多删 lease 文件（UUID 前缀，概率可忽略但未加全 id 校验）。当前会话在 Web 中空闲但绑定（lease 在）时 CLI 删除会被拒——这是有意的「先关闭再删」。

## §2 P1 处置

### 2.1 桥请求 id 分表与审批重放

- **旧缺陷**：一张 `requests` 同时记 client→agent / agent→client；同值 id 覆盖 `session/prompt`，`prompt_in_flight` 永不清零；刷新后 UI 永久「运行中」。
- **修复**：
  - `client_requests: HashMap<u64, ClientRequestFact>` 只记 client→agent（method＋cwd）；`pending_permissions: VecDeque<PendingPermission>` 记 agent→client 的 `session/request_permission` 原帧。
  - prompt 响应只清 `prompt_in_flight == 该 id`；permission 响应（同 id、无 method）从 pending 移除。
  - attach 时重放未应答 permission（上限 32，按 id 去重）；preamble 带 `pending_permission_count`。
  - `onBridgeAttached` 改为「先 setBinding → 再 resyncBusyState → 最后按 prompt_in_flight 置态」；`resyncBusyState` 删除 `if (state.running) return`。
- **证据**：`acp_pump.rs` 单测 `bridge_request_ids_do_not_collide`、`unanswered_permission_is_replayed_on_reattach`；smoke 16.x 的 attach 顺序断言。
- **残余**：桥进程重启后 pending 队列丢失（in-memory）；300 s permission 超时不变。smoke 未用假时钟驱动重放时序。

### 2.2 锁序统一

- `handle_queue_append`、`handle_recall_preview` 改为 **sessions → runs**（与 `release_session`/`evict_over_cap`/`lifecycle_state` 同序）；`queue_append` 在两锁内完成「Restore 检查＋push」，无 await。
- **残余**：没有多线程 runtime 的并发死锁测试；当前 LocalSet 单线程仍掩盖 ABBA，但代码路径已同序。

### 2.3 closing / archived / 通知 / SessionCommand

- **closing**：`release_session` 先在表内保留行、置 `closing=true` 并发 `closing` 通知，第二个临界区才移除；`handle_session_state` 在收尾窗口可读 `closing`；prompt 明确拒绝。单测 `closing_state_is_observable_and_rejects_prompt`。
- **archived**：`SessionHost::is_archived` 由「归档包在、活区侧车不在」派生；`state_of` 返回 `Archived`；delete 可直接删；单测 `delete_archived_session`。
- **通知**：`created`（attach/new）、`active`（prompt 起点）、`idle`（run 收尾）、`closing/closed`（close）、`deleted`（delete）均发 `_orz/session_state`；单测 `session_state_notification_emitted_on_transition` 断言 created→closing→closed。
- **SessionCommand**：`stdio.rs` 只做方法名→`SessionCommand` 映射，`AcpServer::handle_session_command` 统一分发 close/state/delete；不再是死枚举。
- **残余**：`closing` 仍是同步收尾窗口，只有通知可稳定观测；跨线程 `session_state` 查询能否恰好落在窗口内不确定。`archive/restore` 仍走 0cy/CLI 旧路径，未全部收进命令枚举（设计 §3.2 的完整单 owner 仍差这一角）。

### 2.4 错误四要素覆盖 prompt/load/queue/recall

- `stdio.rs` 新增 `acp_error_with_data`：`SessionLifecycle` → 原 -32010..-32014 + data；`SessionNotFound` → -32010 + data；`InvalidRequest` → -32602 + `invalid_state` 四要素；其余 → -32603 + `internal` 四要素。
- prompt 的 busy 改为 `SessionError::Busy`（-32011 + data），不再压成 `InvalidRequest`。
- queue/recall 的参数错误也走 `invalid_request_with_data`。
- `copy.js` 的 `permission_denied`/`provider_error` 标 `reserved: true`（宿主尚无稳定生产者，不再假装已接）；`connection_closed` 由 acp.js 的 closed 回调以四要素对象上浮；`constructor` 原型键缺陷已修。
- 单测 `prompt_error_carries_four_elements_over_acp` 验证删除后 prompt 的 `data.code/class/hint/evidence`。
- **残余**：permission/provider 两类仍无真实宿主生产者（已标 reserved）；端到端「宿主错误→acp.js→弹窗」没有 DOM 级 smoke，只有纯函数＋错误对象断言。

### 2.5 跨工作区根：session→slot + `?root=&session=`

- 桥新增 `session_slots: session id → workspace key`；`session/new|load` 响应时记录；close/delete 时移除。
- `/ws/acp` 新增 `session` 查询参数；`attach` 优先按 session 找 owner slot，preamble 回传 `session_root`（load 的 cwd）与 `cwd=session_root`。
- 前端：`acp.connect(token, root, sessionId)` 带参；`setBinding` 写 sessionStorage（sessionId/root）；刷新/桥重启时无 attach 会话则 `initialize + session/load` 显式续接；工作区切换后 `reconnect` 到新根并解绑旧会话（旧会话留旧区，可从探索器恢复）。
- **残余**：桥重启 + sessionStorage 丢失（隐私模式/换浏览器）时无法自动找回 session id；只能从探索器手动恢复。smoke 16.9 覆盖 sessionStorage 路径，未覆盖隐私模式。

### 2.6 attached ingress 有界 / dead child 过期 / reap 竞态 / 握手泄漏

- attached ingress 由 unbounded 改为 `mpsc::channel(256)`；满时丢帧并置 `attached_overflow`，当前连接收 `_orz/bridge_ingress_truncated`；单测 `attached_ingress_is_bounded`。
- `ExpiredSession` 增加 `reason`（`grace`/`child_exited`）与 6 h TTL；dead child 也留过期事实；单测 `dead_child_is_reported_as_expired_on_next_attach`。
- `reap_once` 按 Arc 身份＋条件复核后移除；`detach` 带 `conn` 代次，旧 loop 不静音新连接。
- attach claim 后 15 s 内 `run_connection` 未启动则自动释放 sink（升级失败自愈）。
- **残余**：15 s 定时器只在 tokio runtime 下生效；升级失败窗口内的 409 仍可能被下一次 attach 看到（自愈前）。

### 2.7 上下文估算口径

- `context.rs` 改为镜像 orz-loop `estimate_message_tokens`：`content + reasoning_content + 每个 tool_call 的 name/arguments JSON`，**每条** `/2` 后求和；`estimate_method` 明写「per message…excludes system preamble」。
- 单测 `estimate_matches_loop_fields_and_per_message_division` 用 26/5/5 字符钉住「逐条」与「整体」差（17 vs 18）。
- **残余**：不含系统 preamble/滑块外携带内容；与真实 tokenizer 仍有偏差；UI 已如实标注。

### 2.8 doctor

- 新增 `retrieval/web/token/cdp` 四项 cheap check；`runs` 改数值序并读 `run_finished/...` 的 `payload.status`；复用启动 `STARTUP_INTEGRITY`，不再二次哈希；`doctor` 分派移到 `web` 之前；`--version` 只认首个位置参数（`orz -p --version` 不再误吞）。
- 单测 `doctor_run_order_is_numeric_and_terminal_is_read`；实跑 `doctor`：`ok=11 warn=1 fail=0`（warn 为开发树无 carrier-manifest）。
- **残余**：配置分层未纳入；端口只探默认 21487（`ORZ_WEB_ADDR` 可覆盖）；CDP 只判「浏览器可发现」，不判运行中可用。

### 2.9 删除语义与 load 墓碑

- load 早退前查 tombstone；`state_of` 支持 archived；delete 对 created/idle 先 close（有意便捷分支，已写入 331 §3.2）、active/closing 拒、closed/archived 直接删；orientation/activation 侧车写也加 tombstone guard；`.closed` 标记 30 天后清理，`.deleted` 永久保留（安全）。
- **残余**：`.deleted` 墓碑无自动清理（长期累积小文件，已在 §6 登记）；删除后 journal/ARC 仍可能被其他维护面并发读写（单写者 + lease 已覆盖主路径）。
