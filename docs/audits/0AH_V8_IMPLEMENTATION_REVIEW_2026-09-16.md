## 2. 阻断项

### 2.1 R-1（P0）T1 硬截断吞掉主滑块 ⇒ 模型面永久失明

**根因是三处口径叠加**，任一处单独看都「合理」：

| 位置 | 事实 |
|---|---|
| [`model_face.rs:183-193`](../../orz/crates/orz-loop/src/model_face.rs) | 未闭合末块的 `last_round` 写成 `ranges.len() - 1`——**会话最后一轮**，而不是它实际累计到的轮（应止于工作现场之前） |
| [`model_face.rs:313-330`](../../orz/crates/orz-loop/src/model_face.rs) | 隐藏区间按**当前现算**的轮区间取（`end = ranges[last_round].1`，末轮即 `messages.len()`）⇒ 末块隐藏区间＝「它的起点 → 会话末尾」 |
| [`agent_loop.rs:1398-1402`](../../orz/crates/orz-loop/src/agent_loop.rs) | T1 只过滤「状态＝Live」，**不过滤未闭合** ⇒ 末块被点名 `Truncated` |

**实测（本机探针）**：20 轮会话、x=4K／y=3K →
① 末块 `#6 声明轮次 16-20`（工作现场在 19-20，**声明已越界**）；
② 截断前模型面 42 条消息、末轮工具回复在场；
③ 点名全部 Live 块（＝T1 的真实行为）后：**模型面 3 条消息，20 轮工具回复存活 0/20**。

**影响**：真机上跑到 ≈500K 估算（T1）后，模型突然看不到自己的工作现场，且**新轮次一产生就落在隐藏
区间里**（末块仍在增长，隐藏区间随会话末尾一起延长），直到该末块累计满 y 才恢复——期间模型面只剩
「前置 ＋ 固定指针 ＋ 分块表 ＋ marker」。违反 **I1**，并砸坏设计指定的唯一总量闸门；
T1 告知块里的「工作现场逐字未动／任务无需中止」同时变成**不实陈述**。数据未丢（末块逐字档案已先落盘），
丢掉的是模型面本身。

**为何钉子没拦下**：`t1_truncation_*` 的构造里 x 相对会话足够大，**没有残段**（末块恰在 y 边界闭合），
故该用例只断言「被截块不在场」——它从缺口旁边绕过去了。凡有「不足 y 的残段」即触发，属常态。

**最小修复方向**（三处口径级改动）：
1. 末块 `last_round` 改为**它真正累计到的最后一轮**（严格止于工作现场之前）；
2. T1／守卫只点名 `closed` 块（残段留给工作现场或另立「残段」语义）；
3. 隐藏区间改用**记账时**记录的区间，而非按当前会话现算。
并补一条钉子：**截断后主滑块逐字仍在模型面**（现有钉子正面覆盖不到）。

### 2.2 R-2（P1）分块表每轮重写 ⇒ 前缀纪律（I6）与成本前提同时失效

- [`render_block_table`](../../orz/crates/orz-loop/src/model_face.rs) 每行写入轮区间／`≈Ntk` 估算／动作计数／
  目标／`run=`；**末块那一行每新增一轮就变**（区间、估算、计数都在长）。
- 表挂在**固定指针之后**（[`build_model_face`](../../orz/crates/orz-loop/src/model_face.rs) 的顺序＝
  前置 → 指针 → **分块表** → D4 机械段 → 各分块 → 主滑块 → 尾部），即模型面的**第 2 条消息**。
- **实测**：相邻两轮的分块表逐字不同，首个差异行**恰是末块行**；模型面首个差异消息位就在表的位置。

**影响**：从「首个分块形成」那一刻起（正好是 x=160K 的主战场），**每轮的前缀都在表这里断掉**，
表之后的全部内容（各分块 ＋ 整个主滑块 ＋ 尾部）每轮重算 ⇒ provider 前缀缓存命中退化为 0。
设计 §9 的「稳态轮：只追加不重写 ⇒ miss≈本轮新增、hit≈当前模型面」与 §11 的「命中率 ≥90%」
**双双不成立**，成本会按「每轮全量 miss」走——这一条直接决定成本账是否可信。

**修复方向**：表按 **epoch 冻结**（仅在压缩／截断时重渲一次，与 D4 段同命），或至少
① 末块行排除／估算分桶（如 8K 粒度）② 易变列移到尾部追加消息（不落在前缀里）。

### 2.3 R-3（P1）收尾压缩与恢复预检在 v8 工作点必然触发，且不另存逐字副本

- 触发线（[`compact.rs:98-100`](../../orz/crates/orz-loop/src/compact.rs)）：`session_end_trigger_tokens = 160_000`、
  `recovery_trigger_tokens = 200_000 → recovery_target_tokens = 160_000`，**量的都是本地面估算**；
  而 v8 阶梯从 192K **模型面**估算起就响，本地面 ≥ 模型面 ⇒ **任何进入 v8 阶梯量级的会话，
  收尾时必然被 drain**（[`controller.rs`](../../orz/crates/orz-loop/src/controller.rs) session_end 段 →
  [`run_template_compact`](../../orz/crates/orz-loop/src/agent_loop.rs) 的 `messages.drain`）。
- 被 drain 的逐字正文**没有另存副本**（D2-2 至少留了 `recovery-conversation-full.json`），
  marker 钉进侧车后写回 ⇒ **归档包里不再是逐字全量**。
- 恢复侧同理：D2-2 在首个请求前 `compact_messages` 截断 ⇒ 恢复后的**块号锚在一个已被截断的会话上**，
  分块表不覆盖被截部分（块号与旧 marker 的对应关系随之失真）。
- 检索／grill 车道同一形态（[`dispatch.rs`](../../orz/crates/orz-loop/src/retrieval/dispatch.rs) session-end 段）。

**影响**：判据表「本地面完整性 100%」、设计 §6「按块回放是生命线」、§7「本地面无实际上限」三条
在真机上同时不成立；而 T1 又把更多内容推给回放。这不是「口径冲突」，是本批核心承诺的落地缺口。

**修复方向（择一，须用户裁定）**：① 主车道退役 session_end 压缩（总量交给 H1／T1）；
② drain 前按块逐字落盘（复用本批已有的 `block_archive_markdown`／`block_archive_path`）；
③ D2-2 至少改为「按块归档 ＋ 带块号的 marker」，让恢复后的块表与旧 marker 仍可对齐。

## 3. 符合性与卫生缺口（P2／P3）

### 3.1 R-4 marker 文案与 v8 事实矛盾（P2，I5 相关）
压缩／截断 marker 复用 [`summary.rs::render_marker_lines`](../../orz/crates/orz-loop/src/summary.rs) 的 v7 文案：
「compaction 存档…**不含被压区逐字原文**」「会话档案（sidecar）…**被压区不在其中**」——v8 下被压块
**仍在 `messages`（⇒ 在 sidecar）**，且**另有按块逐字档案**。这条与同一条消息里的
`MODEL_FACE_DECLARATION`（「本地单对话全量留档、不被覆盖写入」）**正面冲突**，属 I5 的如实告知义务问题。
应按 v8 改写（v7 的「载体口径收窄」是基于 drain 的结论，随勘误作废）。

### 3.2 R-5 T1 档案写失败被静默吞掉（P2）
压缩路径写失败会落 `archive_write_failed=true`；但 T1 两处用 `let _ = write_archive_retry(...)`
（[`agent_loop.rs:1495`](../../orz/crates/orz-loop/src/agent_loop.rs)、
[`agent_loop.rs:1538`](../../orz/crates/orz-loop/src/agent_loop.rs)），失败既不落事件、也不改文案——
而此时内容**已被移出模型面**，回放指针可能悬空。与「回放是生命线」不对称，应同纪律落账。

### 3.3 R-6 分块表缺键（P2）
设计 §2 要求每行＝`[块#k] 轮次 a–b ≈Ntk | 主工具目标 TOP-n | 动作计数 | 台账 [seq] s1–s2 | run=…`；
实现只有 `run=`。台账 `[seq]` 与 journal seq 只出现在 marker 的定位行 ⇒ **§11「三元一致齐备率 100%」
无法按块机检**。补两列（或明确裁定该项口径改为 marker 级）。

### 3.4 R-7 窗口内指针化：改写本地面 ＋ 回读承诺不实（P2）
`action_ledger::pointerize_oversized_tool_results` 就地改写工具结果正文（保留 400 字符头），
其「回读指针」指向 run journal 的 `tool_completed`——但该事件**只带 `tool/call_id/exit_code/wall_ms`**，
**不带正文**（`output_object_id` 仅终端／截断输出族有）。因此：① 它**改写了本地面字节**（I3 语义受损）；
② 对读类结果「原文仍在本地档案、逐字可回读」**为不实陈述**（正文只在被改写的消息里）。
要么补齐落盘（改前把原文落到档案），要么把文案按真实载体改写。

### 3.5 R-8「先裁回放块」未实现（P2）
设计 §6／§12 明确「回放块膨胀到线时**先裁回放块**（可再生），再考虑更旧的原始块」。实现里回放＝普通
`read_file` 结果，无块号记账、无优先级（仅 >8K 的窗口内结果可能被指针化）。**实现面与回执均未登记**，
应至少登记为未落项。

### 3.6 R-9 量尺口径与换算（P2）
`model_face_estimate` 只估投影层消息，**不含系统提示词、工具定义**，也不含 loop-top 取读数**之后**才注入的
状态行／F6 提示 ⇒ 阶梯实际落点**晚于**设计意图（真机 prompt 会更大）。另：整条阶梯的真实 token 锚定
全挂在 `估算 ≈ 真实 ÷ 0.77`（承自 v7 视图尺），设计 §3.1 明文要求「须在实施批复测」，本批**未做**。
建议真机首件即复测该系数，否则 192K–500K 的「≈148K–385K 真实」全部悬空。

### 3.7 R-10 回放生命线要「读两次」（P2）
`.gsa/compaction/blocks/<tag>-block-<k>.md` 属会话卷内部区：首读被拒（`policy_denial` +
`code=session_volume_notice`），二读才放行（`session_volume_opened`）。指针文案未提示这件事，
模型可能把首次拒绝读成「路径不可用」而放弃唯一的回放面；该首次拒绝还会进入失败会计。
建议压缩／截断时**顺手开启该会话的卷门**，或在指针里写明「首读会收到通知信封，再读一次即可」。
（既有 `.gsa/ledger/current.md` 指针同族受限，属既有摩擦；v8 把回放升为组成部分后风险等级上升。）

> **处置补录（2026-09-16，R-12⑤ 一并裁定）**：① 指针文案已按建议写「再读一次即放行」（本批落码）；
> ② 「顺手开卷门」与「扩白名单窗口」**均不做**——读码核证：`session_volume_read_verdict`
> （[`resources.rs`](../../orz/crates/codegen/orz-tools/src/types/resources.rs) B1 区域分类）对
> canonical 落在卷内的**内部区**返回 `InternalAfterNotice`，而 `noticed` 取自
> `{cwd}/.gsa/access_state.json`（**卷级持久化**，跨 prompt／跨进程一次）⇒ 通知给过一次后，
> `.gsa/compaction/blocks/*` 的**后续读全部直接放行**，回放面在门语义下本来就可达；
> 白名单两窗口（`session/terminal/*.log`、`run_tests_output.txt`）是**免通知恒放行**窗口，
> 不是唯一可读面。③ 扩白名单等于把压缩存档从「通知后开放」改成「免通知恒开放」——功能上无
> 增益、却动 `AUTH-GSA-SESSION-VOLUME` 的授权面（该契约面属另一权威，本批不擅动）。据此
> **裁定：不扩窗口；回放走两段门**（设计 §6 补录）。

### 3.8 R-11 残留与卫生（P3）

## 4. 设计层裁定项（属设计稿自身的洞，非实现偏离）

1. **T1「每会话一次」⇒ 有效天花板其实是 1.10M 估算（≈850K 真实）**：T1 响过一次后不再武装，

   要么把守卫降到 ~600–700K。**直接影响成本账与质量承诺**。
2. **H1 的「打断」代价过大**：窗口内除 `blackboard_write` 外动作全部丢弃，而窗口真正要的只是

3. **阶梯可批量触发**：`due()` 遍历整表，一轮暴涨会一次性注入 4–5 条提醒块（含即将被 T1 截断内容的软提醒）。
