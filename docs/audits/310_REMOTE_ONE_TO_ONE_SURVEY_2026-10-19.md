## §1 检索（四路）

1. **业界远程方案**：RustDesk（自建 ID/relay、每连接 ID＋密码）与 MeshCentral（agent
   常驻设备管理）为两大开源自托管代表；临时支持型 vs 常驻管理型分野；网络层设备身份
   以 Tailscale/WireGuard 注册制为代表——**裸硬件码不作唯一凭据**（业界共识：漂移误拒）。
2. **Windows 输入锁死**：`BlockInput` 需管理员且效力止于 **UAC 安全桌面**（提权弹窗时
   锁失效或挡死流程）；硬重启可物理绕过；UIAccess 滥用属攻击技术不入产品面。
3. **设备到达检测**：`WM_DEVICECHANGE`/`DBT_DEVICEARRIVAL`＋`RegisterDeviceNotification`
   （服务形态 `SERVICE_CONTROL_DEVICEEVENT`；须按 GUID 注册）；WMI `Win32_DeviceChangeEvent`
   简易但噪。
4. **勒索行为检测**：Defender 行为启发按「批量加密＋ACL 变更」检测、**不区分意图**；
   Controlled Folder Access 直接拦截——自研勒索式锁机必然被杀软拦截/标黑。

## §2 判定速览（详见调研底稿 §3）

| 件 | 判定 |
|---|---|
| ① 设备绑定鉴权 | 可做，**改配对注册制**（Ed25519 密钥对钉公钥，硬件指纹仅展示位；裸硬件码漂移误拒） |
| ②〔远程使用中〕＋二存一 | 可做（桥级焦点模型，0di 基建同族） |
| ③ 退出显式确认 | 可做（两段确认票） |
| ④ 本地外设锁死 | **部分可行改形态**——硬锁不彻底；正确形态＝**锁屏/会话切换**＋物理接触面（电源键）为任何软件的设计边界 |
| ⑤ 勒索式锁机 | **拒绝原案**（杀软必杀＋USB 触发高误报＋失败模式灾难）→ **替代方案五件**＝fail-closed 即刻断远程＋锁屏＋git 兜底推送（用户要的「留记录＋推送备份」原样保留）＋风险提醒模型＋ACAF 后门解锁 |
| ⑥ ACAF 密码后门 | 可做现成可扩（provision 时 identity secret 入 keystore＋安全桌面输入＋rate-limit） |
| ⑦ 业界检索 | 已收 |

## §3 架构三选项（待用户裁决）

- **A（推荐）**：orz 做**鉴权守卫层**（配对/二存一/风险机制/审计/后门），传输与画面
  借 RustDesk（自建 relay）或 Tailscale（设备身份＋ACL）——orz 不自研远程协议。
- **B（轻量）**：orz web 桥扩展为**远程指令面**（移动设备远程用 orz：对话/审批/状态，
  无画面流）——工程最小，先落地再演进。
- **C（不推荐）**：全自研远程桌面（画面流/输入注入/设备锁）。
