## §2 勘测发现（本批新确认，均已写入设计稿）

1. **装配链唯一性核实**：全部车道（TUI stdio／`-p`／`--stdio`／web spawn 的 agent child／
   codex app-server hub）会话装配都经 `PermissionBridge::spawn_with_hub_and_policy` 唯一
   调用点（`orz-host/src/lib.rs:1013`），`default_initial_yolo` 单源改造即全车道覆盖。
2. **env 贯通可行性核实**：orz-bin `main` 的 argv→env 桥段（`main.rs:243-353`）先于
   `web`/`doctor`/`archive` 子命令分派（`main.rs:368` 起）；web 桥 spawn child 默认继承 env
   （`orz-web/src/server.rs:785` 无 `env_clear`）——桥式方案零穿参贯通。
3. **Web 解析器会拒旗**：`orz_web::parse_args`（`orz-web/src/lib.rs:136`）未知参数即报错，
   `orz web --yolo` 现状不可达——S1 增补「容忍白名单」勘定项（设计稿 §1.5），S2 随批。
   白名单只吞不落字段，防 web 侧二次解析双源漂移。
4. **banner 路径笔误勘误**：347 档 §2 「`lib.rs:685` banner doc」实为 orz-bin
   `main.rs:682-686`（orz-bin 无 lib.rs）；就地勘误，不另立档。
5. **Web 工作台开关**：现状 Web 面无任何审批模式接口（仅 ACP 网关 `permission` 事件弹窗，
   `main.js:1907`）——开关＝新契约面，S1 裁决降级独立候选（设计稿 §6，`candidate` 不动计数）。
