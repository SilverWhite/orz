## §1 测试内容与目标（What & Why）

- **形态**：客服 agent 仿真评测。**双控制环境**——agent 与用户模拟器**都能**调用工具改变世界状态（Telecom 域建模为 Dec-POMDP）；每域四件套＝policy（策略文档）＋tools（环境工具面）＋tasks（题集）＋可选 user tools。
- **判分哲学**：看**终态**不看路径——DB 哈希比对／环境断言，到达等价终态即过，不要求复现参考轨迹；另有沟通成分（须说清的 info 子串匹配）。
- **能力面**：工具编排＋策略遵循（policy 拒绝）＋沟通协调＋（banking_knowledge 域）知识检索（698 文档、12 种检索策略、shell 检索形态）。
- **与项目目标同向**：pass^k（k 次全过概率）专曝「平均分好看、重复跑不稳定」；OpenRouter 自述选 τ² Airline 因其地板高、对 **provider／基建（harness）差异敏感**——与「找摩擦、干净归因」同向（252 §5 既有判断，本轮无更正）。
- **模态范围**：本线只做**文本**（half-duplex）；voice（full-duplex 音频，需 OpenAI/Gemini/xAI realtime＋portaudio/ffmpeg）与 live 形态**明确不入范围**。
- 域清单（v1.0.1 在册五个）：`airline`／`retail`／`telecom`／`banking_knowledge`＋`mock`（冒烟测试用，不入正式轮）。

## §2 S0① 官方提交 k 值（252 批唯一硬待核项——已核，含更正）

**逐字证据**（`docs/leaderboard-submission.md`）：

- 「**4+ trials** — we strongly prefer results with at least 4 trials per domain for statistical reliability」
- 提交字段：「pass_1 through pass_4: Success rate percentage (0-100) or `null`」——**只到 pass_4**；
- 示例命令全部 `--num-trials 4`；维护者核对清单「4 trials per domain (check trajectory files)」；
- 官方自带基线（`data/tau2/results/final/` 27 个结果文件）**无一例外**文件名带 `_4trials`，user 模型一律 `gpt-4.1-2025-04-14`。

**metrics 源码**（`src/tau2/metrics/agent_metrics.py`）：pass^k＝`C(成功数,k)/C(trials数,k)`（无偏估计，pass-hat-k），k 从 1 到 num_trials 逐级算出。⇒ **4 trials 恰好产出提交所需的 pass_1–pass_4 四个字段**。

**更正登记**：252 批建议「对外可比／上榜 k=8」——**作废**。k=8 出自 Sierra 官方博文（GPT-4 级重复八次剩 25%），属叙事口径；提交面既无 pass_5+ 字段、核验清单也只查 4 trials。**修正后口径＝对外上榜 k=4（事实门槛）／内部摩擦 k=3–5 亦可，k=8 仅作内部加严可选项**。报表仍须写明 k 值＋user 模拟器配置＋版本 pin（不变）。

## §5 S0④ 判分器与用户模拟器

**reward 结构**（`docs/evaluation.md`）：最终 reward＝各成分**连乘**；成分五种——

| 成分 | 判法 | 性质 |
|---|---|---|
| DB | 预测环境终态哈希 vs 参考动作回放终态哈希 | 确定性 |
| ENV_ASSERTION | 对预测环境跑程序化断言 | 确定性 |
| COMMUNICATE | 须传达 info 逐条子串匹配 | 确定性 |
| ACTION | 工具调用逐条与参考比对 | 确定性 |
| **NL_ASSERTION** | **LLM judge 逐条判真**（官方标注 WIP） | **LLM 判分** |

- **唯一 LLM 判分成分 NL_ASSERTION 的默认模型＝`gpt-4.1-2025-04-14`、temp 0**（`src/tau2/config.py` `DEFAULT_LLM_NL_ASSERTIONS`，可 CLI 覆盖）；retail 112/114 题将其计入 reward ⇒ **retail 读数天然含 gpt-4.1 判分成分**——换 judge 省外部依赖但偏离官方读数口径（可比性代价），留 S1 裁决。
- **用户模拟器**＝提示引导的 LLM（`data/tau2/user_simulator/simulation_guidelines*.md`），**非微调模型**；默认与 agent 同款 `gpt-4.1-2025-04-14`、temp 0；`--user-llm` 可换；官方 27 个基线文件全部 user=gpt-4.1。
- **规模参数**（config.py 默认）：`max_steps=200`、`max_errors=10`、`seed=300`、并发默认 3、`num_trials=1`（我们须显式给 4）。
- **提交纪律**：同一 `--agent-llm`＋`--user-llm`＋参数须跨域跨跑完全一致；每域恰一条结果；全部题目、`base` split。
- **S1 前置裁决项**：① user sim 用同款 DeepSeek（单源省配额）还是 gpt-4.1（对齐官方惯例、需 OpenAI key）；② NL judge 保持 gpt-4.1（可比）还是换 DeepSeek（纯自研栈）。两选都合法（custom 提交须 methodology.notes 说明），但影响读数可中性归因的范围。

## §6 S0⑤ 可跑性

- **文本模式无容器**：纯 Python CLI＋LLM API 即可，无 Docker 编排（与 TB/SCBench 的容器成本结构根本不同——252 判断维持）。
- **Python `>=3.12,<3.14`**；装法＝`git clone`＋`uv sync`（pip 不再支持安装）；本机恰有 Python 3.12。可选 extras 中本线**只需默认＋knowledge**（banking 域用；voice/live/gym/experiments 不装）。
- **keys 最小集**：模型 provider key（LiteLLM 走 DeepSeek，`DEEPSEEK_API_KEY`）；视裁决或需 `OPENAI_API_KEY`（judge／user sim）；`OPENROUTER_API_KEY` **仅** banking 的 `qwen_embeddings*` 检索配置需要（`bm25` 为本地、`terminal_use` 为本地 shell——banking 不必绑 OpenRouter）。
- **Windows**：仓库 issue 全量检索仅 7 条 windows 相关，**无文本模式阻断报告**；本机未实测（S2/S3 验证）。banking 的 shell 检索（`terminal_use`）在 Windows 下的假设未验——建议 banking 域列**二阶段**或 WSL 跑。
- 官方基线体量参考：单域 4 trials 全量轨迹 JSON＝8.8–51MB/域（telecom 最大、51MB/114 题×4）——单轨迹 ~50–110KB，盘面与备份按此量级。

## §10 上榜路径与要求汇总（「要求」面答案）

- **渠道**：fork `sierra-research/tau2-bench` → 建提交目录 `{model_name}_{model_organization}_{submission_date}/`（内含 `submission.json`）→ 轨迹外链（Google Drive/HF 等，维护者后续移 S3）→ `manifest.json` 登记 → PR（附结果描述＋轨迹链接）。
- **自检**：`tau2 submit validate`（查文件/覆盖率/配置一致性/指标-轨迹吻合）＋`tau2 submit verify-trajs`。
- **`verified` 标条件**：轨迹可复核＋`modified_prompts: false`＋零漏题；否则 Unverified 带警示标。
- **排名形态**：per-domain 排名、**单域可交**（官方建议四域齐交但不强制）；voice 另榜（不入）。
- **submission.json 必填**：model_name／model_organization／submitting_organization／submission_date（YYYY-MM-DD）／contact_info（email,name,github）／results（每域 pass_1–pass_4）；banking 另必填 `retrieval_config`（榜单徽章，接受 alltools/alltools-qwen/terminal_use/openai_embeddings/qwen_embeddings/bm25 或自描述串）。
- **S1 关键裁决项（新识别）**：scaffold 之择——**(a) 官方 `tau2` CLI 直跑 DeepSeek**＝standard 提交、最干净可 verified、但测的是模型底座（orz 摩擦面不在场）；**(b) orz harness 作 agent 执行体**＝custom 提交（methodology.notes＋references 强制）、测的是 orz 摩擦（与项目目标同向）但 verified 复核更严。两法可**先 (a) 后 (b)** 分账并行：(a) 得对外读数、(b) 得摩擦读数——S1 冻结时定。

### §12.1 user simulator 惯例：非强制、已漂移、有自任先例（答 S1 裁决项①）

- **规则面**：提交 schema（`schema.json`）无 user 模型强制字段，`methodology.user_simulator` 为**申报字段**；硬约束只有「同一 agent＋user＋参数跨域跨跑一致」＋verified 三件（轨迹可复核／modified_prompts=false／零漏题）。
- **惯例面**：官方基线（2025 期）＝gpt-4.1；**Sierra 自家 2026-08 批已整体换 user_sim=gpt-5.2**——惯例随时间漂移，非固定门槛。
- **自任先例（在榜实锤）**：DeepSeek-V3.2 提交（2025-12-01）**user_simulator=DeepSeek-V3.2 自任**、只报 pass_1、无轨迹、τ² 版本还是 v0.1.3，照样在榜（Unverified 标）；Gemini 3.0 Pro（Google 提交）同样自任 user_sim 且带 prompt adjustments 声明；RAFT-30B-A3B 用 claude-sonnet-4-5-2。
- **结论**：非 gpt-4.1（乃至自任同款）user sim **可正常进榜**；代价＝与非官方惯例读数不同质（榜不按 user sim 归一）＋verified 需补轨迹申报。DeepSeek 自任先例即「自跑自报」路线的完整模板。

- **饱和度**：airline pass_1 头部 83（余 17pp）；retail pass_1 头部 ~85（余 15pp）但 **pass_4 头部仅 ~52–62（余近半）**；telecom pass_1 已 89–98（开始挤）、pass_4 顶部 72–94。banking（2026-08 Sierra 批）头部 Qwen3.8-Max 55.2、Grok4.5 47.9、GPT-5.6-sol 46.9、Claude Fable 5 39.7、GLM-5.2 37.1、Kimi K3 37.1。

- **DeepSeek 缺口注记**：榜上 DeepSeek 仅 V3.2（2025-12，v0.1.3 旧版口径）；**V4.x 无读数**——与 Aider 线「代差证据缺位」同形，官方 CLI 臂若跑 V4.x 即为榜补该读数。
- **版本杂居事实**：榜面新旧版本读数并存（DeepSeek 条目 v0.1.3、Sierra 2026 批 v1.0.1），榜不强制 pin——我线纪律仍为 v1.0.1 钉死、报表五元组声明（§8）。

### §12.3 对 §7/§10 的修正性注记

- 「先 (a) 官方 CLI 后 (b) orz」的原排序依据仅三条：(a) 零开发（官方 CLI 当天可跑）、(a) 为 (b) 的对照臂、(a) 是 verified 最短路径。**顺序并无原则性**——(b) 为目标主线时可先行，(a) 裁剪为**最小对照臂**（如仅 airline 50 题×k=4，派生成本 ¥1–2）随行或随后，A/B 归因效力不变（只要求同版本 pin＋同配置）。
- orz 臂（(b)）需要 S2 适配器（τ² 工具面→orz，沿 0cw S2 SCB 适配器先例）；适配器转译层自身会引入新摩擦——须在报表标注「适配器层 vs orz 核心面」，这正是要找的东西，但归因时要分层。

### §12.4 榜单新鲜度：没死，但重心迁移（文本老三域事实上停止吸新）

manifest 三区结构（`web/leaderboard/public/submissions/manifest.json`）：

- **submissions（正式文本榜）29 条**：2026-02-26 → 2026-08-04，几乎全是 Sierra 自跑；其中 **2026-05-05 与 2026-08-04 两批（GPT-5.5/5.6-sol、Claude Opus 4.8/Fable 5、Kimi K3、GLM-5.2、Qwen3.8-Max、Grok 4.5 等全部现役旗舰）只跑 banking_knowledge 单域**。全文本域（airline/retail/telecom）的最后一批＝2026-03-02 世代（Gemini 3 Pro/Flash、GLM-5-think、Qwen3.5）；此后第三方全文本提交仅 raft-30b（2026-04-29）一条。

### §12.5 「题目简单吗」——pass_1 错觉与 pass_4 实况

- 榜面 pass_1 对旗舰确显得友好（airline ~83／retail ~85／telecom ~98）——但榜册是**幸存者样本**：GPT-4.1 航空 56／电信 34，Kimi-k2 电信 65.8，DeepSeek-V3.2 航空 63.8；对 DeepSeek V4 Flash 世代读数远离天花板。
- **设计意图即反「简单」**：GPT-5.2 retail pass_1 81.6 → pass_4 **51.8**（−30pp）、airline 83 → 72——旗舰做「简单」客服题四连全过的概率只有五到七成。双控制（用户改世界状态）＋隐藏态 DB＋policy 约束＋communicate_info＋用户模拟器非平稳性，全部是让单次成功率高估能力的结构。
- **结构性「简单」的成分也要如实记**：工具面小而封闭、单会话（~10–30 轮）、无环境工程——相对 TB/SWE 的工程维度确实轻；其难在**多轮一致性×策略×沟通的可靠性**，恰是 orz 会话/上下文线（0cy/0cz）所压的位置。

### §12.6 用户裁决（2026-10-12）：全 DeepSeek 单源、零 OpenAI key

用户裁决：「用deepseek吧，就用v4.1，openai的key既然能不使用那就不用了，还能便宜点」⇒

- **agent＝DeepSeek V4.1**（现行接口名 `deepseek-flash`，0cv 已对齐）；**user simulator＝同款自任**（沿 DeepSeek-V3.2 在榜先例，§12.1）；**retail NL judge＝同款内部化**（放弃官方 gpt-4.1 判分口径，读数偏离官方须在 methodology 申报）。
- **零 OpenAI key 依赖**：外币项（§9 retail judge $5–25）归零；全链路按内账低价单价计。
- ** verified 面注记**：verified 三件（轨迹可复核／modified_prompts=false／零漏题）不因 user sim／judge 换型而阻——原则仍可奔 verified；但榜面同侪读数（Sierra 2026 批）为 gpt-5.2 user sim 口径，跨条目可比性自带折扣，如实申报即可。
- **方法论星号（如实登记）**：自任 user sim＝同模型自对弈，存在同款误解相关性（用户模拟器或「放水」、或与 agent 犯同类策略误读）——DeepSeek-V3.2 先例同款风险；不影响进榜与摩擦用途，解读沟通类读数时带星号。
- **排程修正（同日）**：§9 尾注「错峰两到三周」系按 r4 式 2h 午间窗的最保守排法；DeepSeek 低谷实为 **0:30–8:30 八小时大窗**，并发 8–15 时一夜可吐约 500–1,000 sim ⇒ 全四域 k=4（1,500 sims）约 **2–4 个通宵窗**可完，无人值守；窗长/并发/是否补高峰为 S1 排程参数。成本与时间的解耦机理＝成本∝token（对话形态量小＋前缀缓存命中），时间∝轮次×往返延迟÷并发（user sim 与 agent 双侧串行往返，每轮一次完整 API 调用）。

### §12.7 banking 适配层勘定（触发＝用户问「banking 的适配程度和前期内容都检索完了吗」；此前仅域级事实，本节补齐，四域 S0 至此全闭合）

- **数据结构**：`db.json`＋`documents/` 698 份知识文档＋`prompts/` 14 个检索策略模板（agentic_search[_write]／all_tools／classic_rag 系 8 变体／full_kb／grep_only／no_knowledge／required_docs＋components 3 件）＋`tasks/` 逐题 97 文件（**id 有 5 个缺口：009/011/013/030/042**，102−97＝5 对账平）＋`tasks_voice.json`；源码侧 `DATABASE_GUIDE.md`＋`db_query/tools/environment/retrieval{,_mixins,_toolkits}.py`＋tests 含 `test_sandbox_manager.py`。
- **检索 variant 注册表（v1.0.1 实读，17 名）**：`no_knowledge`／`full_kb`（全 KB 进 prompt）／`golden_retrieval`（诊断用）／dense 系 7（qwen/openai × embeddings[_reranker][_grep]）／bm25 系 4（bm25[_reranker][_grep]）／`grep_only`／shell 系 2（`terminal_use`[只读|`_write`]）／**`alltools`（默认）与 `alltools-qwen`**（dense＋bm25＋grep＋shell 全开）。dense 模型＝openai `text-embedding-3-large`／openrouter `qwen3-embedding-8b`；**embedding 有磁盘缓存**（`embeddings_cache.py`，698 文档一次性成本极小）。grep 系为**进程内检索工具**（`grep_retriever.py`），非 shell、不依赖沙箱。
- **沙箱＝源码级 Windows 拒绝**：shell 系经 `srt`（sandbox-runtime CLI），Linux 需 `socat`、macOS 需 `rg`，**`sys.platform` 非 linux/darwin 直接 raise**（`sandbox_manager.py` 原文「sandbox-runtime is not supported on platform …」）⇒ `terminal_use`×2／`alltools`×2 在 Windows 原生**结构性不可用**（比 S0⑤ 时的「未验证」更硬）；错误文案自建议「不需要 shell 就换别的 retrieval config」。
- **榜面惯例与零 key 裁决相撞**：Sierra 2026-08 banking 批（Qwen3.8-Max 55.2／GPT-5.6-sol 46.9／GLM-5.2 37.1）**全部 `retrieval_config=alltools`**——即 OpenAI dense＋沙箱全开档。我方「零 OpenAI key」裁决下此档不可用。
- **零 OpenAI 三路径**：①`alltools-qwen`（dense 走 OpenRouter，一个外部 key＋仍需沙箱 ⇒ **须 WSL/Linux**）；②`bm25`／`bm25_grep`／`grep_only`（rank_bm25 本地＋进程内 grep，**无沙箱无 key，Windows 原生可跑**）；③`terminal_use` 系（仅沙箱，同样须 Linux）。reranker 系（pointwise_llm_reranker＝额外 LLM 调用、bge＝本地重排模型）**首轮一律不用**，保归因干净。
- **banking 裁决项（升级为三选）**：**A**＝WSL/容器内跑＋`alltools-qwen`（最贴榜面惯例，代价＝Linux 环境验证）；**B**＝Windows 原生＋`bm25_grep`（零 key 零沙箱，`retrieval_config` 徽章如实申报即可上榜——提交文档明确允许非标准检索配置）；**C**＝banking 二阶段缓行，三域先行。默认建议＝**三域先行＋B 档补全四域**，A 待真要冲榜面同质性再验。

### §12.8 banking dense 通路与价格（触发＝用户问「只变动 key 为 deepseek 行吗／qwen 价格如何」；用户补充＝项目有 WSL 与 Docker 容器环境）

- **DeepSeek 无 embedding API**（外部核证，2026-10-12）：官方仅 chat/reasoner 类模型，文档明示建议第三方 embedding——⇒「单 DeepSeek key」可兜三域＋user sim＋judge（§12.6 裁决不变），**banking 的 dense 检索成分必须有第二来源或放弃 dense**。
- **embedder 通路（源码实读）**：`openai` 型 embedder＝标准 OpenAI SDK，**认 `OPENAI_BASE_URL` 环境变量 ⇒ 阿里百炼 compatible-mode（`dashscope.aliyuncs.com/compatible-mode/v1`）可零代码直插**（embedder_model 换 `text-embedding-v4`）；`openrouter` 型 embedder **写死** `openrouter.ai/api/v1` ⇒ 该路必须 OpenRouter key（`qwen3-embedding-8b`，官方注册表原生档）。
- **价格（两条都近乎免费，不构成裁决因子）**：百炼 `text-embedding-v4`＝**¥0.5/M tokens**（开通 90 天内 50–100 万 token 免费额度）；OpenRouter `qwen3-embedding-8b`≈**$0.01/M**（二手 Tracker，可能有滞后）。我方实际用量＝一次性索引 698 文档 ~0.5M token＋运行期查询 ~1M token ⇒ **两路均 <¥1**。
- **沙箱解锁**：用户确认 WSL＋Docker 在场 ⇒ `srt` 沙箱（Linux 需 `socat`）可跑，`alltools` 全功能档（dense＋bm25＋grep＋shell）在容器内可行——§12.7 的 A 档成立。
- **banking dense 档位修正（三选）**：**A1**＝容器＋`alltools` 机械形态＋`OPENAI_BASE_URL`→百炼（阿里 key；国内网络稳、人民币计价；`retrieval_config` 徽章写自述串如 `alltools-dashscope`＋methodology.notes）；**A2**＝容器＋`alltools-qwen`（OpenRouter key；**官方提交表接受名单内的原生档名**，榜面语义最正统；境外端点视网络车道稳定性）；**B**＝Windows 原生＋`bm25_grep`（零 key 零沙箱，无 dense 无 shell）。dense 底模与榜面（text-embedding-3-large）不同质——检索层作为变量记入五元组。

### §12.9 用户裁决（2026-10-12 二批）：非官方配置以如实申报上榜＋排程不分峰值低谷

- **非官方配置可上榜＝确认**（用户问「官方反正也接非官方配置的成绩吧，只要明确都交代明白？」）：提交文档原文允许「不同检索方法用短描述串」＋`methodology.notes` 说明，徽章照显示；榜面先例（Gemini 3.0 Pro 带 prompt adjustments 申报、DeepSeek 自任 user sim、RAFT 用第三方 user sim）均在榜。**verified 保全要点＝prompt 模板不改**（用标准 variant 模板原样、只换 embedder 后端 env）⇒ `modified_prompts=false` 保得住；轨迹齐全＋零漏题 ⇒ verified 仍可奔。A1（百炼）档由此正式可行。
- **排程终裁**（用户：「这个价格能不分峰值低谷连续跑，我能承受」）：**不再做峰值/低谷窗调度，24 小时连续跑**；低谷价从「排程约束」降级为「偶然折扣」。成本上限核算＝即便按低谷价 2× 计峰值，全四域 k=4 也仅 ¥16–66 量级。残留运维项＝限流退避与断点续跑（runner 必做）；与 0dc r4 的并发共存靠退避自然消化，无需窗位错峰。

### §12.10 用户裁决（2026-10-12 三批）：user sim 自任定案＋banking 单点换 key

- **user simulator＝DeepSeek V4.1 自任自对弈，定案**（用户：「就背着自对弈的误解相关跑吧，deepseek官方都这么做的」）。§12.6 的方法论星号**保留为报表常驻注记**（沟通协调类读数解读带星）；缓解事实随注记一并写＝telecom 的复杂度不对称设计已把 user sim 误差压到四域最低（论文 Table 2：16% vs retail 40%／airline 47%），且 retail/airline 为单控无用户工具。
- **候选评估留档（均未采纳）**：①GLM（Z.ai 开放平台）／Qwen（DashScope 中档）作第三方 user sim——方法论更贴官方惯例、可去相关性，但需增 key／增成本（¥20–150 量级），用户裁决不换；②Google AI Studio 免费层——配额差 1–2 个数量级（需 2–5 万次调用 vs 免费档 ~250–1,000 RPD／10–15 RPM）且境内可达性脆，**仅限 S3 冒烟与开发调试用途**。
- **key 清单定案（共两把）**：`DEEPSEEK_API_KEY`（chat：agent＋user sim＋NL judge）＋阿里百炼 key（banking dense embedding，A1 档＝容器内 `alltools` 机械形态＋`OPENAI_BASE_URL`→dashscope＋`text-embedding-v4`，徽章自述串申报）。**零 OpenAI、零 Google、零 OpenRouter。**
