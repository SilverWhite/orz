### 1.3 判分器核证：pytest 确定性 oracle（零 LLM 判官依赖）

- 评测系统 v2.0＝**pytest 驱动**：`PytestRunner` 经 uvx 隔离执行题目仓自带 `tests/test_checkpoint_N.py`，按 marker 四分类——无 marker（当前 checkpoint）＝**CORE**、`@pytest.mark.functionality`＝FUNCTIONALITY、`@pytest.mark.error`＝ERROR、**既往 checkpoint 测试＝REGRESSION**；checkpoint 通过判据＝PassPolicy（`core-cases`／`any`）。
- LLM judge（`slop-code metrics judge`，rubric `configs/rubrics/llm_judge.jsonl`，OpenRouter 模型）**仅为代码质量参考面**，不进主 oracle——与本仓「机械提取、不引二手账面」纪律相容，主读数零 LLM 判官。
- `slop-code eval outputs/<run>/` 出逐 checkpoint 结构化报告；`one_shot`（折叠 checkpoint）与 `pass_policy` 均 CLI 可配，本线不用 one_shot（要的就是逐 checkpoint 长程）。
- **基准不饱和（外部难度锚）**：论文最强 Opus 4.6 strict pass 17%、GPT-5.4 11%；HumanLayer 复测 Opus 5 仅 24%（4/17，且全部集中在 circuit_eval ck1–3 与 database_migration ck1 早期 checkpoint）——「随 checkpoint 推进 pass 率坍缩」即本基准设计的退化信号，对摩擦探针线（不追分、看行为）正对口。

## §2 agent 接入契约核证

### 2.1 SCBench 侧（harness Agent ABC）

- 接入单元＝Python 类：`Agent` 抽象基类六方法（`_from_config`／`setup(session)`／`run(task)`／`reset()`／`save_artifacts(path)`／`cleanup()`）＋`register_agent` 注册＋YAML 配置（`type/binary/version/cost_limits{cost_limit,step_limit}`；claude_code 参考：`step_limit: 100`/checkpoint）；现有 9 个 agent 实现（claude_code/codex/cursor_cli/gemini/kimi_cli/miniswe/opencode/openhands/pi）可作模板。
- **checkpoint 循环语义（对 RLI 观测关键）**：每 checkpoint 调一次 `run(task)`，**默认不重置状态**（`finish_checkpoint()` 仅累积成本，`reset()` 由各 agent 自行决定）；claude_code 实现以 `resume=True`→CLI `--continue` 维持**单连续会话跨全部 checkpoint**——长程退化（path dependence、code erosion）正是建立在同会话延续之上。
- 容器形态：每 agent 一张 `docker.j2` 模板镜像（agent CLI 装入镜像，版本可 pin），`StreamingRuntime`/`SubmissionRuntime` 承载容器内执行与输出流；workspace 快照/diff 面齐备（snapshots.py）。
- 任务文本＝prompt 模板（`configs/prompts/just-solve.jinja` 等）渲染 checkpoint_N.md；产物面 `save_artifacts` 落 stdout/trajectory/messages 供解析。

### 2.2 orz 侧（无头入口与会话连续性）

- **`orz -p "<prompt>" --real`**（TB 2.1 先例形态）＝每次调用**新会话**——跨 checkpoint 上下文断裂，**不适用** 0cj。
- **`orz --stdio`**＝ACP 服务入口（`session/new`＋`session/prompt` 多轮；ACP 路径与 `-p` 同源生产装配，orz-host `acp_server`），**同会话＝同黑板＝同上下文**，逐 checkpoint `session/prompt` 即得 SCBench 语义的 orz 等价物——**S2 适配器定形：容器内常驻 `orz --stdio`，适配器经 stdio 管道逐 checkpoint 投递任务文本**。
- **RLI 作域已核**（controller.rs `render_rli_section`）：RLI 通道**已生产化常开**（0bf 2026-09-22「RLI 生产化与域建模试验」——kill-switch 语义反转为缺省 ON，显式 `ORZ_LIF_RLI_SHADOW=0/off/false/no` 才关；「影子」仅存于该 env 名与内部结构名，**同日用户勘误确认「目前 RLI 已不是影子」**）；状态**会话级、跨 run 累积**（面内自述「rli.history → 会话相对；全 run 无窗口」）——一题一个连续会话＝RLI 时间轴天然覆盖全题长程，观测面成立。
- 读数收取面（S3 用）：①消费率＝journal（`.gsa/runs/RUN-*/events.jsonl`）中 `blackboard_read section=rli` 调用事件（0bf S3 解析先例，基线 0/3）；②阈值推面＝0bd ⑦ 在役事件；③0ck 注解已在 0.8.10 载体（155 批进体），本轮即「注解单臂」实验处理。
- 每题 run 粒度：一次 `session/prompt`＝一个 run（journal 一条 RUN-*），RLI 跨 run 连续；checkpoint 间无 reset。

### 2.3 S2 适配器工作量定性（新写，规模小）

新增 `orz` agent 包（Agent 子类 ≈ 现有 CLI agent 模板规模）＋YAML 配置＋`docker.j2`（orz-linux musl 静态二进制注入镜像，TB 同源产物）＋ACP stdio 驱动与逐 checkpoint 投递＋journal/产物回收。零 orz 源码改动（观测线纪律：只观测不改造）。
