# 会话内检查点时代机制设计稿（/checkpoint ＋ /btw；CONTEXT-CHECKPOINT-ERA）（2026-10-30）

> **状态**：设计稿 v1.0，待用户裁决立项（候选编号 0dx；本稿落盘不占计数）。
> **来源**：LIF 工作区三会话工具调用衰减曲线只读取证（51da03ea／073b8892／224b39bd）＋ SCB 四轮会话形态对照实证（SprocketLab/slop-code-bench issue [#44](https://github.com/SprocketLab/slop-code-bench/issues/44)／[#45](https://github.com/SprocketLab/slop-code-bench/issues/45)）＋用户逐条裁决（原文摘录随 §2）。

## §0 问题与定位

### 0.1 实证基础

**衰减曲线（行为面，历史基线）**——三个会话逐用户轮工具调用数：

| 会话 | 逐轮调用数 | LIF 域 |
|---|---|---|
| 51da03ea（10-22～25，主线讨论） | 71 → 30 → 20 → 16 → 7 → 6 → 19 → 0 | stuck |
| 073b8892（10-23，协议维护讨论） | 30 → 36 → 12 → 9 → 6 | low_progress |
| 224b39bd（10-28～30，MD1 支线） | 17 → 4 → 3 → 1 → 2 → 1（讨论段） | low_progress |

三会话同形：**开局合规量高、逐轮单调塌缩至近零**；黑板签名同构（开局写 1–2 次、blackboard_read 全程为零或早期归零）；51da03ea 合规最重的一轮（71 次）恰好紧跟压缩之后＝**干净上下文即高合规**。

**SCB 四轮对照（产物面，issue #45 表格）**：连续会话 R1＝full solve 1/36；每 checkpoint 重置 R2/R3（带泄漏通道）＝5/36、3/14；clean room R4＝4/36，core-green 73.5%／isolated 44.9% 均为四轮最高。**重置形态优于连续形态**；且 #44 实证模型在 14/14 题主动翻找跨 checkpoint 上下文（150 次读取）、#45 披露 clean room 中模型自行发现并解包上一轮归档——**模型寻求连续性，但付不出在陈化上下文中维持纪律的成本**。

### 0.2 归因与治理对象

衰减＝**上下文陈化分量（可变）＋先验最小化分量（恒定）**。本设计只治理前者：**给时代长度封顶，把每轮工作上下文锁在"新开窗口"档**。先验分量（时代内后期仍会偷懒）不治；黑板时代内弃养、量尺对账缺口（0dw）各归各的项。

### 0.3 会话语义重述（用户裁决）

**会话＝话题分类器**：一个会话承载一个话题，不再是整体任务容器。**时代＝话题内检查点**；**run＝一次执行**。三层身份定案与 `GAP-RUN-SESSION-BOUNDARY`（0ba，pending 候选）并案处理。

## §1 机制定义

### 1.1 触发面

| 输入形态 | 语义 | 行为 |
|---|---|---|
| `/checkpoint`（会话 idle 时） | 手动时代重置 | 立即执行时代切换（§1.2）；无伴随输入则切换后不自动拉起 run |
| `/checkpoint`（run 在途） | — | 不受理，返回提示（在途切换走无前缀路径；机械最简） |
| 无 `/btw` 前缀用户输入（idle） | **新时代开局** | 机械层执行时代切换，随即拉起新 run，该输入即新时代首条用户消息 |
| 无 `/btw` 前缀用户输入（run 在途） | 下一时代开局（排队） | 沿 0di 排队语义挂起；在下一个安全边界（loop-top／run 终态）执行时代切换后拉起灌入——**不立即打断** |
| `/btw` 前缀用户输入（任意时刻） | **同时代补充** | 照走 0di 中途补充语义（LLM 调用边界 flush、排队、不打断），零行为变化 |

触发是输入的**句法属性**，外生、零歧义、零模型参与（SCB checkpoint 外生性原则的会话内移植）。会话 idle 时收到 `/btw` 前缀输入＝按普通输入处理（无在途 run 可补充，即同时代新轮）。

### 1.2 时代切换动作（纯机械、零模型参与、零 API 调用）

1. **无损折叠**：当前时代全部消息整段落为**单个回放块**——原文写入 `.gsa/compaction/blocks/`（与 v0.4 分块同构），**不摘要、不打包压缩**（对照净室轮 R4 的存档 .gz：降低回查摩擦，免解包）。
2. **工作窗重置**：清空滑块，仅保留幸存面（§1.3）。
3. **时代标记**：插入一条 **v0.4 marker 同构的最小机械标记**——指针字段齐全（块路径／轮次区间／digest／台账 seq），**无语义摘要槽**（与 compress marker 的唯一实质差异；不追加编辑清单等任何额外内容——见 §2 裁决 4）。时代块因此自然进入既有块表／回答前机械审计面（context_map／分块表），**模型按既有机械面自查，机械层不喂**。
4. **黑板清空**：模型分区（plan／notes／findings／state）随时代清空（§1.4）；journal／ledger **不清**（§1.5）。
5. **落账**：journal 记时代边界事件（era 边界、块号、触发来源＝命令／无前缀）——可观测面，供逐时代行为读数。

### 1.3 幸存面（封闭清单）

系统提示、工具定义、时代标记（§1.2-3）、用户的新输入。**其余全折**——含黑板模型分区与 state 分区（旧 state 留在时代块内可回查；新时代目标由用户无前缀输入重新声明）。**幸存面新增必须走裁决**（防常驻面回潮）。

### 1.4 黑板时代化（用户裁决：黑板不跨时代）

黑板从"跨时代记忆"**降格为"时代内草稿面"**：notes／plan／findings／state 为时代内 scratch；**跨时代知识唯一合法通道＝工作区文件**（INDEX／MAP／讨论文档／实验数据——带 provenance，沿 fep_env_research 七条边界"数值必须指回 manifest/log/JSON"的认识论）。结构性收益：**陈旧板面寿命上限＝一个时代**（224b39bd 陈旧笔记挂 250 轮的事故类目被结构消灭）。

**工具教学随批**：`blackboard_write` 描述由"fold-proof durable memory"改为 era-scoped 表述（"跨时代记忆走工作区文件"）；顺带修 `blackboard_read` 描述分区列表缺 `state` 的漂移（0dw 邻接发现）。

### 1.5 审计链连续（相对 R4 的增量）

journal／ledger 为**会话级**审计存储，不属黑板记忆，不随时代清。故本设计＝**R4 净室内核＋会话连续审计线＋块回查合法阀**：时代块给模型的连续性诉求（#44/#45 实证）一条标注清晰边界的合法通道——找得到、但找到的东西带"上一时代"戳，陈旧内容无从冒充现行事实。

### 1.6 压缩分层（压缩机制不退休）

| 层 | 机制 | 保真 | 职责 |
|---|---|---|---|
| 时代边界 | `/checkpoint`／无前缀输入 | **无损**整段块（零模型参与） | 给上下文陈化封顶 |
| 时代内 | 现有滑块／阶梯／`context_manage`（compress 等） | 有损语义（模型参与） | 时代内长轮正常运转，**照旧** |
| 跨时代 | 无机械记忆：黑板已时代化；文件为唯一通道 | — | 知识存活必须走 provenance 文件 |

## §2 裁决记录（本对话用户令摘录，设计稿如实转录）

1. 触发＝/btw 协议："用户插话或者单次补充必须使用 /btw，在这一前提下使用无 btw 前缀的用户输入来作为自动重置的触发就好了，机械层直接做，做完了再自动拉起模型，把用户输入灌进去"。
2. 压缩不退休："单次运行的压缩还是正常的，压缩机制不退休"。
3. 黑板不跨时代："黑板实际上不跨时代也可以吧？……做干净的滑块切换"（撤设计讨论中"黑板跨时代"的中间提案）。
4. 边界零追加："时代边界这一部分不额外追加，依旧就作为回答前的机械审计就可以了，让模型自己查——既然 1017 喜欢明确内容和工程化，那我们就让他自己做工程化"。
5. 净室对照："新时代的开始就相当于重启进程，只不过净室轮中 checkpoint 是用的存档，而本设计降低回查摩擦，使用干净滑块切换，不大安装包，省得还要解包"。
6. 手动命令先行认可："手动的 /checkpoint 暂时先用着我考虑问题不大"。

## §4 验收判据草案

1. `/checkpoint`（idle）：块生成、工作窗重置、黑板模型分区清空、块表可见、journal 事件在案、新 run 语义正确。
2. 无前缀输入（idle／在途）：换代＋灌入／安全边界换代；`/btw`（idle／在途）：不换代、0di 排队照旧。
3. journal／ledger 跨时代连续；state 旧值在块内可回查。
4. 教学面与时代语义一致（blackboard_write／read 描述）。
5. 行为读数面：S4 判据（§3）。

## §5 边界与已知限制

- 不治先验分量：时代内衰减照旧，本设计**封顶不消灭**。
- 忘带 `/btw` 的代价＝非预期换代；恢复＝块回查＋TUI 用户面反馈行（"[时代已切换｜补充请用 /btw]"——用户面提示，不属模型面追加，与裁决 4 不冲突）。
- 无损块的体积代价：会话卷随时代线性增长（现况 3.4MB/2 天量级，可接受；块为原文文本、无打包）。
- 跨多时代回查＝逐块 read_file 分页（块粒度回查；不做跨块全文检索，机械面不新增）。
- 与 0dw（量尺对账）正交并行；与 0cy 划界＝0cy 管会话间断点卫生、本设计管会话内时代切换；与 0cz/0da 清零族划界＝无损折叠 vs 有损交接。
