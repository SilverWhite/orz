## 1. 问题（O1）

框架不校验「**正在优化的量**」与「**验收判定的量**」是否同一口径，也不校验
「当前做法是不是最短路径」。TB 4.0 探针里这两个缺口同时发生：agent 以纯 IP 规则
剔除机器人后统计点击率，得出 4.0182% 并据此收敛到 `ad_load=0.25`；而验收以
「最终配置 + 疲劳重放」解析计算，得 0.4363%（差 9.2 倍）。收尾的反例门只检验了
**同一把尺子下**的敏感性（含/不含机器人、不同停留阈值），从未质疑尺子本身。

同源问题在本项目自身也有先例：**过度自制**——本该复用成熟组件却自行长路自建，
方向偏移在投入大量工时后才被纠正。

## 2. 用户裁决与设计原则（2026-09-11）

1. **不在周期问询里加这一问**。若把它挂到周期性中立问询上，会让模型在动作过程中
   **反复质疑**自己，干扰动作。
2. **大方向上的决定与设计应当一开始就完成**；动作过程中的中立问询只承担
   **回看与确定**，不承担回查与质疑。
3. **即便中途需要二次决策，也不应表现为"回查和质疑"**。
4. 因此 O1 的正确形态是：**开局先做一次判断**——在中立问询机制下开一个**小的
   额外设计**，把这一问放在**第一轮动作最后的机械审查**里，一次性请求模型判断
   当前实际任务的**口径与方向**以及**做法优劣**。

## 3. 设计

### 3.1 一句话定义

**伴审计中立问询** = 复用既有中立问询（orientation）的软门语义、票据与 pending
软消费机制，把三问**附着在机械审查报告上**由机械层直接带给模型看；问句要求模型
**声明**（而非自证）当前任务的口径、方向与做法优劣；**一次性**，此后永不重复。

载体与既有机制的关系（2026-09-11 用户复核后的关键事实，务必按此理解）：

- 框架确已设计「机械审查 + 反例质询」成对出现——`[MECHANICAL_AUDIT v0.1]` 报告块
  与 `[COUNTEREXAMPLE_GATE]` 块**同轮注入**，报告内容为「执行事实 / 预算 /
  异常事实」三段（`orz-loop/src/mechanical_audit.rs:127` 起）。
- 但该报告**目前只有一个注入点**：模型**第一次不调用工具、准备交答案**的那一刻
  （`orz-loop/src/agent_loop.rs:2141-2185`，`once_only: true`、
  `position: "final_answer"`）。它**不是每轮都出**，也**不在首轮动作结束时出**。
- 长任务的实证反例：TB 4.0 探针里模型从第 1 轮一路调工具到第 776 轮，报告与反例
  质询直到全部工作做完之后才出现（事件序号 7078）。
- ⇒ **若只把三问附到现有那份报告上，长任务里它会晚到收尾，恰好与"开局先做判断"
  相反**。因此 §3.2 的注入时机是本设计的唯一待裁决点（§7.1）。

### 3.2 触发

| 项 | 定义 |
|---|---|
| 触发类型 | `audit_companion`（新增；既有为 `completed_turns_interval` / `pre_handoff`） |
| 说明 | 本设计的设计稿（2026-09-11 首版）曾把落点写成 `post_tool_batch_gap` 独立注入；用户复核指明**载体应是机械审查报告**（"机械层直接带着进审查报告里让模型自己看"），故载体改为报告，时机见 §7.1 |
| 载体 | **机械审查报告** `[MECHANICAL_AUDIT v0.1]` —— 三问作为该报告的一次性附着段（同一块内，非独立消息） |
| 建议触发条件 | **首轮动作批次结束**——第一轮模型输出产生至少一次工具调用、且该批工具结果已全部返回；由机械层此时产出一次同源报告并附三问 |
| 频次 | **会话内恰好一次**。与阈值 50 的周期问询互不影响、互不重置 |
| 并发闸 | 沿用既有 **单一 pending 闸**：同一时刻只允许一个 pending checkpoint；本问询未消费前不触发周期问询 |
| 无工具批次（**用户已认可**） | 若首轮模型输出**没有**工具调用（纯文本回复），不在该轮触发；顺延到**首个含工具调用的批次结束**后再注入（避免打断"先回答"的回合） |
| 终答前报告 | 既有终答前 `[MECHANICAL_AUDIT]` + `[COUNTEREXAMPLE_GATE]` 注入**保持不变**；由于本问询一次性，终答前那次**不再重复三问** |

### 3.3 问句（附着段 `[AUDIT_COMPANION_INQUIRY v0.1]`）

**三问并列（用户 2026-09-11 裁决：详细一些也好，反正只跟着机械审查触发一次）**，
与既有 `ORIENTATION_BLOCK v0.4` 并列、**独立常量**（不复用、不改写周期问询的三问）。
作为机械审查报告块内的一次性附着段：

```
[MECHANICAL_AUDIT v0.1]
执行事实：…（既有三段照旧）
预算：…
异常事实：…

[AUDIT_COMPANION_INQUIRY v0.1]
开局声明（一次性，非强制模板，不打断动作）：
1. 口径：本任务实际要交付什么、会被按什么判定？请写明判定标准、度量口径与
   数据来源；若存在多种可选取法，写明你采用的是哪一种、为什么。
2. 方向：本任务的大方向是什么？当前所处的阶段与下一步要解决的问题是什么？
3. 做法：当前做法的优劣各是什么？是否存在更短、更直接、更省成本的路径
   （例如已有能力可直接复用、无需自建）？若有，为什么没有选它？
[/AUDIT_COMPANION_INQUIRY]
[/MECHANICAL_AUDIT]
```

**措辞纪律**（对应 §2 原则）：用"声明 / 判断"，不用"检查 / 复核 / 是否搞错"；
不要求自证、不要求反驳；**不设结构化字段强制**。目的是让模型在开局**定下来**，
而不是让它进入自我怀疑循环。第 3 问里的"是否有更短路径"正是对**过度自制**类方向
偏移的直接提问（用户 2026-09-11：有些内容本就不该绕远去做）。

### 3.4 软门语义（沿用，不新增）

- 不阻断工具、不设模板校验、不禁止工具调用；纯文本回答被消费后 loop 明确续跑，
  终答仍只由模型自发（沿 THIN-HARNESS-REDESIGN-V2 §9.2 主车道延迟 commit 软门）。
- 事件先行、commit 在后：journal 写入失败不得留下"已 reset 未 fire"的计数
  （沿 review P2-2）。
- **恢复语义**：fire 后未被消费即中断（传输错误/取消/panic），计数不提交，
  下次 run 在 `loop_top_gap` 首轮重触发——沿既有 recovery-resumes-counting；
  孤儿事件由运行终止事件解释，不补机制。

### 3.5 与既有机制的分工（不重叠）

| 机制 | 时机 | 职责 |
|---|---|---|
| **初始轮问询（本设计）** | 首轮动作结束，一次 | 开局**定**口径、方向、做法 |
| 周期中立问询（现状） | 每 50 个模型轮 | **回看与确定**（三问保持现状，不质疑） |
| 反例门（现状） | 计划/正式结论写入前一次 | 结论前的反例检查 |

## 4. 非目标

- **不改**周期中立问询的三问与阈值（保持 §2 原则 2：动作中只回看与确定）。
- **不新增**硬门、不新增工具、不改工具面、不改轮次预算。
- **不要求**结构化回答字段，不把"是否答对"变成评分或拦截条件。
- 不做任何"质疑型"追问；不因回答内容触发额外轮次。
- **不落黑板锚点**（用户 2026-09-11 裁决）：实际使用中只要该问询能被触发，后续会
  有新的讨论与询问，届时再决策；**不把旧的审查内容长期留在黑板上**。
- **不额外设计消费审计**（用户 2026-09-11 裁决）：本问询跟着机械审查走，
  机械审查自身的审计设计已足够；再单独记录"是否已被消费/已作答"属多余。
- **不改**既有终答前的审查报告 + 反例质询注入（只保证三问不重复）。

## 6. 成本与收益

- **成本**：每会话 **+1 次模型调用**（一次性，随任务规模摊薄）；无新增常驻 token；
  无工具面变化。首轮问询的回答会短暂占用上下文（一句话量级）。
- **收益**：把"口径 / 方向 / 做法"的判断前置到开局——正是 O1 命中场景
  （代理指标 ≠ 验收口径）与"过度自制"类方向偏移的**最早可拦截点**。
  按 TB 4.0 探针的代价换算，一次拦截可省数小时墙钟与数千万 tokens。

## 7. 待用户裁决的开放项

### 7.1 唯一待裁决：注入时机（A/B）

载体已定（机械审查报告，用户 2026-09-11 复核）；**时机是唯一未定项**：

- **A（不推荐）零改动法**：三问只附着到**现有终答前那次**报告上。零新增注入点，
  但在长任务里它和反例质询一样**晚到收尾**（TB 4.0 实证：第 776 轮才出），
  **不解决 O1**。
- **B（推荐）开局法**：让机械层在**首轮动作批次结束时**产出一次**同源同格式**报告
  并附三问；终答前那次保持不变且不重复三问。满足"开局先做判断"，且载体仍是审查报告
  由机械层带给模型。代价：新增一个报告注入点（报告生成器与块格式复用，不新建机制）。

**建议取 B**；若取 A，则本设计与 O1 的目标不匹配，应退回重新定位。
