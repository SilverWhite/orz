## 1. 背景与数据（2026-08-18）

- 复验运行 `D:\tb-eval\jobs\2026-08-18__19-40-12`：57 请求，命中率 **81.9%**
  （miss 1,116K）；其中 39 次折叠推进 + 1 次压缩后的相邻请求贡献 **~1,044K
  （93.5%）** 的 miss。今日全天命中率 75.95%（07–09 时失败运行 71–76%、
  19–21 时复验运行 78–83%）。
- 纯追加理想下限：前缀完全稳定时 miss ≈ 末请求 − 首请求 ≈ 185K → 理论上限
  ≈97%。
- **根因 A（触发线不复位）**：视图内台账块随推进累积（每次推进新增摘要行），
  推进后视图（preamble + 台账 + 尾部 2 轮）仍 ≥ `fold_trigger_tokens`(128K) →
  每 ~1.5 轮推一次（39 次 / 57 轮）。
- **根因 B（重写成本）**：每次推进重写视图内台账块，公共前缀在旧台账末尾
  截断，其后整段（含尾部）重新计费；单次失配 5–113K（早期 ~15–30K、后期
  60–113K）。
- **根因 C（压缩联动）**：288K 兜底压缩整段重写 ~173K；因推进风暴未压住视图
  而触发。

## 2. 设计定案（单纯外挂文件形态）

### 2.1 视图结构

- 未折叠：`messages` 原文（同现状，无指针）。
- 已折叠：`[U0][固定指针消息][最近 1 轮原文]`。

固定指针消息（合成消息，不在 `messages` 持久化，**字节级固定**——路径固定、
文本固定、不含任何变化 ID/序号）：

> 【历史折叠】更早轮次的机械摘要已外挂存档：`<abs-path>`（本会话内固定）。
> 需要回顾历史时按行检索该文件，例如 `grep "轮次" <abs-path>`、
> `grep <工具名> <abs-path>`。当前会话仅保留最近 1 轮原文，更早内容一律在该
> 文件中。

### 2.2 推进（每窗口一次，纯机械，无模型调用）

触发沿用：loop-top 完整轮间隙、`build_request_view` 估算（chars/2）≥
`fold_trigger_tokens`（128K，可配 `ORZ_FOLD_TRIGGER_TOKENS`）且存在 ≥2 个
完整轮（至少 1 轮可折叠 + 保留 1 轮）。

执行（与现有 `advance_fold` 同触发点，行为改为）：

1. `kept_start` = 最近 **1** 轮起点（`collapsed_cut(messages, tail=1)` 语义；
   fallback 压缩 widened tail 时按 `tail+1`）；
2. 将 `messages[上次 fold_cut .. kept_start)` 中**新增**折叠轮次的摘要行
   **追加**进外挂文件（原子追加：O_APPEND 单行写 + flush，或写临时文件后
   rename；带轮次分隔标记）；
3. `fold_cut` = `kept_start`；`fold_start`、指针消息**不变**；
4. 不调模型、不重渲染任何块、**不删除 `messages`**（messages 全量保留，
   journal/sidecar 轨迹不变）。

推进后视图 = 指针 + 最近 1 轮 ≈ 30–60K（本任务单轮可 ~50K）< 128K →
**触发线真实复位**，推进频率回到「每窗口一次」而非「每 1.5 轮一次」。

### 2.3 外挂文件

- 路径：`{session_cwd}/.gsa/ledger/current.md`（会话内固定；run 目录天然隔离，
  跨 run 不混用）。
- 行格式（沿用现有台账行语义，前缀加**全局轮次序号**，跨压缩连续）：
  `[<全局序号>] 轮次 <序号>: <工具> 目标=<目标> 结果=<指针> 最终回复=<文本>`
- 追加式写入、只增不轮转（压缩不重置）；序号续点以文件为准——推进时读文件
  尾行取最大序号 +1（文件只增，读尾行 O(1)）。
- 规模：摘要行 ~200–350 字符/行；1000 轮 ≈ 300KB，grep 瞬时，无索引需求。

### 2.4 压缩联动

- 摘要输入 = 折叠视图（含指针 + 最近 1 轮），摘要调用成本低。
- drain / marker 插入 / `fold_state.reset()` 不变；marker 文本追加一行
  「历史摘要累积于 `<abs-path>`」（marker 为压缩时新插入，不涉前缀稳定）。
- 外挂文件只增不重置；400 修复不变量（retain 后移、触发未执行零副作用、
  preamble/safe_fold_cut 放弃折叠）全部保留。

### 2.5 审计

- `messages` 全量保留 + journal/sidecar 逐事件全文轨迹不变（审计双轨不变）；
- 外挂文件是**可确定性重推的模型可读投影**（由 journal 可重建），损坏不致命。

## 3. 明确不做

- 不激活 `memory_get` / `memory_search`（用户裁定：不需要记忆本身、模型无总结
  负担；「接口」= 固定路径 + 既有 read_file/grep 使用契约，零新增工具面）。
- 不做模型侧总结负担（摘要行机械生成，不调模型）。
- 不改压缩触发参数（192K/256K）与 drain/marker 执行语义。
- 视图内大工具结果截断列为第二阶段候选（§4），不阻塞第一阶段。

## 4. 第二阶段候选：视图内大工具结果截断（头 + 指针，全文进轨迹）

仅在用户后续放行时实施。核心：视图内大工具结果（read_file/grep/终端等）只留
头部摘要 + 指针，全文保留在 journal/sidecar（机械轨迹），模型按需取全文。

- 利：每轮追加从 10–50K 降到 ~2–5K → 128K 窗口内可累积 25–60 轮 → 推进频率
  再降、纯追加 miss 大减 → 命中率 ~95–97%；视图更短更稳，推进边界失配也更小；
  同等窗口下模型有效工作记忆更久。
- 弊：模型丢失工作上下文细节（编译日志/大文件全文需额外 read_file 取回，多一
  轮工具往返与预算）；截断阈值按工具/场景需分别定；依赖模型主动取全文的纪律
  （可能基于头部误判，需指针醒目 + 提示词强调）；每个大结果工具的视图注入点
  都要改（机械面比第一阶段大）。
- 验证方式：并入验证④（2–3 题交叉）实机观察「模型查全文」行为与任务质量，
  确认不伤成功率后再定阈。

## 5. 预期收益（第一阶段）

- 推进次数：本任务 57 轮从 39 次降至 ~8–15 次（128K 窗口、单轮 ~10–50K 追加）；
- 推进总 miss：~1,044K → ~150–300K（每次边界失配 ~10–30K，摊薄到窗口）；
- 命中率：81.9% → **~91–93%**（本任务；含纯追加 ~185K 下限的贡献）。

## 8. 风险与回滚

- 模型不主动翻文件 → 任务质量风险：指针消息醒目 + 摘要行信息量足够（目标/指针/
  最终回复）；若验证④观察恶化，可回调尾部保真至 2 轮（单参数）。
- 文件写入失败：推进失败不阻塞会话（fold 状态不更新，下次触发重试）；journal
  仍是权威轨迹。
- 序号错乱：以文件为准续号，可确定性重推修复。
- 回滚：改动集中于 build_request_view / advance_fold / 推进写文件三点，单提交
  可逆；最坏代价=每窗口一次全量视图（低频，接受）。
