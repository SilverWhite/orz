## 0. 背景与病灶（实证）

- plan 门已于 2026-08-27 从全部生产入口摘除（CLI 与 ACP 一致），`plan_write`
  下线、submit 对无 plan 放行。由此：
  1. 黑板轮换触发源（新 plan epoch 批准）在生产中不再出现；`.gsa/blackboard`
     epoch 归档只被 `--plan` 诊断路径与测试触达——「按 plan 归档」实际空转。
  2. ACP 生产路径每 prompt 新建 controller/黑板（无 plan、无归档目录）——
     工作记录既不按 plan 也不按对话延续；跨 prompt 只延续消息/压缩 marker、
     检索分区、LIF spikes 等少量 sidecar 状态。
  3. 压缩五段摘要的目的/计划槽机械读 `plan.goal`/`steps` → 生产恒
     「（未设置）」；注意事项槽的 plan 失败步骤源永不出现；marker 的
     `plan_epoch` 为「（未设置）」，回查行仍引导模型用 epoch 参数读不存在的
     归档（实机返回 `blackboard archive dir not configured`）。
- 跑分实证（official-r1 87 runs + 2026-08-29 c1–c4 30 runs + s5x 36 runs +
  8-31 检索复验 7 runs）：上下文压缩几乎不触发（全语料共 2 次），ledger fold
  稀疏（c1–c4 共 8 次，超时 run 中仅 2 个 fold 过）；超时主体为墙钟工具时间。
  长 run 缺总览记录 → read_file/grep 自寻频繁；模型对 blackboard_read 使用率
  低；web 密集任务 search/fetch 次数显著高于 blackboard_read，反复检索形态
  存在（inline vs blackboard 通道 A/B 待验，见 §7-7）。
- 结论：黑板生命周期需要换轴到 conversation，并独立于上下文压缩维护
  「总览 + 可回查」能力；两端都坏——不折叠则无整体性记录（模型自寻），
  折叠但槽位空/指针死则更糟（总览空洞）。

## 1. 用户裁决（2026-09-03，登记为设计输入）

- **D1 生命周期轴 = 对话**：一个对话一个黑板（ACP session 跨多 prompt；
  CLI 单 run = 单对话）。
- **D2 黑板 live 面 = 活跃工作集 + 结构化折叠标注**：折叠 = 先归档全量 →
  不活跃历史降级为标注；阈值放宽但不无界。
- **D3 折叠触发与上下文压缩解耦**：不共享触发器；共享「归档 + 标注 + 指针」
  机制。
- **D4 压缩五段槽保留字段、空槽统一渲染「（无）」**：只压缩真实存在的内容，
  不补语义来源、不编造目的/计划。
- **D5 折叠触发草案**：活跃工作集 + 过往内容 ≥ 黑板窗口 70% 时对过往折叠
  一次，复用既有压缩机制；具体数值待校准（本稿按草案登记，不冻结）。
- **D6 黑板窗口有必要放宽**（相对上下文压缩尺度），但必须先定义窗口并设界；
  放宽依据 = PULL-only + 渲染 cap，而非模型上下文。

## 1a. v0.2–v0.4 设计输入（2026-09-03 续，登记）

- **E1 候选主线 = 渲染折叠（方案 B）**：不删除、不重写黑板存储记录；折叠只
  发生在 blackboard_read 渲染面，机械消费方（实体锚点/写门/action 板/白名单）
  读存储结构、不经过渲染，零影响。
- **E2 折叠键 = 域 → 轮数**：域是写时机械盖章且模型已可见的参考（temporal
  PULL、failure_agg 段标注），替代 v0.1「活跃/过往」按分区判定规则。
- **E3 展开交互**：早期内容默认折叠为域段标注；模型需要时按「域 + 单轮/轮数
  范围」点开，代价最多一轮动作（PULL 哲学不变）。
- **E4 触发 = 明确字符阈值 + 占比**：live 内容到达阈值 T 后，默认渲染只展开
  近期占比（草案约 20%）+ 当前域段 + 最近 K 轮，更早内容折叠为标注；数值待
  校准（见 §9.5）。
- **E5 主线确认 = 方案 B（v0.3）**：黑板彻底不做存储压缩，只做渲染折叠；
  方案 A 冻结为对比档案，不再推进。
- **E6 会话疲劳度 = 黑板 live 字符累积**（相对窗口 W）：单调、机械可计，
  用于明确判断何时建议换对话；软门非强制；取代/扩展
  FUS-SESSION-CONTEXT-MONITOR 的压缩次数度量（BACKLOG 6d pending 未实施）。
- **E7 折叠/存档/删除三语义分离**：折叠 = 渲染投影零损失；存档 = 无损打包
  保留（gzip 草案）；删除 = 真删（retention/用户显式）。「归档瘦身（只留
  最近 N 轮全文）」属半删除语义，仅作独立待裁决项。
- **E8 盖章选型 = 结构化字段**：各记录写时盖 (round, domain)，serde default
  兼容；exec 行结构化为带章行；否决并行索引。
- **E9 疲劳提醒形态 = 用户侧**：机械追加在输出最后，弹给用户、不进入模型
  上下文、不扰乱模型；由用户自行决定是否换对话。
- **E10 存档形态 = 纯打包**：黑板与对话存档合成单一 gzip 压缩包，原子写 +
  digest；不做任何压缩/瘦身/内容变换；重载多等片刻换取干净；范围 = 改存档
  机制本身。
- **E11 体验项暂缓（不阻断）**：归档瘦身、存档体积达到阈值后的用户提醒；
  纯文本安全裕度高，后续按体验排期。
- v0.5 裁定（R1–R6）见 §12：本组开放问题全部收口。
- **E12 软上限不强保（v0.8）**：W 为建议寿命，超出后系统不强制、不拦截、
  不降级，也不额外做弱保软；超出后果由使用者自行负责；90% 用户侧事实
  提示即系统给出的全部（维持 E9）。

> 说明：§2–§5 保留为方案 A（v0.1 存储折叠）全文，自 v0.3 起冻结为对比档案；
> 方案 B（v0.2/v0.3 渲染折叠）见 §9，v0.3 补充见 §10。定稿前以用户裁决为准。

## 2. 黑板窗口定义（草案）

- 窗口 W = 黑板 **live 内容**（非归档）字符预算，按字符确定性计量（沿用
  chars/2 的 token 估算口径，供事件/恢复预检使用）。
- W 不是模型上下文预算：黑板常驻零注入，只有 PULL 读取结果进上下文。因此
  W 的标尺 = ① 全量 PULL 读取成本上界（各分区渲染 cap 之和应显著小于单轮
  注入预算）；② conversation sidecar 每 prompt 序列化/恢复成本；③ retention
  与磁盘纪律。
- 草案默认：W = 256K 字符（≈128K tokens 估算量级）；活跃预算 ≤ W/4；折叠
  目标 ≤ W/2（70% 触发 → 50% 滞回止）。数值待校准，冻结前不实施。
  （注：本节属 v0.1 方案 A 语境；现行 W/T 数值以 v0.7 §11.1 为准：
  W=10MiB 存储字节 / T=64K 字符。）
- **渲染侧独立 cap**：放宽存储不放开单次 read 渲染。exec（50/4K）、actions
  （10 条）、retrieval（8K×条目/32K 段）既有 cap 沿用；`edits` 与
  `tool_actions` 渲染现无硬上限，换 conversation 轴后必须补 cap（定稿项）。

## 3. 活跃工作集定义（Active Working Set，草案）

判定原则：**机械、零语义**——按「恒驻面 + 每分区最近尾 + 被当前状态引用」
三规则，不做语义判断。

### 3.1 恒驻不折叠面

- gate_log（审计链）；
- 白名单；
- 会话锚点（若建：首条用户消息 + 最近用户消息的机械截断副本，零语义；
  待定项见 §7-3）；
- action board 的 pending order 与当前 delivery 状态；
- 折叠标注本身与归档指针（标注是 live 面常驻成员）。

### 3.2 每分区最近尾（沿用既有渲染 cap 同源口径，草案值）

| 分区 | 活跃 = 最近尾 | past 折叠去向 |
|---|---|---|
| exec | 最近 50 条 / 4K 字符 | 计数 + 时间范围 + 归档指针 |
| actions 结果板 | 最近 10 条 receipt | 计数 + 指针（receipt_id 点读跨归档，既有能力） |
| edits | Top-40（路径槽语义） | 计数 + Top-N 路径 + 指针 |
| tool_actions | 最近 40 条（定稿前可调） | 按类别计数 + 指针 |
| failure_agg | 未解决/最近活跃目标行 | 已归档行折叠为计数 + 指针 |
| retrieval（internal/external） | 当前 activation 未 close 结果 | 随 activation 生命周期归档（现状） |
| entities | 最近引用 ≤200 条的精确值（hash/size/mtime） | 标注「已归档，写前需重读刷新」；机械写门对归档实体降级为要求 read_file 刷新，不 deny、不放行 |
| dep_graph | run 内 live-only（既有边界） | 不折叠、不持久化 |

### 3.3 被引用行

被当前订单/会话目标/折叠标注点名的行（receipt_id、实体 id、文件路径）恒视为
活跃，直到引用解除。其余皆为 past，折叠仅作用于 past。

## 4. 折叠触发与执行（草案，70% + 复用）

- 触发点：prompt/run 结束与 loop-top 安全间隙（写操作完成、不打断批次、
  不插入模型轮中间）。
- 计量：`used = chars(active) + chars(past)`（live 内容，字符口径）。
- 触发条件：`used ≥ 70% × W` 且 `used − active ≥ min_foldable`
  （草案 16K 字符，防无谓折叠）。
- 折叠序列（原子、机械、零模型）：
  1. 归档全量快照（复用 epoch.rs 原子写/自检/回退加载纪律；身份改用
     conversation/fold 时间戳单调编号，见 §6）；
  2. 生成每分区折叠标注（计数/时间范围/路径 Top-N/失败行/归档指针；
     复用 summary.rs 截断与 failure_agg 行渲染）；
  3. 重写 live 面 = 活跃工作集 + 标注；
  4. 折叠后使用率降至 ≤ 50% × W 即止（滞回，防临界抖动）。
- 复用清单：epoch 归档原子写/自检/`latest_epoch_snapshot` 回退/retention
  保留最高编号/claim 单调占号、summary.rs 机械槽与截断口径、receipt 点读
  跨归档、digest 绑定。不调用模型；不建第二套摘要。
- 事件面：黑板折叠事件（草案名 `blackboard_fold`，payload = 折叠身份/前后
  用量/折叠分区计数/归档路径/digest），schema/verifier/fixtures 先行；或
  扩展既有 `epoch_archive_write_failed` 事件模式，定稿前二选一（§7-4）。

## 5. 空槽「（无）」契约

- 五段槽字段保留；空槽统一渲染「（无）」，取代现状「（未设置）」/空串混用；
  非空槽只放真实内容。
- 语义注记：目的/计划恒空不是缺陷——最近用户消息保留在压缩尾部（既有设计
  明确「不设用户原问题槽」），压缩不再重复承载目的；「整体性记录」职责交给
  黑板折叠标注（§3/§4），不是五段槽。
- 影响面：summary.rs 槽渲染与 marker 文本、schema（若枚举槽位文案）、
  verifier/测试同步；存档补全段逻辑不变。

## 6. 接线影响清单（实施前逐项定稿）

- epoch.rs：生产接线随 R4 同批退役（with_plan/rotate/claim 仅 `--plan` 与
  测试域）；会话存档身份 = 会话 id + 时间戳（§11.3 单包），不保留独立
  plan-epoch 快照编号体系。
- controller / ACP：conversation sidecar 持有黑板 live 视图；每 prompt
  续载而非重建；检索分区从独立 activation sidecar 并入/对齐会话黑板侧车。
- blackboard_read：生产面 `epoch` 参数退役（R4）；历史会话经存档包整体
  恢复后即 live，无跨快照参数需求；P2-11 增量头/分区游标在折叠态下按视图
  推进（折叠 = 分区可见内容变化）。
- marker：`plan_epoch` 字段语义收口为 conversation/fold id（或退役改名，
  定稿前裁决）。
- failure_agg / temporal：作用域轴 run-relative → conversation-relative

## 9. 方案 B：域→轮数渲染折叠（v0.2–v0.5；v0.3 定主线，v0.5 裁定收口）

### 9.1 核心语义

- 黑板存储 = 会话内全量记录（不因折叠删除/重写）；折叠是纯渲染语义：
  blackboard_read 默认视图按「域 → 轮数」折叠，折叠内容在存储中仍然
  存在且可被精确点开。
- 折叠键 = (domain, round)：每条记录写入时机械盖 (round, domain) 章
  （round = 会话内逻辑模型轮；domain = 写时所属 LIF 域，权威 = 域机器写时
  盖章）。无域机器/单域会话统一回退域值 `normal`（单段 normal，折叠退化为
  纯轮数区间，无分支）；旧无章行（round=0/domain=None）归独立 `pre-stamp`
  段，只给计数 + 时间范围标注（R1，§12）。

### 9.2 默认渲染规则（折叠态）

1. 展开子集 = 当前域段（当前轮所在域连续段）+ 最近 K 轮（K=10 定档，
   §11.1）；两者重叠按并集；各分区既有渲染 cap 为硬上限。
2. 更早内容按域段聚合为标注行：`[域段 normal r1–r30 · N 条 · 摘要预览]`
   （每段一条；域来回切换时每段独立标注，展开参数可跨段指定轮数范围）。
3. 标注行内容 = 段内计数、首末轮、Top-N 路径/失败行（复用 failure_agg 行
   渲染与路径截断口径），保证模型能判断该不该展开、展开哪段。
4. 触发折叠态：分区 live 字符 ≥ 分区阈值 T（64K 字符）或对话黑板 live
   合计 ≥ W（v0.7 定档 10MiB 存储字节，§11.1）。未达阈值 = 全量渲染
   现状不变。

### 9.3 展开契约（blackboard_read 扩展，R2 定名）

- 新增可选参数：`domain`（str）+ `round_from`/`round_to`（u64，含边界；
  相等 = 单轮），与既有 `section` 组合；展开响应沿用各分区既有渲染 cap
  （exec 4K / actions 10 条 / 条目 8K 等），超限截断 + 指针。
- 组合守卫（fail loud）：`domain` 与 `round_*` 必须同时给出，缺任一显式
  报错；与 `receipt_id`、`since` 互斥（显式报错，不静默忽略）；`pre-stamp`
  段无 round，只能用 `since` 或 `receipt_id` 展开。
- 默认视图（无展开参数）= §9.2 折叠态；显式展开 = 折叠态 + 目标段行。
- 与 P2-11 增量头/游标交互：折叠只改变可见投影，不改变存储版本；读取游标
  语义按「折叠态视图」推进（定稿项）。

### 9.4 留痕与机械面

- 写入侧：edits / tool_actions / exec / actions receipts / failure_agg /
  retrieval 行补 (round, domain) 盖章——v0.3 定**结构化字段**（E8）：
  exec 行结构化为 `ExecEntry { text, round, domain, ts }`，serde default
  向后兼容；否决并行索引（行数组与索引双写漂移面大，违反单一来源纪律）。
  域亦可在渲染时经 temporal 段表推导，但写时盖章与 failure_agg 先例一致，
  统一采用写时盖章；retrieval 行按派发轮所属域盖章（R1）。
- 机械消费方不经渲染，不受折叠影响；entities 精确值恒可读（若要控制渲染
  体积，entities 分区渲染 cap 单列：Top-200 + 8K 字符上限，超限计数 +
  指针；不进域折叠，R1）。
- 不做存储归档/重写；live 侧车随对话增长登记为边界（§7-8），后续如需
  归档，复用同一 (domain, round) 索引把旧段 payload 移入归档目录，模型面
  契约不变。

### 9.5 触发数值（v0.4 定档）

- 定档见 §11.1（v0.7：T=64K 字符 / W=10MiB 存储字节 / K=10 / 展开下限
  20%）。v0.2–v0.6 草案值（T=32K / W=256K–512K 字符）已被 v0.7 取代。
- 校准输入（不再阻断；转为真实使用数据到位后再调参的体验项）：对话级 live
  内容增长曲线、分区大小分布、折叠前后 blackboard_read 响应 token 分布与
  展开调用频率。

### 9.6 方案 B 相对方案 A 的取舍

> v0.3：B 已定为主线，A 冻结（本小节保留取舍记录）。

- 优势：无破坏性状态机（无归档重写/无 active-past 判定）、机械面零影响、
  恢复/崩溃语义不变、实现面窄（盖章 + 渲染折叠 + 展开参数）。
- 代价：存储无界（对话级 sidecar/磁盘增长，由 retention 与后续归档缓解）；
  每次折叠态读取需要按段聚合（渲染计算成本，需有界）。

## 10. v0.3 补充：会话疲劳度 / 存档语义 / 盖章选型

### 10.1 会话疲劳度（草案，软门）

- 度量 = 黑板 live 侧车紧凑 JSON 字节 / W（v0.7 定 W=10MiB，§11.1）。
  单调、机械、可复核；存储字节是真实资源度量（侧车序列化/恢复/磁盘），
  且随轮数与压缩轮次单调增长（疲劳 = 工作总量代理，非复杂度模型，§13.2）。
- 档位草案：<50% 正常；50–70% 轮末机械提醒一次（建议收束当前线索/核对
  遗留）；70–90% 建议准备换对话（新对话 = 新黑板，旧黑板随会话归档）；
  ≥90% 明确提示接近黑板寿命上限，继续会增加轮间复杂度与存档压力。
- 门槛（B3 复审 v0.9 裁决）：50/70/90 三档**只按水位判定，无压缩轮数
  门槛**（W=10 MiB 对纯文本已足够宽松，压缩次数不参与）；70% 建议换对话
  在越过 70% 时直接给出，90% 接近上限提示始终给出（事实层，措辞软、由
  用户决定）。原 v0.6/v0.8「70% ≥2 压缩」门槛撤销。
- 单次投递（B3 复审 v0.9 裁决）：每次运行至多一条，取达到的最高未提醒档；
  同一次判定内把已越线的未提醒档全部落档（巨幅跳跃只报最高档，低档不
  滞留到后续 run 倒序补发）。
- 形态（v0.4 E9 收口）：用户侧提醒——机械追加在模型输出最后、弹给用户，
  不写入模型可见消息、不进模型上下文；session 分区可另带水位行作信息面
  （如需），但提醒通道在用户侧。不占工具轮、不强制、不打断；定稿时收口
  FUS-SESSION-CONTEXT-MONITOR（BACKLOG 6d）度量定义。
- 与渲染折叠解耦：折叠按 T/W 阈值改善默认视图；疲劳度按同一 W 的水位给出
  建议，两者可共用 W 但各自独立生效。

### 10.2 折叠 / 存档 / 删除三语义

- 折叠（render fold）：默认视图压缩，存储零损失，任何记录仍可展开回查。
- 存档（archive）：无损保留 + 自动打包（草案 gzip，纯文本/JSON 典型
  5–15× 压缩比），会话结束触发；成本 = 磁盘 + 压缩时间，可回查。
- 删除（delete）：真删，不可回查；仅 retention 清理或用户显式触发；与
  存档不是程度差异，是语义差异。

### 10.3 存档压力评估

- 黑板存的是结构化行与指针；大载荷（终端全文/web 页/检索全文）不进黑板，
  走 session/terminal、retrieval-results 与 journal（已有 retention）——
  黑板本身的体积大头不在载荷而在行数。
- 渲染折叠保留全量行 → 会话级 sidecar 行数单调增长；纯文本 + gzip 打包
  成本低，会话级规模可接受（E7）。
- 「归档瘦身（只留最近数轮全文、旧段只留标注）」= 半删除，违背「所有内容
  可回查」承诺；仅作为磁盘压力真实出现后的可选独立项（单独裁决），不做默认。

### 10.4 盖章选型结论（E8）

- 结构化字段：单写者加两个可选字段（round/domain，serde default），写入点
  一次落章；渲染/归档/标注聚合直接消费；无同步不变量。
- 并行索引否决理由：行数组与索引需双写并维护隐式一致（顺序/追加/恢复/
  序列化同步），漂移面大；exec 行结构化的迁移成本最低。
- 无章旧行回退：round=0/domain=None → 归为 pre-stamp 段，渲染为首段标注。

## 11. 定档参数与存档形态（v0.4–v0.7）

### 11.1 定档参数（直觉定档，可 env 覆盖）

| 参数 | 值 | 直觉依据 |
|---|---|---|
| W（对话黑板 live 预算） | 10 MiB（紧凑 JSON 字节） | 存储/恢复成本预算 + 会话寿命软上限（PULL-only + 渲染 cap，黑板不占常驻上下文）；初始默认按直觉量级，论证见 §13，待真实长会话遥测复核 |
| T（分区折叠阈值） | 64K 字符/分区 | 单分区 live 超 T 后该分区默认视图进入折叠态；默认渲染仍远小于单轮注入预算 |
| K（最近轮） | 10 轮 | 已确认口径；覆盖一个近期工作窗口 |
| 展开下限占比 | 20% | 最近 K 轮行数不足总行数 20% 时放宽到最近 20% 行 |
| 疲劳提醒档 | 50% / 70% / 90% × W | 每档越线提醒一次；50 建议收束、70 建议准备换对话、90 接近寿命上限 |

- 默认展开 = 当前域段 ∪ 最近 K 轮 ∪ 最近 20% 行（并集）；单域/无域会话回退
  为纯轮数折叠。各分区既有渲染 cap 仍为硬上限（exec 50 条/4K、actions 10 条
  等），超限截断 + 指针。
- **W 计量对象（v0.7）**：整份黑板 live 侧车的紧凑序列化 JSON 字节（含
  检索分区/entities 当前内容与折叠标注）；它是侧车序列化、恢复、磁盘的
  真实度量。增长主体是域折叠记录分区；检索/entities 另有独立 cap 与
  生命周期，不会单独失控。
- **口径沿革**：v0.2 草案 W=256K 字符、v0.4–v0.6 定 W=512K 字符（≈256K
  token）均被 v0.7 否决/取代——字符口径低估了真实大任务在多次压缩后的
  生存需求；存储字节口径直接绑定资源，语义更干净。T（渲染）仍按字符：
  渲染成本与存储成本分列，互不换算。
- **疲劳门槛（B3 复审 v0.9）**：50/70/90 三档只按水位判定，无压缩轮数
  门槛；单次只投最高未提醒档并连同已越线低档一并落档（跳档不刷屏、
  低档不滞留补发）。
- min_foldable 等 v0.1 存储折叠参数不再适用（方案 B 无存储折叠）。
- 落地形态：编译期常量 + env 覆盖（沿用 ORZ_* 既有模式，如
  `ORZ_BLACKBOARD_LIVE_BUDGET_BYTES`（默认 10 MiB）/
  `ORZ_BLACKBOARD_FOLD_PARTITION_CHARS`（默认 64K）/
  `ORZ_BLACKBOARD_FOLD_TAIL_ROUNDS`（默认 10）），真实使用数据到位后
  可只调参不改语义。

### 11.2 疲劳提醒形态（E9）

- 弹给用户、机械追加在模型输出最后；不写入模型可见消息、不进模型上下文、
  不占工具轮；措辞给事实不给指令（如「黑板使用 72%，接近建议换对话水位」）。
- 每档越线提醒一次（50/70/90），用户忽略不重复；由用户自行决定是否换对话。
  单次运行至多一条：取达到的最高未提醒档，已越线的未提醒低档同时落档
  （巨幅跳跃只报最高档，后续 run 不再倒序补发低档——B3 复审 v0.9 裁决）。
- 无独立 UI 通道的宿主面（如纯 CLI 单跑）可降级为 run 结束时的 stderr/
  日志附言，不注入模型消息。
- 门槛（B3 复审 v0.9）：三档只按水位判定，无压缩轮数门槛——70% 越过即
  给建议、90% 提示始终给出（接近预算上限是事实，不因任何理由隐瞒）。
- 绝对水位（v0.7，W=10MiB）：50/70/90% ≈ 5 / 7 / 9 MiB。

### 11.3 存档形态（E10）

- 会话关闭/归档时：conversation sidecar + 黑板 live sidecar（含折叠标注）
  + 会话元数据（session id/时间/疲劳水位）合成**单一 gzip 压缩包**
  （`.gsa/archives/<session8>.json.gz`——沿用 conversations sidecar 的
  8 字符前缀约定，B3 复审登记口径；原草案字面 `<session>` 按此执行），
  原子写 + digest。
- 只打包、不压缩内容：不做行裁剪、不做语义/结构化变换；恢复 = 解包读回
  （等待时间换干净）；原 sidecar 保留至 retention 清扫（包是附加存档，
  不是删除动作）。
- 范围声明：本主题对存档机制的改动止于「打成一个包」；run journal /
  检索产物等既有存储不动。

### 11.4 体验项暂缓（E11，登记不排期）

- 归档瘦身（旧段换标注、半删除）与存档体积阈值用户提醒：纯文本安全裕度高，
  待存档体积在真实使用中形成数据后再按体验排期。

## 12. 裁定收口（v0.5，2026-09-03 用户授权裁定）

### R1 域缺失 / 单域 / 旧行回退

- 域权威 = LIF/temporal 域机器写时盖章（failure_agg 先例）；机器未启用或
  单域会话统一回退域值 `normal`——写入即盖 normal，单域会话 = 单段，
  折叠退化为纯轮数区间，无分支逻辑。
- 旧无章行（round=0/domain=None）归独立 `pre-stamp` 段：标注 = 计数 +
  时间范围，不并入 normal；只能按 `since`/`receipt_id` 展开，不能按域/轮。
- retrieval 行按派发轮所属域盖章；entities 不进域折叠（渲染 cap 单列：
  Top-200 + 8K 字符上限，超限计数 + 指针）。

### R2 blackboard_read 展开参数

- 定名：`domain`（str）+ `round_from`/`round_to`（u64，含边界；相等 = 单轮）。
- 组合守卫（fail loud）：domain 与 round_* 必须同时给出；与 `receipt_id`、
  `since` 互斥，冲突显式报错；pre-stamp 段用 `since`/`receipt_id`。
- 展开响应沿用各分区渲染 cap，超限截断 + 指针；默认视图 = §9.2 折叠态。

### R3 折叠 / 存档事件

- 不新增 `blackboard_fold`：渲染折叠零持久化、逐读事件只会产生噪声。
- 新增 v0.2 事件 `session_archive`（每条会话存档一次：archive_id / path /
  digest / status=completed|failed / attempts / fatigue_pct），

## 13. 评估复核：复杂度与压缩的关系（v0.8）

### 13.1 命题拆解

- **事实**：上下文压缩把模型可见上下文压回窗口（机制目的，成立）。
- **直觉 A（未证实）**：压缩后任务/状态复杂度增长不快 → 会话应能撑过大量
  压缩。评估：方案 B 下黑板存储单调增长、压缩不重置黑板；每多一次压缩，
  旧工作的模型可见性更间接（marker/折叠标注/存档），找回旧工作的摩擦随
  轮数与域段数近似线性上升。因此「复杂度随压缩重置或慢增长」在机制上
  不成立，不能作为 W 的论证依据。
- **直觉 B（未证实）**：大任务压缩频繁。跑分语料中频繁的是 ledger fold
  而非五段压缩（context_compressed 全语料仅 2 次）；ACP 长会话的
  session_end 压缩可能频繁，但本仓库无多 prompt 长会话语料，无法证实。

### 13.2 结论

- W=10MiB 保留为默认，论证依据改为：① 每 prompt 侧车序列化/恢复成本预算
  （10MiB 量级预估几十–几百 ms，S4 实测）；② PULL-only + 渲染 cap 使黑板
  存储不占常驻上下文，可给宽松寿命；③ 会话归档是一次性成本，可接受。
  不作「复杂度」论断。
- 疲劳字节尺 = 工作总量代理（单调），不是复杂度模型；疲劳提醒只按水位
  给档，不引入压缩轮数门槛（B3 复审 v0.9 裁决——压缩次数不参与提醒判定）。

### 13.3 遥测与复核路径（数据到位后调 W/档位）

- 每会话记录：live 侧车字节/prompt、恢复与序列化延迟、折叠态
  blackboard_read 次数与展开调用频率、域段数、context_compressed 次数
  （会话内）、会话终点水位。
- 复核判据：真实长会话中 70/90% 档触发率与用户换对话意愿对照；恢复延迟
  是否进入不可接受区间；据此调 W 与档位（env 覆盖，不改语义）。

### 13.4 软上限语义（E12）

- 超出 W 不强制、不拦截、不降级、无额外弱保软；90% 用户侧事实提示即全部。
- 若未来产品化需要硬上限，必须回到存储折叠（方案 A 语义），本设计默认不
  提供。
