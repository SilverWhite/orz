## 0. 共识基线（2026-08-30 用户确认无异议）

1. **文件工具 = 透镜代数**：`read_file` 返回 view=(hash, size, window)；
   `search_replace` 为 put，锚点守卫机械强制 GetPut 律（put∘get = id）。
2. **状态 = 内容寻址**：文件/进程/环境实体以 hash 为身份；状态比较 = 哈希相等，
   模型验证编辑生效是 O(1) 比较而非重读。
3. **可见面 = 类型化文法 + 监视自动机**：工具是带类型签名的函数；结果永远是固定
   类型的值（成功=摘要+指针，失败=code+reason）；机械门（ACAF/锚点/预算/候选
   计数/并发=1）构成监视自动机，模型只看到合法迁移。
4. **工具内部 = 数学算法**：web/grep/压缩摘要的结果选择用子模/MMR（相关性 −
   λ×多样性）；复读哨兵从标定常数转为有界内存、阈值以上确定性检测的流式算法。
5. **设计纪律**：性质由结构保证（定理级），不依赖模型版本标定数据；对模型极简
    ≠ 对框架极简；新增机制一律视为债务，须证明必要性。

## 1. 本稿新增讨论的问题

上一稿的四个结构都发生在"工具内部"——每个工具是什么、结果怎么选。本稿讨论两个
更大的问题：

- **Q1**：能否改变工具的**使用定义**（工具意味着什么）或**调用方式**（模型如何
  发起）？
- **Q2**：能否把机械层建成"结合计算机语言的数学计算体"，而不是接口调用的集合？
- **Q3**（2026-08-30 追加）：多步分解与跨轮记忆的底层是时间事件与逻辑——能否把
  这一部分也抽入机械层：每一步以 spike 记录，显式存下时间性的数学特征供模型使用？

## 2. 模型最熟悉的确定性计算是什么

论点：模型训练分布里最密集、最不需要分解、可直接确定性计算的是**确定性文本/
结构变换**：

- 字符串精确/正则搜索与替换（grep / sed / awk 形态）；
- 结构化查询（JSON Path / jq / XPath 形态）；
- 哈希与校验（git、sha256 形态）；
- diff/patch、排序、去重、计数；
- 类型化函数应用与组合（代码调用形态）。

特征：操作原子、结果确定、无需模型管理中间状态。模型描述"什么"，机器计算"怎样"。

分界线（本稿核心判断）：**需要多步分解的事（跟踪状态、编排流程、跨轮记忆）恰是
模型最弱处；不需要分解的确定性变换恰是模型最熟处。"顺手"就是尽可能把模型推到
分界线右边。** 历史证据同向：2.3–2.9 往返/动作的失败形态 = 模型被迫做项目管理的
仪式；PUSH→PULL、prompt 全空、实体状态进黑板 = 把"记住"从模型搬到机械层。

## 3. 调用方式：从 RPC 到表达式求值（Q1 一半）

现状：OpenAI 风格 tool_calls = 一次调用一个工具一个往返；模型必须把意图拆成
序列并自行管理状态。

提议（讨论，非定案）：调用方式从"调用远端函数"改为"提交表达式、机械层归约"。

- 模型提交一个小型类型化表达式的项（term），如 `pipe(read(path), grep(pattern),
  head(20))`，或带 let 的 JSON AST；
- 机械层 = 求值器：纯子项（字符串/正则/哈希/JSON 查询）确定性归约；效应子项
  （run / replace / web）派发半助理层并过全部硬门；
- 返回 = 表达式的值 + 归约留痕（receipt = reduction trace，与事件面同构）。

收益：组合在同一往返内完成，不必为每一步往返；模型写代码表达式与训练分布同构；
确定性部分零模型参与。

风险（诚实记录）：自定义 DSL 的"熟悉度"未必高于 tool_calls 本身——模型训练数据
两者都有，tool_calls 轨迹同样密集。折中档：**顶层保留 tool_calls 形态，但每个
工具的契约成为确定性函数，并允许一层组合（批量/管线）**。激进档才引入表达式
求值。

## 4. 使用定义：从"命令"到"变换"（Q1 另一半）

改变使用定义 = 每个工具不再是"执行一个动作"，而是"计算一个确定性函数"：

| 工具 | 命令语义（现状） | 变换语义（提议） |
|---|---|---|
| grep | 搜索 | `filter(lines, pattern)` 纯函数 |
| read_file | 读文件 | `view(path) → (hash, size, window)` |
| search_replace | 替换 | `put(path, anchor, new) → 结果`（透镜律） |
| web_search | 搜索网页 | `query(q) → ranked subset`（MMR 子模选择） |
| blackboard_read | 读板块 | `query(partition, selector)` 结构化查询 |

机械层对每个变换给出类型签名；模型看到的不是八种自由格式，而是一本同构的函数库。

## 5. 机械层 = 数学计算体（Q2，综合形态）

把 §3/§4 合起来：机械层不再是一组 Rust 接口 + 调用协议，而是一个**类型化项重写
系统（term-rewriting system）**：

- **对象**：文件/进程/环境/检索结果/黑板分区，全部内容寻址；
- **态射**：工具即类型化函数；组合即调用方式；
- **求值器**：机械层内核——纯部分确定性归约，效应部分过监视自动机；
- **监视自动机**：ACAF/锚点/预算/候选计数/并发=1 构成迁移合法性；
- **留痕**：每次归约的 trace 即事件面/journal 语义（与现有事件链同构）。

"AI 本身也是数学"的落实：模型是 token→token 的函数；与它对接的最自然界面是
**另一个函数集合（库）**，而不是协议。机械层以"函数库 + 求值器"形态存在，模型
以调用者身份使用——两端共享同一个数学语言（函数应用/组合），"顺手"成为结构性质
而非标定结果。

## 8. 时间与逻辑的抽取：spike 记录与时间特征面（2026-08-30 追加讨论）

### 8.1 弱项再定位：弱的是簿记，不是决策

"多步分解与跨轮记忆是最弱"需要修正：模型的弱项不是**分解决策**本身（plan 门时代
模型仍负责选择步骤），而是**跨轮维持分解结构、重建历史、跟踪时间**——这是簿记。
可抽出的正是簿记（时间与逻辑状态），不是决策（下一步做什么仍由模型选择，机械层
不给建议的裁决不变）。

### 8.2 底层 = 时间事件 + 逻辑

用户判断：两个弱项的底层是时间事件与逻辑。落法：

- **时间 = spike 记录**：现有事件 journal 已是"每一步一条带 wall_ms 的结构化
  事件"——即离散时间事件流（spike train）。新增的是特征化：
  - 机械层维护定长特征向量 F(t) = φ(事件流[0..t])：各工具类型计数与 EWMA 延迟、
    相邻模型轮间隔（ISI）、墙钟/预算/轮数使用率、最近成功动作距今时长
    （progress recency）、相位标签、延迟趋势（web 是否爬升）；
  - 特征由 run 自身事件**确定性计算**，不依赖外部数据（"数据不可靠"顾虑不适用）；
  - 暴露方式：黑板 `temporal` 分区按需点读 + 决策相关点注入（预算临近、长工具
    调用前、终答前与机械审计报告同轮）。
- **逻辑 = 依赖图 + 时序逻辑监视**：
  - 依赖图 G：动作 + 实体 + 锚点构成有向图（read→write 锚点依赖、工具→实体变更
    边），机械维护、可查询——模型不必重建"我改过什么、谁依赖谁"；
  - 时序逻辑：run 性质 = 事件流上的 LTL 公式（"search_replace 前必有锚点匹配的
    read"、"submit 后无工具"、"有终止事件"），机械层为运行时验证监视器——现有
    事件链校验正是雏形，提升为一等公民；
  - 违例 = 事实（审计报告语），不给建议。

### 8.3 时间从约束变信息

现状时间只以"预算/超时"形态出现——失败触发器。本节把时间变为**正向信息通道**：
模型用时间特征自我定速、感知漂移、决定优先级，而不只是躲被杀。历史组件都是半成品
时间机制，本节能统一成一面：stall 看门狗的间隔检测、ledger fold 的
`view_estimate_after`、机械审计的覆盖写（时间作为互补维度保留、不覆盖）、压缩的
"旧前缀 + 新尾"。

### 8.4 边界与风险

- 特征集必须由**决策点反推**（每个特征对应模型一个真实决策：要不要继续等？要不要
  换查询？要不要开始收尾？），不做穷举——否则即噪声（表面充分性纪律的时间版）。
- "spike" 是神经编码隐喻；数学内容是点过程统计 + 时序逻辑，不引入真正的 SNN 编码。
- 抽取的是簿记不是决策；下一步动作仍由模型选择。
- 与"新增机制一律视为债务"的关系：不是新增机制，是把既有事件/校验的产出**特征化
  并上移到模型可见面**；仍须证明每个特征对应一个决策点。

### 8.5 LIF 积分结构做 spike 捕捉（2026-08-30 用户提议）

- **结构**：每通道一个一阶漏积分器 + 阈值 + 复位 + 不应期：
  u[k] = α·u[k-1] + w·x[k]（α = exp(−Δt/τ)）；u ≥ θ → fire（结构化事件）+ 复位
  （整复位或部分复位）；fire 后 Δt_ref 内不再 fire（迟滞/防抖）。
- **数学定位**：这是经典 leaky-bucket / 一阶 IIR 低通（EWMA）+ 阈值事件检测 +
  迟滞；"LIF" 是神经编码的助记，不引入 SNN 语义。同一原语同时产出两类特征：
  连续 potential（压力/新鲜度）与离散 fire（显著时刻）。
- **通道映射**：每信号类型一个通道——工具错误率、复读命中、延迟离群、deny 计数、
  预算消耗率、进度新鲜度等。journal 事件流即输入 spike train；fires = 显著时刻
  （压缩后的离散时间特征），potentials = 模拟压力（连续时间特征）。
- **统一守卫代数**：现有守卫（复读命中门槛、stall 间隔、deny 熔断）全部成为同一
  原语的不同 (通道, w, τ, θ, refractory) 实例——守卫从零散常数收敛为一个带参数的
  统一结构。复读"间隔不重置"对应 leak=0 的特例（纯积分器）。
- **参数纪律**：τ/θ/w 是带语义的设计常量（τ = 决策相关记忆窗口，θ = 构成告警的
  命中数），不是数据标定值——延续"定理非标定"纪律，参数由决策点反推。
- **暴露面**：黑板 `temporal` 分区渲染每通道 (potential, last_fire, τ, θ)；fires
  入事件面（temporal_fire 类事件）；potentials 按需点读。
- **边界**：模拟量渲染需决策相关（量化档或带语义标签），否则模型不会消费；LIF
  只做时间特征捕捉，逻辑侧（依赖图 + LTL 监视）独立保留。
- **基础形态定案倾向（2026-08-30 用户：LIF 本身熟悉、基础形态够用）**：采用事件
  驱动离散 LIF，唯一更新式 u(t) = u(t₀)·exp(−(t−t₀)/τ) + w（事件到达时）；u < θ
  静默，u ≥ θ → fire（复位——整复位或阈值相减按通道语义选定）+ 不应期 Δt_ref。
  时间性由 τ 显式承载，无额外时间窗口机制；无事件时电位自然衰减即"新鲜度/压力"
  连续特征。leak=0 极限即现有复读计数（纯积分器），stall 检测 = 距最近事件时间，
  deny 熔断 = 带泄漏计数——基础形态全覆盖 §8.2 特征清单。
  明确不引入：随机发放、多房室/电导模型、自适应阈值（保持确定性 + "新增机制一律
  视为债务"）。可塑性/学习于 2026-08-30 修订为"生理参数可学习 = 在线自调"（§9.5），
  仍不引入反向传播/标定拟合。

### 8.6 模型依赖的定位（2026-08-30 用户质疑：决策点反推是否仍具模型依赖）

诚实结论：有残差依赖，但可精确定位并压缩到"模型类"粒度，不是"模型版本"粒度。

分层：

1. **计算正确性（零依赖）**：LIF 更新、透镜律、自动机安全、内容寻址——结构定理，
   任何模型成立。
2. **特征值（零依赖）**：通道内容 = 本 run 自身事件的确定性函数（当前延迟、错误
   计数、距最近成功动作时长）——本次运行的现场事实，不是跨 run 标定。
3. **通道集与阈值（类级依赖）**：哪些通道服务给模型、θ 取多少，依赖模型类（会推理
   的 agentic 模型 vs 快速非推理模型）的倾向；类内跨版本稳定。
4. **版本级拟合（禁止）**：按具体版本行为拟合的常量。反例：orientation 阈值 50
   （按 DeepSeek V4 轮次分布推导）——新层不得复制该模式。

阈值边界：θ 上界由架构给定（必须在灾难条件前触发：墙钟耗尽、预算爆、输出预算
烧穿），模型依赖只移动合法区间内的偏好点；选架构边界内的定值即可，不重拟合。

纪律：τ/θ/w 优先从架构边界推导；推不出架构边界时，显式承认类级依赖，做成小型
显式 profile（模型类 → 通道集/θ 偏好），不混入计算层。

### 8.7 离线验证记录（2026-08-30：真实 run 事件流推演）

事件字段 = event_type / timestamp / payload(tool, exit_code, wall_ms, decision)。

通道与参数（基础 LIF 事件驱动式，全部为语义推导常量）：

| 通道 | w | τ | θ | refractory | 语义 |
|---|---|---|---|---|---|
| err | 1 | 180s | 4 | 60s | 4 次工具错误 / 3 分钟窗口 |
| slow | min(5, wall_ms/60s) | 600s | 3 | 60s | 3 次 >60s 工具调用 / 10 分钟窗口 |
| stall | 1 | 600s | 2 | 120s | 2 次 >90s 事件间隔 |
| deny | 1 | 120s | 4 | 60s | 本批 0 触发（全 allow_once） |
| prog | 1 | 180s | — | — | 成功注入，衰减显示，不触发 |

结果：

- 告警稀疏不嘈杂：err 4/31、slow 2/102、stall ≥6/102；触发点语义合理——
  mteb-retrieve 错误压力 3 次触发（593/1009/1086s）、caffe-cifar-10 stall 触发
  （2770s）、largest-eigenval stall 触发（818.8s，墙钟杀于 842s——仅 24s 提前量）。
- 时间渲染（25/50/75/100% 四点）可给出紧凑数字状态，模型面可行。

三个发现（设计约束）：

1. **slow 通道在 S5-1 前 run 上盲**：旧二进制 tool_completed 无 wall_ms（长 run
   max_tool_ms=0）——时间特征层依赖 wall_ms/timestamp 作为一等字段（S5-1 已落，
   现状满足）。
2. **fires 渲染必须按查询时刻截断**（fires ≤ t），不能显示 run 累计数（探针第一版
   曾误导）——temporal 分区渲染语义，写入设计。
3. **wallclock 900s 批（S5-1 前）无 slow 告警积累**：120s web 上限落地后 slow 触发
   转为可观测（dna-insert web_search=120s×2 → fire@910s）。

结论：基础 LIF 结构在真实数据上成立、零标定、O(1)/run；暴露的依赖前置与渲染语义
均属设计细节而非结构缺陷。

### 8.9 动作特征与即时使用：强制模板轮回归（2026-08-30 用户提议）
> 2026-08-30 修订：不引回强制模板轮；fires 出口改为客观语言汇报（见 §9.7）。

方向修正：LIF 特征面从"提取模型自身特征"改为**提取模型动作的特征，并即时使用**。

依据：

- **可观测性**：模型内部状态（思考/意图）是私有的（ADR §5.4.6 reasoning 不进
  journal）；动作（工具调用与结果、时序、成败）是公开、journaled、可验证的。
  机械层只能合法观测动作。
- **接地性**：动作特征是"事实"（工具失败、45s 延迟、连续 deny），不是对模型状态
  的猜测——符合机械层"只给事实不给建议"。
- **即时使用**：特征在运行中直接驱动机械响应（orientation 触发、temporal 分区
  渲染、守卫告警），不是事后分析。

闭环形态：动作流 → LIF 特征库（potentials + fires）→ fires 触发机械响应
（强制模板轮探针等）→ 探针输出本身是动作 → 回灌特征库。

强制模板轮回归的条件（使"实际有用"成立）：

1. 触发 = LIF 动作特征 fire（证据驱动，非固定轮）；round50 仅作长任务兜底。
2. 形态沿用 §9.2 修复：简短、不禁工具、回答被消费、不误判终答。
3. 探针输出是特征：模型自述下一步 → 与后续实际动作做一致性校验（stated vs
   done），不一致本身是高价值特征——连接逻辑侧（依赖图）。

通道组合（降噪）：单通道 fire 有噪声（err 爆发可能是正常调试）。二阶组合：
"stuck"通道 = err 压力 ∧ 进度新鲜度低（一阶通道输出作为二阶输入电流）；决策特征
由一阶动作特征组合而成。

分工边界：动作特征驱动行为/控制层（问询/介入）；模型输出特征留在 transport
健康层（复读/stall 守护输出预算）——不合并。

### 8.10 二阶通道的输入机制：一阶电位作为输入电流（2026-08-30 澄清）

"一阶通道的输出作为二阶输入电流"的含义：

- 一阶通道的输出 = **膜电位 u(t)**（连续值），不是 fire 事件。
- 二阶通道的输入电流 I(t) = 一阶电位（或其归一化）的函数；二阶通道以同一 LIF
  方程积分 I(t)，仍只有自身 (w, τ, θ, refractory)。

无新参数的推荐形式（归一化乘积）：

- 归一化证据分数 e_A = u_A/θ_A（无量纲、≈[0,1]，含义 = 该通道距触发还有多远）。
- I_stuck(t) = w·(u_err/θ_err)·(1 − u_prog)；u_prog 天然 ∈[0,1]（成功置 1、
  按 τ 衰减）。
- 语义：错误压力高 ∧ 近期无成功 → I 大；正常调试（有成功穿插）→ (1−u_prog)≈0
  → I≈0。二阶 τ 决定"卡住条件须持续多久"，θ 决定累计证据门槛，refractory 决定
  干预间距。

数值示例：3 错误/2 分钟且无成功 → u_err≈3/4=0.75、u_prog≈0.1 → I≈0.68w；持续
约 τ_stuck 后 u_stuck 累计过 θ → fire。随后一次成功 → u_prog→1 → I→0，u_stuck
泄漏衰减，不 fire。

事件驱动实现（O(1)/事件）：每个事件/查询时刻，用当前 u_err/u_prog 求 I(t)，再按
u_stuck ← u_stuck·exp(−Δt/τ) + I·Δt 更新；确定性、无额外状态。

唯一会引入新参数的地方：若用硬 AND（u_err ≥ a 且 u_prog ≤ b）需次阈值常量 a/b
——违背"最简单形态"倾向，推荐归一化乘积规避。

**用户确认（2026-08-30）**：二阶 = 决策级联合证据降噪（与 τ 的时间平滑互补，
滤单条件假阳而非瞬时毛刺）；不引入新超参，采用归一化乘积。代价是灵敏度降低
（单信号升高不触发）——因模板轮每次花费一个模型轮，干预标准应为双信号确认；
round50 兜底通道覆盖长任务周期检查，漏检风险被托底。结构收益：一阶通道 = 可复用
特征原语，二阶通道 = 决策面，直接映射机械动作；新增干预只加二阶组合，不动一阶层。

### 8.11 总体形态定稿（2026-08-30 用户综合）

三层结构：

1. **模型** = 调用者/决策者（固定策略，只发 term、只读表面）；
2. **类型化项重写系统** = 计算核心（纯函数确定性归约 + 效应过监视自动机；依赖图
   作为内部状态随归约维护）；
3. **LIF** = 全局时间监控组件（独立于重写语义，挂最外面）。

唯一耦合面 = 事件流：重写系统每次归约、效应结果、模型轮均吐事件；LIF 消费该流。

不变量：**term 不能写 LIF；LIF 只读事件、只按自身动力学演化、只发 fires**（运行
起始配置除外）——守住 P2 观察/动作分离。

fires 双出口：

- **temporal 分区**（potentials + fires ≤ t）为可查询状态，模型经 term
  （如 `temporal.query`）读取——与"工具即类型化函数"一致；
- **客观汇报注入**（分叉特征事实陈述、守卫告警）由 LIF 自主发起，不经模型调用，
  直接进模型表面（2026-08-30 修订：不引回强制模板轮，见 §9.7）。

逻辑侧兄弟组件（不重叠）：依赖图（重写系统状态内，锚点/实体边随归约维护）+
LTL 时序验证（独立验证器，消费同一事件流）。LIF 负责"时间事件"，两者负责"逻辑"。

模型可见面 = 类型化函数库 + temporal 分区 + 探针注入，全部由结构生成、非标定。

### 9.1 工具类型签名（domain.service + target + data → 类型化值）

共享信封：成功 = 摘要 + 上限 + 指针（全文留盘/黑板）；失败 = fail-closed 信封
{step, code, message, trace_id}。

| 服务 | target | data | 结果类型 | 律/不变量 |
|---|---|---|---|---|
| file.read | file | offset?, length? | View = {path, hash, size, window{offset, content ≤16K}, truncated} | GetPut 前提：hash/size 即写前锚点 |
| file.grep | file?（可省=工作区） | pattern, path?, head_limit? | Grep = {pattern, files_searched, matches≤cap, truncated} | 纯函数；files_searched 信封 |
| file.search_replace | file | old, new, anchor?{hash,size} | Replace = {ok, diff{+,-}, new_anchor} | GetPut 律：anchor≠当前 hash → fail-closed；返回新锚点 |
| terminal.run | process?（缺省=新进程） | cmd, timeout?, cwd? | Cmd = {exit_code?, wall_ms, timed_out, stdout_tail≤N, stderr_tail≤N, pointer?} | 效应；host 拥有 cwd/env/超时；分层超时；中间回报 |
| retrieval.web_search | 无 | query, max_results? | Search = {query, sources≤cap[{title,url,snippet}], count, pointer} | 效应；子代理 relay；120s 超时；候选计数；MMR 选择 |
| retrieval.web_fetch | 无 | url | Fetch = {url, status, pointer, size} | 效应；候选计数；上限 |
| blackboard.read | 无 | partition, selector? | Board = {partition, entries≤8K, total_cap, pointer} | 纯查询；temporal 分区 = 时间特征查询口 |

检索模式变体：local_browser 模式隐藏 web 族、显示 browser_read（7 工具面）——
browser_read 视为 web_fetch 的 evidence 变体（返回 evidence pointer），签名同族。

调用形态（tool_calls 顶层 vs 表达式求值）仍属 §6.1 待裁决；以下签名与两种形态都
兼容——term 即这些类型化函数的应用，求值器负责归约与留痕。

#### 9.1.1 共享类型声明（信封 / 指针 / 失败）

```text
type Offset   = { n: Int ≥ 0 }
type Length   = { n: Int ≥ 1 }
type Pattern  = Text（正则；编译失败 = 类型化错误值）
type Anchor   = { path: File, hash: SHA256, size: Int }     -- GetPut 写前锚点
type Pointer  = FilePtr {path, hash, offset?}
              | BoardPtr {partition, selector}
              | EvidencePtr {canonical_url, fetch_id}
              | CmdPtr {log_path, span}
type Fail     = { step: arg_validation | gate | execution | delivery,
                  code: Symbol, message: Text ≤ 200 B, trace_id: TraceId }
type Result a = Ok { summary: Text ≤ 200 B, cap: Cap, payload: a, pointer: Pointer? }
              | Fail Fail
```

- 成功一律"摘要 + 上限 + 指针"三件套：模型读摘要做决策，全文经 pointer 按需取；
  cap 显式给出成本上界（每工具见签名）。
- 纯子项错误语义按 §6.5 待裁决（倾向：参数/模式错误 = 类型化错误值，同 Fail
  结构、step=arg_validation；效应错误 = fail-closed 信封，不变）。
- trace_id 与事件面同构：归约留痕 = receipt，可直接映射到事件链（§3/§5）。

#### 9.1.2 逐项签名（8 工具）

**① file.read（纯函数）**

```text
file.read : File → Offset? → Length? → Result View
View = { path, hash, size, window: {offset, content: Text ≤ 16 KiB, truncated: Bool} }
```

- 缺省 offset=0、length=cap；超窗截断并置 truncated=true，不静默裁剪。
- 律：返回的 (hash, size) 即写前锚点（search_replace 的 GetPut 前提）；同文件
  同状态同结果；解码按 GAP-ENCODING-GATE 契约（BOM 剥离 → UTF-8 严格 →
  GB18030 → lossy，命中编码随事件留痕）。

**② file.grep（纯函数）**

```text
file.grep : File? → Pattern → Path? → HeadLimit? → Result Grep
Grep = { pattern, files_searched: Int, matches: [Match ≤ 64], truncated: Bool }
Match = { path, line_no, span: {start, end}, text: Text ≤ 200 B }
```

- file 缺省 = 工作区；files_searched 是信封字段——模型看到"搜了多少"而非文件
  清单爆炸。
- 律：纯函数；结果上限 64 条 + truncated 标志，超出即停（候选计数纪律）。

**③ file.search_replace（效应：写）**

```text
file.search_replace : File → Old → New → Anchor? → Result Replace
Replace = { ok, diff: {minus: Int, plus: Int}, new_anchor: Anchor }
```

- GetPut 律：未给 anchor → 取依赖图中最近 read 的锚点；给了 anchor 且 hash ≠
  当前文件 hash → Fail(code=anchor_mismatch)。
- old 匹配数 n：n=0 → Fail(no_match)；n=1 → 替换；n>1 → Fail(ambiguous)——歧义
  必须 fail-closed，禁止静默替换首处（GetPut 一致性）。
- 返回 new_anchor，使下一轮 read 校验为 O(1) 哈希比较（§0 共识 2）。

**④ terminal.run（效应：执行）**

```text
terminal.run : Process? → Cmd → Timeout? → Cwd? → Result Cmd
Cmd = { exit_code: Int?, wall_ms: Int, timed_out: Bool,
        stdout_tail: Text ≤ 8 KiB, stderr_tail: Text ≤ 8 KiB }
```

- process 缺省 = 新进程；host 拥有 cwd/env/超时/资源（模型不可指定 env、不可
  绕权限）；分层超时（tool 级 timeout、run 级 wallclock）。
- wall_ms 是一等字段（§8.7 发现 1：时间特征层依赖它）；中间回报（S5-2）为同
  签名可选增量。
- 失败语义分层：exit_code ≠ 0 是**值**（结构化 Cmd），不是 Fail；Fail 只覆盖
  未启动、超时杀、门拒绝（ACAF/权限）。

**⑤ retrieval.web_search（效应：检索）**

```text
retrieval.web_search : Query → MaxResults? → Result Search
Search = { query, sources: [Source ≤ 10], count, pointer: EvidencePtr }
Source = { title, url, snippet: Text ≤ 200 B, weight, tier }
```

- 效应链：子代理 relay → 120s 超时 → 候选计数 → MMR 子模选择（相关性 −
  λ×多样性）→ 三层来源加权。
- local_browser 模式隐藏本工具与 web_fetch，显示 browser_read（7 工具面）。

**⑥ retrieval.web_fetch（效应：检索）**

```text
retrieval.web_fetch : URL → Result Fetch
Fetch = { url: CanonicalURL, status, size: Int, pointer: EvidencePtr }
```

- URL 规范化（http/https、userinfo 拒绝，ACAF Slice2B 目标解析）；大小上限 +
  全文留盘，模型只收 EvidencePtr。
- browser_read = 同族 evidence 变体（签名同构，返回 EvidencePtr）。

**⑦ blackboard.read（纯查询）**

```text
blackboard.read : Partition → Selector? → Result Board
Board = { partition, entries: [Entry ≤ 8 KiB], total_cap: Int }
```

- selector 类型化（key 路径/前缀），不引入自由查询语言。
- temporal 分区 = 时间特征查询口：potentials + fires；fires 必须按查询时刻截断
  （fires ≤ t，§8.7 发现 2）。

**⑧ delivery.submit（效应：交付）**

```text
delivery.submit : Draft? → Result Submit
Submit = { stage: 1 | 2, checklist: [Check], state: State }
```

- 两阶段：stage 1 = 信息展示（非硬门）→ stage 2 = 确认置 done；receipt 绑定
  终答（AGENT-DELIVERY-FLOW 形态不变）。
- 时序不变量（§8.2 LTL）：submit(2) 后无工具事件；终答前机械审计同轮注入。

### 9.2 组合与律

- 类型化管线：read → (anchor) → search_replace 是透镜管线；grep → read 是
  过滤→取窗管线。折中档允许一层组合（如 pipe(file.read, file.grep)）在同一往返
  归约，返回组合值或指针。
- 依赖图边随归约维护：read→write 锚点边、工具→实体变更边（§8.11 逻辑侧）。
- 确定性：纯服务（file.read/grep/blackboard.read）同状态下结果确定；效应服务
  只返回结构化信封，不返回自由文本。

### 9.3 stuck 二阶通道参数语义推导（零拟合；2026-08-30 离线重推修正）

一阶通道：

| 通道 | w | τ | θ | refractory | 语义推导 |
|---|---|---|---|---|---|
| err | 1/事件 | 180s | 4 | 60s | 4 次工具错误 / 3 分钟窗口 = "错误压力高"；实证 θ=4 在 31 run 仅 4 触发，高于正常调试爆发（常见 1–3 连错） |
| prog | 成功置 1 | 300s | —（∈[0,1]） | — | 进度新鲜度：成功即满、按 τ 衰减 |

二阶 stuck：

- I(t) = w·(u_err/θ_err)·(1 − u_prog)，w=1（归一化乘积，无新超参）；
- τ_stuck = 120s（"卡住条件须持续"的窗口 ≈ 2–3 个模型轮）；
- θ_stuck = 60s（秒级证据单位：u_ss = I·τ，θ 语义 = "满强度卡住约 1 分钟"）；
- refractory = 300s（两次问询探针最小间隔）。

推导数值：错误压力 0.75、无进展 0.9 → I≈0.68，u_ss≈82 > 60 → 会触发；

#### 9.3.1 精确事件驱动更新（闭式解，O(1)/事件）

二阶输入是**连续电流** I(t)，不是离散 spike。朴素右端点离散（草案的
u_s ← u_s·e^(−Δt/τ) + I·Δt）把"当前事件 spike 后的证据"回溯到整个前区间，
在真实数据上会把 u_s 膨胀 7–21×（fix-ocaml-gc：67.0 vs 真值 9.1；caffe-cifar-10
LSmDLs3：242.8 vs 真值 11.4）。正确做法是带泄漏核的精确积分——两阶指数乘积的
积分有闭式解：

```text
设 α = 1/τ_err − 1/τ_stuck，β = 1/τ_err + 1/τ_prog − 1/τ_stuck
（本参数下 α = −1/360，β = 1/1800，无退化分支）

u_stuck(t) = u_stuck(t₀)·e^(−Δt/τ_stuck)
           + (u_err(t₀)/θ_err)·e^(−Δt/τ_stuck)
             ·[ (1 − e^(−Δt·α))/α − u_prog(t₀)·(1 − e^(−Δt·β))/β ]

随后：u_err(t₀) → u_err(t₀)·e^(−Δt/τ_err)；u_prog 同理；再叠加事件 spike。
实现用 expm1 保数值稳定（(1−e^(−x))/x = −expm1(−x)/x）。
```

- **无需 min(1,·) 截断**：err 通道 full-reset 下 u_err ≤ θ_err 恒成立
  （u_err += 1 后 ≥4 即复位 0；事件间只衰减），u_err/θ_err ∈ [0,1] 是结构性
  事实，非近似。
- 验证：与 0.05s 步长 ODE 数值参考对 102 runs 全量对照，最大偏差 0.006；
  O(1)/事件、零新参数、确定性。

#### 9.3.2 参数语义（修正后）

| 参数 | 值 | 语义推导 |
|---|---|---|
| τ_stuck | 120s | "卡住须持续"窗口 ≈ 2–3 个模型轮（caffe-cifar-10 FMaD2Ce 实测 ~40s/轮） |

### 9.5 可学习生理参数 + 线性/非线性定位（2026-08-30 用户方向修正）

> 方向修正：§8.5 原定"不引入可塑性/学习"——2026-08-30 用户裁决：LIF 的生理参数
> （τ/θ/refractory）应可学习，时间性与可学习参数绑定，LIF 不是不可变内容。
> 同时定位：本设计对 LIF 的使用面 = **动作路径的振荡分叉前兆检测**（stuck/err/
> gap 通道），外部"LIF 除振荡分叉外弱于 EMA"的可用性结论与本使用面不冲突。

#### 9.5.1 使用面定位：振荡分叉前兆

- 模型动作路径的"卡住"形态 = 动作在失败点附近振荡、无进度——对应外部可用性结论
  中 LIF 唯一强于 EMA 的任务类（振荡分叉前兆，0.91 vs 0.85，且 spike 特征增量
  +0.05）。
- 通道映射：err = 振荡幅度（错误簇）；stuck = 临界前兆（错误压力 ∧ 无成功）；
  gap/stall = 解谐/脱锁（事件间隔漂移）。
- 因此"其他任务上 LIF 弱于 EMA"与本设计无关；真正要验证的是 LIF vs EMA **在本方
  事件流上**的对照（§9.4.3 四对照门），不是跨任务通用性。

#### 9.5.2 可学习参数：两层方案（语义固定 + 物理自适应）

- 分层的理由：固定秒数（如 τ=120s）隐含"模型轮 ≈ 40s"的假设，模型节奏变化时
  语义漂移（"2–3 轮"不再是 120s）。把"轮数语义"与"秒数物理"拆开：
  1. **语义参数（固定、决策推导）**：τ = 2–3 模型轮、θ 语义（如 4 错误 / 满强度
     持续 ~1 轮）、refractory 语义（如 ≥1 轮）——不随 run 变化；
  2. **物理参数（在线自调、事件推导）**：T̂ = run 自身事件的稳健节奏估计（如工具
     间隔中位数/EWMA，确定性算法），τ_sec = k·T̂；θ 与 refractory 同除以 T̂ 归一。
- 学习边界：**在线自调 ≠ 反向传播/标定拟合**——无标签、无梯度、无跨 run 拟合；
  更新规则是事件流的确定性函数（与"特征值"同层，§8.6 零依赖）。反向传播式学习
  需要监督目标，本设计不引入（与外部项目"不注入"边界同理，不展开）。
- 闭式解兼容：α/β 依赖 τ，逐区间用当前 τ 重算即可；闭式解与 O(1)/事件性质保持，
  精确性不因自适应而损失（τ 在区间内为常量、跨区间更新）。
- 范围边界：可学习对象 = 生理参数（τ/θ/refractory），通道集仍按决策点反推
  （§8.4），不因可学习而自动扩张。
- 验收：自适应后的 fires 须保持语义正确（§9.4.3 四对照门），且与固定默认参数
  相比行为差异可解释（如慢节奏 run 上固定 τ 漏触发、自适应 τ 正常触发）。

#### 9.5.3 线性/非线性定位

- LIF = 线性极点（e^(−Δt/τ) 衰减 + 加法输入，与 EMA 同构）+ 非线性（阈值穿越、
  复位、不应期、二阶归一化乘积）。
- EMA 只有线性部分——这正是外部对照中"无阈值结构任务弱于 EMA、分叉前兆任务强于
  EMA"的数学原因：分叉前兆有"连续接近 + 阈值事件"结构，非线性部分（spike）在此
  做功。
- 本设计推论：
  - potentials（膜电位）= 线性面，用于连续压力/新鲜度渲染（与 EMA 等价）；
  - fires = 非线性面，用于干预（探针注入）——价值主张在 fires；
  - §9.4.3 的"spike 移除"对照正是检验非线性面是否做功：fires 若不优于
    membrane-only，则探针触发源退回 EMA/计数。

### 9.6 T̂ 估计器与四对照门（可执行形态；2026-08-30 开工）

#### 9.6.1 基础公式的自适应参数（回答：只有 τ）

- 基础更新律 u(t) = u(t₀)·e^(−Δt/τ) + w 中，唯一内在参数是 **τ**（时间常数）；
  w 为结构权重（1/事件），θ 与 refractory 不在更新律内、属决策语义。
- 通道级分层（2026-08-30 确认）：速率/间隔探测器（err、stall）用**固定时间语义**
  τ（精确的墙钟速率/间隔检测）；持续/新鲜度通道（stuck、prog）用**轮语义**
  τ_sec = k_τ·T̂（自适应）；θ_sec、refractory_sec 由各自语义常数 × T̂ 归一
  （非学习，仅单位换算）；w 固定。
- 二阶通道同理：τ_stuck = k_s·T̂，α/β 逐区间用当前 τ 重算（§9.5.2 闭式解兼容）。

#### 9.6.2 T̂ 估计器规格（确定性、在线、零标签；2026-08-30 首轮修正）

- **决策轮定义**：相邻"决策输出"（model_output 且 tool_calls 非空）的间隔；一轮 =
  一次模型决策到下一次（含思考与工具执行）。text 输出与 tool_calls 输出同属一轮，
  不算间隔。
- **节奏分布事实（102 runs）**：决策间隔重尾双峰——典型轮 3–8s（caffe FMaD2Ce
  median 5.4s），长工具轮 100–1000s（mean 39.7s）。**单标量 T̂ 不稳定**
  （median 5.4 vs mean 39.7 vs 截尾均值 28.2），必须用在线局部估计，不用
  per-run 标量。
- 算法：有界内存储层（最近 16–32 个决策间隔）+ 稳健中心估计（中位数），每事件
  O(1)、确定性；长间隔截尾（>300s 计 300s）防单次长工具拉偏。
- 初始化与收敛：默认 T̂₀ = 8s（典型轮实测上界）；采样 ≥ 8 个间隔后启用；
  钳制 T̂ ∈ [3s, 600s]。在线滑动窗在 caffe 上稳定跟踪 3–12s（51/74 决策间隔
  < 10s），不随长尾漂移。
- **语义映射（err 保持时间语义，stuck/prog 轮语义；2026-08-30 混合确认）**：
  τ_err = 180s **固定**（错误速率：4 错误 / 3 分钟墙钟——精确的速率探测，不随
  节奏伸缩）、τ_prog = 8·T̂（成功新鲜度，轮语义）、τ_stuck = 3·T̂（卡住须持续
  2–3 轮）、θ_stuck = 1.5·T̂（满强度 1.5 轮）、refractory_stuck = 8·T̂（探针
  间隔）；stall 阈值 90s 固定（墙钟间隔探测）；θ_err = 4 事件（无量纲计数）。
- err 保持时间语义的理由（实证 §9.6.5.6）：轮语义在 102 runs 上使 err 触发
  从 22 run / 24 fires 降到 11 run / 8 fires（窗口被快节奏收紧），且无任何 run
  是"轮触发而时间不触发"——时间语义严格不劣；时间窗还强化 stuck 二阶证据（峰值
  θ 比 0.55 → 0.73）。
- 直观例子（mteb-retrieve 真实 run，第一次 fire @593.7s）：563.8s 失败 →
  u_err=1.54（更早的失败已衰减殆尽）；582.9s 两次失败 → 2.38 → 3.38；593.7s
  失败 → 4.19 ≥ 4 → fire。若 4 次失败散布在 20 分钟内，早先错误衰减殆尽，
  u_err 停在 1–2，不触发——τ_err 把"错误速率"固化为精确的墙钟窗。
- 不变量：θ/τ = 0.5 与"示例到达时间 = 4.05 轮（I=0.675）"在任意节奏下成立——
  语义以轮计，秒值随节奏伸缩。

| C2 spike 移除 | 用膜电位跨阈（u ≥ θ，无复位/无不应期）替代 fires 判定 | fires 时机与 membrane 跨阈不同（阈值事件结构在起作用） |
| C3 leak=0 计数 | τ→∞（纯计数）同 θ | fires 与计数窗口触发不同（泄漏/时间窗在起作用） |
| C4 EMA 对照 | 同 τ 的一阶 EMA 对同一信号做同 θ 判定 | fires 不劣于 EMA；非线性增量由 C2 单独衡量 |

- 通过 = "积分 + spike 捕捉时间特征"成立；任一不通过 → 该通道降级为普通统计
  特征，不得作探针触发源。
- 注意：C1 置换必须在"同事件数、同事件类型序列"下进行；C2 须在同一查询时刻点
  比较，避免采样差异造成假差异。二阶通道上 C2 与 C4 重合（EMA 乘积 ≡ 膜电位，
  单极点同构，§9.6.5.4）——独立对照实际为 C1 / C2≡C4 / C3 三个。

#### 9.6.4 首轮运行计划（2026-08-30，已完成）

1. 102 runs 计算 T̂（model_output 间隔中位数）与分布，交叉检验工具间隔；
2. 自适应参数闭式解重推 err/stuck，与固定参数基线对比 fires 与峰值证据，
   验证 θ/τ 与"到达时间以轮计"不变量；
3. C1 在 err 通道（有实际触发）跑 10 次置换；
4. C2/C4 在 stuck 通道上对比 membrane 跨阈 / EMA 乘积 vs fires。

#### 9.6.5 首轮运行结果（2026-08-30，102 runs）

1. **节奏重尾**：决策间隔 median 5.4s / mean 39.7s（caffe FMaD2Ce）；per-run
   winsorized T̂ 中位数 11.9s。单标量不稳定 → 确认在线局部估计器（§9.6.2）。
2. **自适应改变行为**：err fires 固定 22 run → 自适应（per-run 近似）11 run——
   变化全部来自 T̂ 偏快的 run（τ 变短、窗变紧）；stuck 固定/自适应均 0 触发
   （θ/τ 不变式成立，峰值 θ 比 0.65）。说明：参数语义随节奏迁移，不是装饰。
3. **C1 时间打乱（err 通道，10 置换）**：22 个触发 run 中 14 个 fires 数量改变
   （0–2 之间），8 个不变——时间结构在起作用但存在计数成分；err 通道"非纯
   计数"部分通过。
4. **C2/C4 合并**：二阶通道 EMA 乘积 ≡ 膜电位（单极点同构），C2 与 C4 对二阶
   通道重合；本批 stuck 0 fires 且 0 膜跨阈（max θ 比 0.65）——非线性面既无真
   触发也无误触发，仍未做功（诚实：未决，非通过）。
5. 推论（用户方向 + 实证确认）：err/stall 保持时间语义（固定 τ，精确速率/间隔
   探测），stuck/prog 用轮语义（自适应 τ）——"时间性绑定可学习参数"按通道决策
   语义分层，不统一轮化。
6. **混合方案（err 时间 + stuck/prog 轮）实证**：err fires 时间语义 22 run /
   24 fires vs 轮语义 11 run / 8 fires（T̂ 钳制 [3,600] 口径），分歧全部为
   "时间触发而轮不触发"（轮 ⊂ 时间，本批无轮独有命中）；stuck 三方案均 0 触发，
   但 err 时间窗强化二阶证据（caffe 峰值 θ 比 0.55 → 0.73）。结论：err/stall =
   固定时间语义，stuck/prog = 轮语义——可学习参数按通道决策语义分层。
7. **长积分探针（用户提议：窗口从 run 开始到结束）**：对 102 runs 计算工具错误
   长积分（τ=600s/1800s/leak=0）及语义化长线特征（长压 stuck、最大无成功间隔、
   晚期错误率、同工具重复失败）——与 reward 的 Spearman 全部 |ρ| ≤ 0.15
   （−0.06 ~ −0.15）；最高压力 run 多为成功（mteb-retrieve 24 错 113 成
   reward=1.0；caffe FMaD2Ce 长压 81.9 + 1171s 无成功仍 reward=1.0）。
8. **长积分结论**：工具错误的标量长线聚合（无论短窗/长积分/结构重复）不是"真正
   需要处理的错误"的可靠代理，不支撑 fires 干预触发器；长积分保留在 temporal
   分区作模型自我定速的信息面，不接 fires。缺失的观测面 = 失败目标的身份
   （同一命令/锚点反复失败）——当前事件面无 cmd 文本（tool_completed 仅
   tool/call_id/exit_code），需依赖图把"目标身份"纳入事件面（转正式设计前置）。
9. **长程特征提取（2026-08-30，逐决策轮轨迹）**：4 个代表 run 的特征轨迹——
   largest-eigenval 全特征近零（静默型死亡，唯一信号是 T̂ 漂移与 stall 间隔）；
   caffe FMaD2Ce 在 2658s 出现 u_stuck=36 的分离点后自行恢复（reward=1.0）；
   mteb-retrieve 错误爆发但 u_prog≈1 频繁复位、u_stuck 全程 <4.5（无分离）；
   chess-best-move 平坦低值。观察：分叉特征真实存在但稀少，且不携带结局方向
   （分离后自愈 vs 零特征下死亡）——支撑 §9.7 裁决。

### 9.7 fires 出口修正：取消注入，信息面落在特征域（2026-08-30 用户裁决）

> 裁决：不引回强制模板轮；spike 的"事件通知 + 客观汇报"亦取消（无实际价值），
> fires 仅作内部事件留痕。§8.8/§8.9 的"证据驱动探针 / 模板轮回归"方向由本节
> 取代；信息面全部落在连续特征域（§9.8）。

1. **方向错误 vs 持续错误**：
   - 持续错误（反复失败）→ 工具错误事件累积 → spike 在阈值处触发（u_err/θ、
     stuck 二阶）——spike 覆盖这一分支；
   - 方向错误（错误方向，未报错或散落错误）→ 不产生 spike 信号——spike 覆盖
     不了；需要其他观测（进度缺失的长程结构、目标身份重复，§9.6.5.8）。
2. **分叉判定的定位**：LIF 分叉判定 = 不同特征的分离点（正常 ↔ 卡住/振荡的
   转换点）；正常任务中动作动力学的分叉**不带可用后判定特征**——实证：错误标量
   特征与 reward 近零相关（§9.6.5.7）；caffe 在 u_stuck=36 分离点后自行恢复并
   reward=1.0，largest-eigenval 在零压力特征下墙钟死亡（§9.6.5.9）。分叉事件是
   事实，不是判断依据。
3. **fires 取消注入（2026-08-30 用户裁决）**：spike 的"事件通知 + 客观汇报"不加，
   无实际价值；fires 仅作内部事件留痕（日志/验证），不进模型表面。信息面全部
   落在特征域（见 5 / §9.8）。round50 维持现有软门提醒形态，不扩展为强制模板。
4. **准确性要求降级**：§9.4.3 的准确性要求仍适用（汇报也有注意力成本），但从
   "探针轮成本"降级为"汇报噪声预算"——误触发代价更小，θ 可略放松，refractory
   仍防风暴。
5. **特征域可分性（2026-08-30 实证，用户追问）**：分叉后恢复 ≠ 回到原正常域。
   caffe FMaD2Ce 三域（逐决策轮特征 (u_err, u_prog, u_stuck, T̂) 均值）：
   分叉前正常域 (0.89, 0.95, 1.26, 5.35)、分叉中域 (1.65, 0.27, 15.0, 8.7)、
   恢复后域 (0.38, 0.98, 8.59, 11.15)——两两可分（u_err / T̂ 的 d′≈2，差异是
   行为变化：节奏变慢、错误变少，不只是压力残留）。因此 **spike 只是单一边界
   事件**（标记进入卡住），区分"恢复新域 / 仍卡住 / 回正常"需要连续特征域轨迹；
   判定面 = temporal 分区的连续电位与相位，不依赖 fires。相位域用语义谓词定义
   （如 u_prog < 0.5 ∧ u_stuck > θ），不学标签（§8.6）。

### 9.8 特征域计算（2026-08-30 首轮，102 runs / 4157 决策点）

方法：逐决策轮特征向量 (u_err, u_prog, u_stuck, T̂, err10, succ10)，z 归一后
k-means（仅探索用，生产标签用语义谓词）。

- **k=3（sampled silhouette 0.36）三域**：
  - C1 正常域 n=2759：u_err 0.78 / u_prog 0.97 / u_stuck 1.1 / err10 0.04 /
    succ10 0.87；
  - C0 错误压力域 n=1233：u_err 2.61 / u_stuck 3.8 / err10 0.22 / succ10 0.75；
  - C2 深无进度域 n=165：u_prog 0.01 / succ10 0.03——注意其中 102 个是各 run
    首轮（u_prog 初始 0 的伪域），真深无进度段仅约 63 决策。
- **域轨迹（代表 run）**：caffe FMaD2Ce 正常 → 压力 → 深无进度 → 压力 → 正常
  （终回正常域，reward=1.0）；largest-eigenval 首轮后几乎全程正常域、静默死亡；
  mteb 正常 ↔ 压力多次迁移；chess 基本正常域。
- **语义谓词对照**："低进度高压域"（u_prog < 0.5 ∧ u_stuck > 10）全批仅 7 决策 /
  6 runs；caffe 卡住段特征 (u_prog≈0.27, u_stuck≈15) 与 C2 深无进度
  (u_prog≈0.01) 是不同域——域比单一谓词更细，生产建议用 (u_prog × u_stuck)
  平面网格 + 启动态排除。
- **判别力（诚实）**：末域 / 域迁移数与 reward 无判别——末域分布 reward1
  {正常 46, 压力 23} vs reward0 {正常 24, 压力 9} 同构；n_transitions ρ≈−0.09、
  n_domains ρ≈−0.11。域是事实描述，不是结局信号。

设计落点：

- 特征域 = temporal 分区的主要信息面：每轮给出当前域（语义谓词/网格）、进入
  时间、域内时长——纯确定性计算、O(1)/决策；
- fires 不参与信息面（§9.7 裁决）；k-means 仅探索，生产标签用语义谓词（§8.6）；
- run 首轮启动态（u_prog=0）单独标记，不并入任何域。

### 9.9 temporal 分区渲染规格（草案，2026-08-30）

定位：**观测记录面**——时间轴上的特征域事实序列。域 = 模型进入不同思维/行为
动力学阶段的观测标记；明确为纯观测性结果、仅记录，不承诺用途（使用方向开放，
见 9.9.5）。PULL 查询、零常驻 token、无注入、不给建议（§9.7 裁决）。

#### 9.9.1 数据模型（运行时查询行 + 存档 spike 点位）

```text
type TemporalRecord = {
  t: Time,                      -- 决策轮时刻（model_output 且 tool_calls 非空）
  domain: Start | Normal | Pressure | LowProgress | Stuck,
  entry_round: Int,             -- 进入当前域的轮次（相对 run 起始）
  dwell_rounds: Int,            -- 当前域驻留轮数
  u_prog, u_err, u_stuck: Float, T̂: Float,
  err10, succ10: Float          -- 最近 10 个工具事件中的失败/成功占比
}
```

记录不同域仅需 spike：域内状态行是**运行时**查询面（Now/Recent/Feature 取最近
k ≤ 20），不落盘；持久化只写域切换点位：

```text
type DomainSpike = { t: Time, domain: Domain }   -- 域切换事件；驻留轮数由相邻
                                                 -- spike 推导，不单独存储
```

#### 9.9.2 域定义（语义谓词，非学习；对照 §9.8 聚类）

```text
low_progress = u_prog < 0.5                     -- 最近成功 > ~5.5 轮前（τ_prog=8·T̂）
pressure     = (u_err ≥ 2) ∨ (u_stuck ≥ 1.5·T̂) -- 近 3 分钟窗 ≥2 错误，或卡住证据满 1.5 轮

Start         has_success = false               -- 首次成功前，不并入任何域
Normal         ¬low_progress ∧ ¬pressure
Pressure       ¬low_progress ∧ pressure         -- 有近期成功但仍高压（错误爆发未停）
LowProgress    low_progress ∧ ¬pressure         -- 长时间无成功、无错误压力（静默/方向错误）
Stuck          low_progress ∧ pressure          -- 长时间无成功 + 高压（真卡住）
Recovery       （轨迹属性，非静态格）卡住/低进度 → 正常 的迁移，记入迁移日志
```

与 §9.8 聚类对照：C1 正常域 → Normal；C0（u_err 2.61, u_prog 0.96）→ Pressure；
C2 深无进度（u_prog 0.01）→ LowProgress；caffe 卡住段（u_prog 0.27, u_stuck 15,
θ≈12）→ Stuck——四类分离成立，启动态不再产生伪域。

#### 9.9.3 查询面（经 §9.1 信封）

```text
blackboard.read : Partition="temporal" → Selector → Result Board
Selector = Now | Recent(k ≤ 20) | History | Feature(name, k ≤ 20)
Board = { partition, entries ≤ 1 KiB, total_cap }
```

- Now：当前域状态行（域、入域轮、驻留轮 + u_prog/u_err/u_stuck/T̂/err10/succ10）；
- Recent(k)：最近 k 轮状态行序列（时间倒序）；
- History：域迁移日志（domain, 入域轮, 驻留轮），有界（最近 ≤ 20 条迁移）；
- Feature(name, k)：单特征紧凑序列（如 `0.3,0.5,1.2`）。

渲染示例（caffe FMaD2Ce @2658s，示意）：

```text
temporal.now → [2658s | Stuck | 入域 2 轮前 | 驻留 2 轮]
  u_prog=0.27 u_err=1.2 u_stuck=15.0 T̂=8.7s err10=0.3 succ10=0.1
```

#### 9.9.4 渲染约束

- 只渲染 ≤ 查询时刻（无未来）；fires 不渲染（内部留痕，§9.7）；
- 启动态单独标记，不并入域统计；run 首轮不产生伪域；
- 有界内存：运行时仅保留查询窗（状态行 k ≤ 20）+ 当前域状态，O(1)/决策；
  迁移历史由 spike 存档推导，不单独缓存；
- 更新时机：每决策轮重算一次，确定性、零标签；
- 存档随对话（2026-08-30 用户裁决）：域切换 spike 随 orz 对应会话侧车
  （`.gsa/conversations/{session8}.json` StoredConversation envelope）一同存档
  ——追加字段或同目录伴随文件（载体待正式设计裁决），与对话同生命周期
  （7 天 retention 一并清理），不建独立持久化/索引；跨 prompt 恢复时随侧车
  载入，域状态可重建；
- 无注入、无建议：temporal 是 PULL 面，不进 prompt（除非模型/用户显式查询）。

#### 9.9.5 记录价值与使用方向（开放）

- 已确认价值：域序列 = "模型进入不同思维/行为动力学阶段"的跨轮可查观测记录；
- 存档形态（2026-08-30 用户裁决）：记录不同域仅需 spike 点位（域切换事件），
  随 orz 对应会话侧车一同存档、与对话同生命周期；不单独持久化逐轮状态行；
- 候选使用方向（未定，仅登记）：长工具调用前/预算临近时按需查询、终答前机械
  审计同轮附带域历史、压缩时保留域序列摘要；错误预判断与重试（用户提名：低进度/
  卡住域驻留时长 × 后续域类型）——后者为优先候选，机制未定，见 §9.10；
- 阈值初值已确认（2026-08-30 用户）：u_err ≥ 2、u_prog < 0.5、
  θ_stuck = 1.5·T̂、err10/succ10 窗口 10——语义推导，非拟合，仅作记录内容，
  不牵涉具体机制；入正式设计时沿用为初值。

### 9.10 LIF 职责收窄与域时长预判方向（2026-08-30 用户裁决）

**LIF 定位定稿：单纯时间性外挂。** 当前阶段 LIF 只承担时间特征计算（一阶
积分/泄漏 + 二阶 stuck 通道，输出 u_prog/u_err/u_stuck/T̂ 等时间量），不承担
注入、预判、建议、拦截等任何动作职责；§8.9 的"动作特征即时使用 / 强制模板轮
回归"、§9.7 已取消的事件汇报等扩展用途全部维持搁置，未想清前不扩职责。

- LIF 的时间性输出唯一信息面 = temporal 分区（§9.9）：PULL、零常驻 token、
  无注入、不给建议；
- 域序列继续仅作观测记录（§9.8 结论：域是事实描述，不是结局信号），暂不参与
  任何自动化动作；
- **新开放方向（登记，未设计）**：以"低进度/卡住域驻留时长 × 后续域类型/迁移
  序列"做错误预判断与重试。两个待想点：
  1. 该方向停在观测面（模型 PULL 后自行决策重试）还是进入机制面（框架自动
     干预重试）——前者与 §9.7"不引回强制模板轮"兼容，后者需重开裁决；
  2. 信号形态是"驻留时长 + 后继域"的联合特征（如 Stuck 长驻留 → Normal 与
     Stuck 长驻留 → Stuck 的区分），需先在离线数据上验证哪些 (驻留时长,
     后继域) 组合与失败目标身份 / reward 相关——尚未设计探针。
- 依赖：该方向以 §9.9.2 域标签稳定为前提，且失败目标身份需入事件面（转正式
  设计前置，见 §6 开放项 8/13）。

> 2026-08-30 追加（§9.11）：定位细化为"时间性参考系"——低精度容忍、模型
> 无感；双尺度基线、每轮校准、观测面扩充与动作层耦合试验见 §9.11。

### 9.11 参考系重定位、观测面扩充与模型无感边界（2026-08-30 用户裁决）

**LIF 定位再修正：从"探测器"到"时间性参考系"。** 用户裁决（2026-08-30）：
对个人普通用户/API 用户，模型内部不可访问，降低精度本身不是缺陷——LIF 是
模型对自己动作行为的大概参考，不要求高精度；已确认的窗口/阈值均为语义推导
初值、非精确性窗口，允许相当误差余量，目标只是帮助模型判断（粗决策：继续/
转向/收尾）。**模型无感原则（硬边界）**：上述一切计算全部落在机械层；模型
只通过 `blackboard.read partition="temporal"` 拿到渲染结果并使用（PULL、
零常驻 token、无注入、无模板轮、无自动动作——§9.7/§9.9/§9.10 形态不变），
模型面不新增任何机制；模型"只需要得到结果并使用即可"。

1. **精度定位（决策论依据）**：读数成本有界 + 注意力预算有界 → 优化目标是
   "对决策的互信息"而非估计精度。家庭/国内网络属高方差环境：长窗以偏差换
   方差缩减（吞掉高频网络/环境干扰），粗决策吃得起该偏差；量化档+语义标签
   渲染沿用（§8.5），防止模型对数字过度信任。
2. **双尺度基线结构（吞环境波动、不吞退化）**：
   - 长窗（整 run 在线估计，10–30 分钟级）= **环境基线**：本 run 自己的背景
     错误率，归一化网络抖动/超时/DNS 等干扰；
   - 短窗（≈3 分钟）= **当前偏离**：最近发生了什么；
   - 渲染 = 基线 + 当前 + 比值（如"当前错误率 = 基线 ×2.1"）；
   - 结构定位：CUSUM 的 baseline+drift 原语；旧证据不污染当前读数；模型自身
     退化以相对偏离显现，不被基线平均掉。
3. **校准分层（每任务轮重算，不固定全局值）**：
   - 动因：现有离线数据仅是历史检验；家庭网络随时间/任务漂移，全局常量会
     过期——每轮重算是概念漂移应对；
   - 语义固定、秒值自适应：θ 轮数语义（θ_err=4 事件、θ_stuck=1.5 轮、
     refractory 等）不随 run 变，秒值经本 run T̂ 换算（§9.6.2 延续）；"重算"
     是单位换算，不是每轮拟合阈值；
   - 自指反馈环防制：行为变慢 → T̂ 变大 → 窗口变宽 → "慢"被归一化掩盖；
     err 保留墙钟 180s 绝对锚，T̂ 钳制 [3,600]s，同时记录原始秒值与归一化
     轮值，两者都可查；
   - 早期小样本噪声：run 开头（T̂ 未收敛，≥8 间隔启用前）域标签/读数标注
     可信度与样本量，模型不过度信任前几轮。
4. **观测面扩充优先级（补偿大窗口精度缺失；逐项过 §8.4 决策点反推）**：
   1. 失败目标身份入事件面（F4）——唯一区分"反复失败"与"错误但推进"的观测，
      信息增益最大且便宜；
   2. stated-vs-done 探针一致性——探针自述下一步 vs 实际动作，合规内部探针，
      直接服务耦合试验；
   3. 环境进展接地（测试通过/文件 diff）——解耦"模型在忙"与"任务在推进"
      （u_prog 最大盲区）；
   4. 序结构（熵率/动作转移/自相关）——现有事件流上零成本计算；
   5. 混杂控制——验证纪律：同难度、同模型类下再谈判别（Beyond Resolution
      Rates：轨迹长度-失败关联是难度混杂）。
5. **内部耦合试验（动作层、可证伪、102 runs 离线可跑）**：TRACED 几何搬到
   动作层——用命令/编辑目标语义相似度定义动作位移（progress）与方向变化率
   （curvature），检验三个命题：
   - P1：成功 run 动作级 progress 显著更高、curvature 显著更低（须控难度）；
   - P2：域序列提升对"下一步动作类型"的预测（转移似然）——域携带行为信息的
     直接检验；
   - P3：stated-vs-done 一致性高的 run，后续动作更可预测。
   - 判定：P1–P3 成立 → "时间性 + 全局视野外挂"值得做；不成立 → 参考工具
     保留（自我定速），但不得宣称携带超出事件流的内部信息。
6. **四支柱（本次裁决的落点）**：低精度参考（成本低）+ 双尺度基线（吞环境
   波动不吞退化）+ 每轮自适应（概念漂移免疫）+ 可证伪耦合试验（决定投入
   边界）。

## 10. 理论收益论证：模型压力转移表（2026-08-30 正式开工前检查点）

核心命题：模型每轮负担 L = 决策 + 记忆 + 解析 + 自监控 + 约束遵守。框架可精确
计算的成分（时间特征、状态身份、合法性、一致性、时序逻辑、证据累积）全部机械
服务；模型只保留框架算不了的成分（下一步动作决策）。表面趋近"下一步决策的最小
充分统计量"（§8.6 纪律的落点）。

压力转移表：

| 模型负担（现状） | 转移给 | 机制 | 理论收益 |
|---|---|---|---|
| 时间/进度/错误率自监控（模型无时间感；实测 largest-eigenval stall 仅提前 24s 发现） | LIF 一阶通道 | 积分/泄漏/阈值 | 精确、O(1)、PULL 零常驻 token |
| "我是否卡住"元认知判断（高错误率） | LIF 二阶 stuck 通道 | 联合证据乘积 | 证据驱动，消除误判与误干预（参数级实证见 §9.3.3：本批 0 触发 = 零误干预；早期介入由一阶 err3/gap120 承担） |
| 跨轮记忆/簿记（改过什么、谁依赖谁、过了多久） | 依赖图 + temporal 分区 + 内容寻址 | 查询代替重建 | O(1) 查询 vs O(history) 重建 |
| 工具结果解析（多格式自由文本） | 类型化信封（单一文法） | ADT | 解析成本 O(grammar)，与工具数无关 |
| 多步编排（曾实测 2.3–2.9 往返/动作） | 一层组合（pipe） | 归约 | 往返↓ → 上下文增长↓、延迟↓ |
| 固定轮问询干扰（50 轮无差别触发，曾掐断 5 题） | LIF fires（round50 仅兜底） | 证据触发 + refractory | 干扰从"调度"变"证据"，更少且更相关 |

不变/新增成本（诚实）：模型保留下一步动作决策（唯一框架算不了的成分）；新增 term
文法熟悉成本（保留 tool_calls 顶层则≈0；文法必须 code-like，否则解析收益被抵消）、
temporal 分区按需读取 token（PULL 有界）、探针轮成本（证据门控 + refractory，替换
模型自身更差的自我重定向）。不保证任务级能力（C 类失败——模型真实能力边界，
harness 无法修复）。

理论结论：设计把模型负担从"模型做得差且贵的隐式认知任务"（自监控、时间跟踪、
簿记、元认知）转移到"框架做得准且便宜的显式机械计算"（积分、阈值、查询、依赖边、
一致性校验）。残余负担只有策略决策本身。**方向性收益成立**；量化收益属实施后
实证问题（离线复验或 A/B），不在理论层承诺。
