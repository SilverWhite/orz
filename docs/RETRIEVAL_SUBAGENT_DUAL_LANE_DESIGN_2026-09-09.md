## 0. 用户裁决（登记口径）

**立项裁决（2026-09-09 上午）**

1. 环境背景（R3 复跑当夜）：Clash 频繁超时但未真正掉线、扰乱测试，用户已关闭
   Clash；跑批使用**本地镜像**——Google 检索实际不可用、Chrome 实质不可用，
   但现行机制**无法降级到原生检索**。
2. 方向裁决：**原生检索（web 族）与本地浏览器检索（browser_read）都要开放给
   检索子代理**，像主 agent 工具栏一样**打标注**，**推荐模型先用本地浏览器
   检索**。
3. R3 新摩擦值得立项（FP-1～FP-9，见 0S 审计 §4），随本项统一处置。

**第一轮复核（v1.1）**

4. FP-2 不额外处理：不做「勿原样重试」等提醒（过度设计），仅正常返回检索
   结果——网络错误、超时、防火墙拦截等按真实类别回传。多次重试的根因是
   **浏览器组件可拉起但实质不可用**，与「工具可用性声明与实际情况冲突」
   问题本质相同（FUS-TOOL-PROBE 同族）。
5. 不做「标注健康度」：工具栏给个标注就行，标注本身不做变动，模型自己判断
   选择。
6. mteb：核查镜像是否存在问题——该镜像既往在 VM high-nist 下能跑通。
7. `framework_fallback` 语义还要再额外考虑。
8. FP-3 死在检索慢通道（叠加本地网络节点），节点问题用户后续自行处理。
9. FP-4 不是问题：模型自己的动作不干预，只要没挂死就行。
10. FP-5 关键在机械层拦截下来并正常反馈（R3 已验证满足，见 §3.7）。
11. FP-6 不是大问题：黑板只是总览，模型需要详细信息就让其自行翻阅。

**第二轮复核（v1.2）**

12. 浏览器问题考虑为**注入＋网络环境**问题：用户在**真机环境**中测试并处理；
    **orz 需要能够正常使用真机环境中的浏览器**；**锁版本或其他处理方式不
    通用，不做**；**跑分不重要，需要确定日常使用没问题**。
13. `framework_fallback` 收窄采纳**彻底的 γ 方案**：框架的修改成本不是需要
    重点考虑的内容。

## 1. 背景与证据（R3 实证）

- **binary 工具面的死法**：现行模式 A 下 external 子代理工具面按激活模式
  二选一——`local_browser` 车道仅 browser_read（web 族调用被
  `retrieval_mode_requires_framework_fallback` 拒绝，orz
  `orz-loop/src/retrieval/dispatch.rs` `local_browser_lane_refuses_web_tools`）。
  浏览器「可拉起但实质不可用」时（本地镜像下 Google/SERP 不可用、mteb 容器
  内 Chrome 全导航级 chrome-error），模型手握死车道而无法换到原生检索——
  mteb 52 次拒绝重试烧 865s（预算 2812s 的 31%），靠模型自用终端 curl 才破局。
- **定性**：「工具可用性声明与实际情况冲突」的同族问题（FUS-TOOL-PROBE
  解决过主 agent 探针面的同一矛盾）；结构性解 = 双车道并存 + 静态标注 +
  模式状态退役（γ），把车道选择权完全交还模型，机械层只做事实记录与
  正常回传。
- **mteb 核查结论**（[`0T_MTEB_IMAGE_CHECK`](audits/0T_MTEB_IMAGE_CHECK_2026-09-09.md)）：
  镜像降嫌疑（同镜像 08-31 browser 39/41 健康 vs R3 0/52 全灭）；Chrome 系
  运行时 apt 浮动注入（151→152 自动升级）＋网络环境问题——按裁决 12，该
  问题由用户在真机环境测试处理，orz 侧不以评测容器注入为目标做特化修复。

## 2. 目标与非目标

**目标**

1. external 检索子代理工具面同时注册 `browser_read` 与 `web_search`/`web_fetch`
   两族；激活内模型自行换道；**任何检索模式下两族工具恒在**。
2. 工具带**静态**工具栏标注（主 agent 工具栏同构）：车道名 + 推荐序
   （本地浏览器优先）；标注固定不变，不做健康度/动态字段，选择由模型自主。
3. 推荐序以 ≤1 句框架使用提示告知（沿 FUS-RETRIEVAL-SUBAGENT-WIRING 既有
   风格）。
4. **γ：检索模式三值语义退役**——浏览器可用性改为纯事件事实（见 §3.3）；
   工具面不再由模式裁剪；换道无需任何专门事件（journal 的 ToolCompleted
   本身就是事实）。
5. FP-2：检索失败**正常回传**——导航失败按普通错误结果返回真实类别
   （网络错误/超时/拦截等），与其它工具失败同纪律；无教学句、无阻拦。
6. **真机日常可用性**：orz 的 local_browser 车道在真机环境使用已安装的真实
   浏览器（日常默认有头）可正常拉起、导航、交付——以日常使用为准，
   评测容器注入场景不作目标（裁决 12）。

**非目标**

- 不做锁版本、快照优先化等只对评测容器有效的特化处置（不通用，裁决 12）。
- 不改主 agent 工具面与 console/direct 语义；不改 internal 子代理
  （`retrieve_project_docs`）。
- 不做任何形式的「勿重试」教学、失败计数反馈或机械降级提示（FP-2 裁决：
  过度设计）。
- 不做自动重试循环、不做内容级成败判断。
- `web_search` 全局并发 1、候选 cap、轮预算、ACAF 票据等既有硬门不变。
- 不为跑分特化（通用双车道能力，跑分不重要）。

## 3. 设计

### 3.1 双车道工具面

- external 子代理激活时同时注册 browser_read + web_search/web_fetch；
  `dispatch.rs` 的 `retrieval_mode_requires_framework_fallback` 拒绝族退役
  （由静态标注偏好替代硬拒绝）。
- **γ：`retrieval_mode` 三值状态整体退役**（`off`/`local_browser`/
  `framework_fallback` 不再作为激活状态存在）。工具面恒双族；浏览器缺席时
  browser_read 调用按普通失败回传（§3.4），模型自然走 web 族。
- 引擎 SERP 主序语义（Google 主序、Bing 回退）保留为浏览器车道内的首选
  路径；车道实质不可用时模型依标注与试错自行走原生检索。

### 3.2 静态工具栏标注（主 agent 工具栏同构）

- 标注内容固定两条：车道名（本地浏览器检索 / 原生检索）+ 推荐序
  （本地浏览器优先）。无探活结局、无失败计数、无任何动态字段。
- 形态（示例，定稿时固化措辞）：
  - `browser_read — [车道:本地浏览器检索|推荐首选]`
  - `web_search — [车道:原生检索]`
- 标注落点：工具描述字段 + 激活提示词的既有框架使用提示行（≤1 句推荐序），
  满足零新增常驻 token 纪律。

### 3.3 γ：模式退役与浏览器可用性事件事实化

- **退役面**：`retrieval_mode` 激活状态字段、`retrieval_mode_transition`
  事件族、`framework_fallback` 模式值、`retrieval_mode_requires_framework_fallback`
  拒绝码、SERP 页级失败机械降级（模式 A 的降级语义）——全部退役；「机械
  降级」概念随之消失，浏览器失败就是失败事实 + 正常回传，换道由模型完成。
- **事实化事件面**（schema/verifier/fixtures 先行）：
  - 浏览器每次启动/探活尝试落 `browser_launch_result` 事实事件
    （success/failure + 真实原因）；可用性翻转沿用既有
    `tool_availability_check` 事件。
  - 事件面不带 args、key 不落卷等既有纪律不变。
- **换道**：无模式状态、无 `model_lane_switch` 事件——调用了哪个车道的工具，
  journal 的 ToolCompleted 已是事实，无需专门事件。
- **兼容**：旧 journal 中含 `retrieval_mode`/`retrieval_mode_transition` 的
  事件为合法历史，verifier 放行（只读）；新生产者不再产出。schema 枚举
  收缩需登记版本注记。

### 3.4 检索失败正常回传（FP-2）

- browser_read 导航失败按**普通错误结果**返回，错误信息给真实类别
  （网络错误/超时/防火墙拦截/DNS 失败等），与其它工具失败同一纪律；
  不做「勿原样重试」类教学、不做额外阻拦、不做诊断提示。
- 同一 URL 是否重试由模型自主决定；浏览器「可拉起但实质不可用」的矛盾由
  双车道 + 静态标注 + 失败正常回传结构性化解。

### 3.5 真机日常浏览器可用性（裁决 12）

- 目标形态：orz 在真机（日常开发机）使用**已安装的真实浏览器**（默认有头、
  隔离 profile，GAP-LOCAL-BROWSER 既有机制）稳定完成拉起→导航→内容交付；
  以日常使用可靠性为验收口径，不以评测容器内注入链为验收口径。
- 验证方式：用户在真机环境主导测试（含其网络环境实际条件），orz 侧对暴露
  的问题做通用性修复（不做锁版本/环境特化）；问题与修复按常规登记。
- mteb 容器内问题（注入+网络环境）：用户真机自理，orz 侧不再单列处置；
  核查档案见 §3.6。

### 3.6 mteb 核查档案（方向已转真机）

- 核查结论保留存档（[`0T_MTEB_IMAGE_CHECK`](audits/0T_MTEB_IMAGE_CHECK_2026-09-09.md)）：
  镜像降嫌疑；同镜像 08-31 browser 39/41 健康（apt Chromium 151）vs R3 0/52
  全灭（152，curl 可用）；Chrome 系运行时 apt 浮动注入；用户记忆的「下载
  构建跑通」为 08-30 gate-google-1 与 08-31 sweep-0h 两次本机容器通过，
  VM W2-031 为直跑提示词 + 知识作答；mteb 从未靠 browser 车道通过过。
- 原「活体探针计划」取消（评测容器方向，裁决 12：跑分不重要、特化不通用）。

### 3.7 FP-5 既有行为确认（无需动作）

- 模型自造工具名变体的要求 = 机械层拦截并正常反馈。R3 已验证满足：
  29/29 全部被拦截，结构化 `Tool not found` 信封 1–5ms 返回，模型次轮
  自恢复，无连锁浪费。本项登记为确认，不产生实施动作。

## 4. 不变量

- 零注入边界：无新常驻 token；标注只出现在工具描述与一次性提示。
- fail-closed：web 族工具恒在，不出现无检索工具的激活。
- 审计不变：journal 事件面、failure 盖章、evidence 分级、来源加权三档全部
  跨车道生效；浏览器可用性由事实事件承载，不回退为不可核验的隐式状态。
- 干预边界：模型自身动作（含重复尝试、换道选择）机械层不干预，仅保证
  不挂死（既有 stall/idle 兜底）与结构化反馈。

## 5. S4 复验判据（草案，定稿时固化）

1. 双车道存在性：web 族调用在任何场景不再被
   `retrieval_mode_requires_framework_fallback` 拒绝（负样本转正样本）。
2. 静态标注存在性：两族工具描述含车道名与推荐序；无动态健康度字段。
3. γ 退役兼容：新 run 不再产出 `retrieval_mode`/`retrieval_mode_transition`；
   旧 journal 回放通过 verifier；`browser_launch_result` 事实事件在案。
4. 检索失败回传形态：导航失败错误含真实类别（网络错误/超时/拦截），
   无教学句/阻拦文案。
5. 通用统计：命中率 ≥90%、零真实 400、token/墙钟对照 R3 同题；
   chrome-error 后模型换道行为作自然观察登记，不设指标。
6. 真机日常可用性：真机环境真实浏览器拉起→导航→交付全链通过
   （用户主导验证，口径=日常使用）。
