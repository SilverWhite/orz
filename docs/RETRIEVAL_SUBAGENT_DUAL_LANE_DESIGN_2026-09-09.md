## 0. 用户裁决（登记口径）

**立项裁决（2026-09-09 上午）**

1. 环境背景（R3 复跑当夜）：Clash 频繁超时但未真正掉线、扰乱测试，用户已关闭
   Clash；跑批使用**本地镜像**——Google 检索实际不可用、Chrome 实质不可用，
   但现行机制**无法降级到原生检索**。
2. 方向裁决：**原生检索（web 族）与本地浏览器检索（browser_read）都要开放给
   检索子代理**，像主 agent 工具栏一样**打标注**，**推荐模型先用本地浏览器
   检索**。
3. R3 新摩擦值得立项（FP-1～FP-9，见 0S 审计 §4），随本项统一处置。

**复核裁决（2026-09-09，v1 → v1.1）**

4. FP-2 不额外处理：不做「勿原样重试」等提醒（过度设计），仅正常返回检索
   结果——网络错误、超时、防火墙拦截等按真实类别回传。多次重试的根因是
   **浏览器组件可拉起但实质不可用**，与许久之前「工具可用性声明与实际情况
   冲突」问题本质相同（FUS-TOOL-PROBE 同族）。
5. 不做「标注健康度」：工具栏给个标注就行，标注本身不做变动，模型自己判断
   选择。
6. mteb：核查镜像是否存在问题——该镜像既往在 VM high-nist 下能跑通。
7. `framework_fallback` 语义还要再额外考虑（不入本版定稿）。
8. FP-3 死在检索慢通道（叠加本地网络节点），节点问题用户后续自行处理。
9. FP-4 不是问题：模型自己的动作不干预，只要没挂死就行。
10. FP-5 关键在机械层拦截下来并正常反馈（R3 已验证满足，见 §3.6）。
11. FP-6 不是大问题：黑板只是总览，模型需要详细信息就让其自行翻阅。

## 1. 背景与证据（R3 实证）

- **binary 工具面的死法**：现行模式 A 下 external 子代理工具面按激活模式
  二选一——`local_browser` 车道仅 browser_read（web 族调用被
  `retrieval_mode_requires_framework_fallback` 拒绝，orz
  `orz-loop/src/retrieval/dispatch.rs` `local_browser_lane_refuses_web_tools`）。
  浏览器「可拉起但实质不可用」时（本地镜像下 Google/SERP 不可用、mteb 镜像
  内 Chrome 全导航级 chrome-error），模型手握死车道而无法换到原生检索——
  mteb 52 次拒绝重试烧 865s（预算 2812s 的 31%），靠模型自用终端 curl 才破局。
- **定性**：这是「工具可用性声明与实际情况冲突」的同族问题（FUS-TOOL-PROBE
  解决过主 agent 探针面的同一矛盾）；本设计的结构性解 = 双车道并存 + 静态
  标注，把车道选择权交还模型，而不是机械层替模型判断车道生死。
- **降级触发面过窄**：`browser_launch_failed`（注入失败，R3 四题）与 SERP 页
  级失败才降级；「能拉起但导航全挂」「搜索引擎不可达」不触发任何降级。
  `framework_fallback` 语义如何调整待议（§6）。
- **评测侧注入链脆弱**（FP-1）：快照回退依赖容器 `unzip` + 单源下载，报废
  4 题 browser 车道。
- 对照面：count-dataset-tokens 同形态 2 次即换路径（浏览器健康时重复尝试
  不成灾，属模型正常探索）；mteb 通过靠 3600s 预算冗余 + 模型韧性，不靠
  车道健康（0S 审计 §5）。

## 2. 目标与非目标

**目标**

1. external 检索子代理工具面同时注册 `browser_read` 与 `web_search`/`web_fetch`
   两族；激活内模型自行换道，无需整激活降级。
2. 工具带**静态**工具栏标注（主 agent 工具栏同构）：车道名 + 推荐序
   （本地浏览器优先）；标注固定不变，不做健康度/探活结局等动态内容，
   选择与换道由模型自主判断。
3. 推荐序以 ≤1 句框架使用提示告知（沿 FUS-RETRIEVAL-SUBAGENT-WIRING 既有
   风格）。
4. 换道落事件面，检索记账（候选 cap、evidence、来源加权）跨车道继续生效。
5. FP-2：检索失败**正常回传**——导航失败按普通错误结果返回真实类别
   （网络错误/超时/拦截等），与其它工具失败同纪律；无教学句、无阻拦、
   无诊断提示。
6. FP-1：评测侧注入健壮化随批实施。

**非目标**

- 不改主 agent 工具面与 console/direct 语义；不改 internal 子代理
  （`retrieve_project_docs`）。
- 不做任何形式的「勿重试」教学、失败计数反馈、车道健康度追踪或机械降级
  提示（FP-2 裁决：过度设计）。
- 不做自动重试循环、不做内容级成败判断；页面级失败仍不触发机械降级。
- `web_search` 全局并发 1、候选 cap、轮预算、ACAF 票据等既有硬门不变。
- 不为跑分特化（通用双车道能力）。

## 3. 设计

### 3.1 双车道工具面

- external 子代理激活时同时注册 browser_read + web_search/web_fetch；
  `dispatch.rs` 的 `retrieval_mode_requires_framework_fallback` 拒绝族退役
  （由静态标注偏好替代硬拒绝）。
- `retrieval_mode` 字段保留；`local_browser` 模式下两族工具并存。
  `framework_fallback` 的语义调整（是否收窄为「浏览器能力不存在」、对既有
  事件/verifier 的兼容）**待议**（§6），本版不改其行为。
- 引擎 SERP 主序语义（Google 主序、Bing 回退）保留为浏览器车道内的首选
  路径；车道实质不可用时模型依静态标注与试错自行走原生检索。

### 3.2 静态工具栏标注（主 agent 工具栏同构）

- 标注内容固定两条：车道名（本地浏览器检索 / 原生检索）+ 推荐序
  （本地浏览器优先）。无探活结局、无失败计数、无任何动态字段（用户裁决：
  不做标注健康度，不做变动）。
- 形态（示例，定稿时固化措辞）：
  - `browser_read — [车道:本地浏览器检索|推荐首选]`
  - `web_search — [车道:原生检索]`
- 标注落点：工具描述字段 + 激活提示词的既有框架使用提示行（≤1 句推荐序），
  满足零新增常驻 token 纪律。

### 3.3 换道语义与事件面

- 模型在激活内换道不需模式翻转；首次实际使用非偏好车道时落
  `retrieval_mode_transition`（新增 `reason_code=model_lane_switch`、
  `authority=model`），同一激活至多记一次，防事件面膨胀。
- 机械降级（`browser_launch_failed` 等）语义暂不变，authority 仍为
  `mechanical_probe`；与 `framework_fallback` 的最终关系随 §6 裁决定版。
- 检索记账跨车道：候选 cap 对 browser_read 与 web_fetch 继续累计；
  `retrieval_result_committed` / close record 不区分车道（payload 可选
  `lane` 字段，schema 先行）。

### 3.4 检索失败正常回传（FP-2）

- browser_read 导航失败按**普通错误结果**返回，错误信息给真实类别
  （网络错误/超时/防火墙拦截/DNS 失败等），与其它工具失败同一纪律；
  不做「勿原样重试」类教学、不做额外阻拦、不做诊断提示。
- 同一 URL 是否重试由模型自主决定；浏览器「可拉起但实质不可用」的矛盾由
  双车道 + 静态标注结构性化解（模型有真实可选的第二车道），机械层不再
  试图替模型判断车道生死。

### 3.5 评测侧注入健壮化（FP-1，随批实施）

- `tb_agents/orz.py` 注入链：解压改 `python3 -m zipfile`（不依赖容器 unzip）；
  快照下载加 3 次重试 + 失败原因透传 console；apt 双路径报告不吞并。
- 边界：评测侧工具链改动，不进 orz 判据面；与 0r 同族管理（环境形态文档化）。

### 3.6 mteb 镜像核查（FP-2 关联子项）

- 用户指出 mteb 镜像（`:20260430`，tag 与众不同）既往在 VM high-nist 下
  可跑通；R3 容器内该镜像 Chrome 全导航坏死（curl 可用）需核查镜像本身
  是否有问题（chromium 依赖/网络栈/镜像内配置与 VM 环境差异）。
- 产出：核查注记（对比 VM high-nist 既往证据），不预设修复、不追打。

### 3.7 FP-5 既有行为确认（无需动作）

- 模型自造工具名变体的要求 = 机械层拦截并正常反馈。R3 已验证满足：
  29/29 全部被拦截，结构化 `Tool not found` 信封 1–5ms 返回，模型次轮
  自恢复，无连锁浪费。本项登记为确认，不产生实施动作。

## 4. 不变量

- 零注入边界：无新常驻 token；标注只出现在工具描述与一次性提示。
- fail-closed：web 族工具恒在，不出现无检索工具的激活。
- 审计不变：journal 事件面、failure 盖章、evidence 分级、来源加权三档全部
  跨车道生效。
- 干预边界：模型自身动作（含重复尝试、换道选择）机械层不干预，仅保证
  不挂死（既有 stall/idle 兜底）与结构化反馈。

## 5. S4 复验判据（草案，定稿时固化）

1. 双车道存在性：`local_browser` 模式下 web 族调用不再被
   `retrieval_mode_requires_framework_fallback` 拒绝（负样本转正样本）。
2. 静态标注存在性：两族工具描述含车道名与推荐序；无动态健康度字段。
3. 换道事件：`model_lane_switch` 至多一次/激活，authority=model。
4. 检索失败回传形态：导航失败错误含真实类别（网络错误/超时/拦截），
   无教学句/阻拦文案。
5. 通用统计：命中率 ≥90%、零真实 400、token/墙钟对照 R3 同题；
   chrome-error 后模型换道行为作自然观察登记，不设指标。
