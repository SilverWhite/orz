# 写入面 emoji 机械剥离设计（2026-09-23）

> 状态：**v1.0 已落码（0bi ⑪；run `RUN-CLI-6ab3dbe5`，轮达成 2026-09-24）**。咽喉点按 §5 退路定案＝**编辑族输入解码点**（`run_search_replace`；非 FileSystem 写原语，0BI 档 §3-1）。来源＝2026-09-23 用户裁决。索引条目：`FUS-WRITE-EMOJI-STRIP`。实施记录：[`0BI_FRICTION_CARRYOVER_2026-09-23`](audits/0BI_FRICTION_CARRYOVER_2026-09-23.md) §2-⑪。
> 入口：`TODO.md` P1-0bi ⑪ / `docs/BACKLOG_AND_PRIORITIES.md` 0bi。

## 1. 一句话设计

**agent 写文件时机械剥离 emoji**（含 emoji 序列的残件），并在工具结果面给一行机械告知；
**文件里全盘不出现 emoji**（代码、文档、夹具一视同仁），**对话／模型面不做任何处理**
（用户令「就是文件里全盘不要出现 emoji」「对话面不做处理，主要是文件层面多 emoji 了会麻烦」）。

## 2. 起因

1. 真机用户面首轮（VS Code ＋ `formulahendry.acp-client` 接 ACP，2026-09-23）模型回复带
   emoji（😄😊），引出「之前设计的文档面 emoji 过滤在不在」的核查。
2. **核查结论：该机制从未落地。**（a）机械过滤器不存在；（b）三份系统提示词模板
   （BASE／CODEX／SUBAGENT，仓内 XOR 混淆存储，按仓内种子解密后核对）**没有** emoji 相关
   规则；（c）唯一像纪律的一句在 `orz-tools/.../opencode/edit/mod.rs` 的工具描述里
   （「Only use emojis if the user explicitly requests it. Avoid adding emojis to files unless
   asked.」），属**非在役**的 opencode 实现族且只约束写文件；（d）一处测试断言
   （`orz-agent/src/prompt/context.rs:1335`）引用「基础模板的 `avoid using emojis`」，而源头
   已不存在，属悬空断言；（e）其余 emoji 命中皆为渲染宽度处理与自家 UI 设计约定。
3. **用户裁决（2026-09-23）**：「做机械剥离是不是好一些，这样模型自己也不用操心这点了，
   对话面不做处理，主要是文件层面多 emoji 了会麻烦」——即取**机械剥离**而非提示词纪律，
   且**只管写入面**。

## 3. 范围与边界

| 面 | 处置 |
|---|---|
| agent 写文件／改文件（**全盘**：代码、文档、夹具一视同仁；无扩展名白名单） | **剥离 emoji** |
| 工具结果面 | 一行**机械告知**（剥离计数＋行号），不判定、不建议（**可见性定稿＝B**，见 §5） |
| 对话／模型面消息（含 ACP 流式增量） | **不处理**（用户裁决） |
| 读取面 | 不处理（读到的内容原样） |
| 历史文件 | 不改写（只作用于本次写入的内容） |

**范围定稿（2026-09-23 用户令）**：「就是文件里全盘不要出现 emoji」——不设扩展名白名单，
代码文件与文档同等处理；确有需要的场景只走 §5 的逃逸开关。

> **hashline 整文件口径补记（2026-09-24，0bm 复审批）**：`grok_build_hashline` 编辑面的
> 写入面＝**整文件内容**（无单一 `new_string`），故其剥离作用于最终写入的整文件——既有
> 内容中的历史遗留 emoji（含逃逸开关期写入的）亦会一并剥离（剥离不增删行、行号锚不漂移、
> 告知行随报）。此为「只作用于本次写入的内容」在 hashline 形态下的解释，实现注释已同步
> 声明；`search_replace` 路径维持「只剥 `new_string`」不变。

## 4. 判据（Unicode 层，保守）

剥离对象＝**Emoji 属性字符**，即 `Emoji_Presentation ∪ Extended_Pictographic`：

1. **序列净化**：ZWJ 序列（U+200D）整条剥离**不留残肢**；变异选择符 U+FE0E／U+FE0F、
   肤色修饰 U+1F3FB–U+1F3FF、Keycap U+20E3、区域指示符对（旗帜）同族处理；
   序列中附带出现的孤立 ZWJ／VS／修饰符一并清除。
2. **不动非 emoji 符号**：★／☆、→／⇒、§、数学与制表符等**不是** emoji 属性，一律保留
   （避免误伤文档排版与既有代码字面量）。
3. **空白收敛**：仅当剥离点前后两侧均为空白时，折叠为单空格；否则直接删除，不引入新空白。
4. **不做内容判断**：不区分「表情」与「功能性图标」——一律按上述字符集机械处理。

## 5. 落点（S1 定案项）

- **咽喉点优先**：写入面的**单一**写原语（所有写／改工具共用），避免每个工具各做一份；
  候选＝`orz-host` 的 FileSystem 写路径。若该层不适合承载内容策略，则退到
  `search_replace`／`write`／编辑族的输入解码点，但必须**只有一个**实现点。
- **告知形态**：工具结果尾附一行（例：`[emoji 剥离] 3 处（L12/L45/L46）`）；计数与行号
  可核，随工具结果自然入 journal。
- **逃逸开关**：环境变量显式放行（名待定，候选 `ORZ_WRITE_KEEP_EMOJI=1`）——供确有需要的
  仓库夹具（如 `orz-markdown` 的 fuzz seeds、渲染测试里的 emoji 字面量）。**缺省剥离**。
- **模型面可见性＝B（2026-09-23 用户裁决定稿）**：用户令「**选择 B 是正确的，模型需要知道
  具体发生了什么**」——**模型不需要记任何规则**（真正的「省心」），但剥离发生时**随工具结果
  给一行极简事实**（例 `[emoji 剥离] 3 处（L12/L45）`），并记 journal。
  - 被否备选 **A. 完全无感**（不告知，仅记 journal）：收益＝模型侧零认知负担；代价＝
    ① 模型对「文件里有什么」的认知与实际落盘不一致，而编辑族靠原文匹配 ⇒ 模型后续想改自己
    刚写过的那段（记忆里带 emoji、磁盘上没有）会**匹配失败**；② 模型**故意**写 emoji
    （例如改 `orz-markdown` 的 emoji 夹具）会被**静默改掉意图**。A 若要成立须连带做
    「匹配前对搜索串施加同一剥离」（§7 第 7 条，现**不适用**，保留为备选路径记录）。
  - B 与 0bh 已定的「机械动作随报注解」口径一致（用户当时令：注解随报、成本不大，且压缩后
    模型仍能得知该提醒的含义）。

## 6. 不做

- 对话／模型面剥离（用户裁决；机械剥离会伤表达）。
- 改写历史文件或读取面过滤。
- 语义判断（「这个 emoji 该不该留」）——不做，交给字符集与逃逸开关。
- 不做提示词层面的纪律替代品（本机制即替代品）。

## 7. 判据（验收 6 条）

1. ZWJ 序列（如家庭／职业序列）整条剥离，**无残肢残留**（无孤立 U+200D／VS／肤色）。
2. VS16／肤色／旗帜／keycap 全清；「文本呈现」变体（U+FE0E）同样不留。
3. 非 emoji 符号（★／→／§／数学符号）**逐字保留**。
4. 代码文件与文档**同等处理**（默认），逃逸开关下逐字不变（反例用例）。
5. 告知行可核：计数与行号与实际剥离位置一致。
6. 逃逸开启时，既有 emoji 夹具写入**逐字节不变**。
7. **告知行可核（B 定稿）**：剥离告知行的计数与行号与实际剥离位置一致；**且模型据该告知
   即可避免用「带 emoji 的旧文本」发起后续替换**（构造用例：先写带 emoji 段落 → 告知出现 →
   再以剥离后文本替换成功）。
   - 备选路径记录：若将来改判 A（完全无感），本条须替换为「编辑／搜索匹配前对搜索串施加
     同一剥离」。
